## Read-only selection and rank boundary

`captureBRefitSelection(provider, authorizedAccountId, request)` is an INTERNAL call. The enclosing auth owner must supply an already authorized identity; this function is not callable from raw public request identity. `UnavailableBRefitSource` is the no-default supplier. `LocalBRefitSource(db)` reads the actual saved B selection and the separate `combat_b_fixture_refits` table, with account ownership and ranks in ONE SQLite SELECT. New local DDL is not a migration and is never applied to operating DBs. Missing source does not grant any R1/R5 rank or fabricate physical instance IDs.

Request:
```json
{"version":"combat.b-carriage-buffs.v1.20261002","expectedSelectionRevision":1,"expectedRankRevision":1,"refits":[{"slot":0,"type":"BCB01","rank":1}]}
```

LOCAL source table row: authorized account key, positive rank `revision`, matching `selection_revision`, `source_json` = `{status:"ISOLATED_LOCAL_FIXTURE", ranks:[{type,rank}] exactly all seven unique types, instances:[{slot,instanceId,carriageId}]}`. All ranks 1..5. Physical IDs unique and explicitly supplied by that account's isolated source, not derived from catalog IDs. Same type in several cells uses the one account rank separately per occupant/body, without multiplying other cells.

Response is a detached `BRefitDeparture`: `{version,accountId,selectionRevision,rankRevision,sourceStatus,cars:[{slot,instanceId,carriageId,occupant,type,rank}]}`. It is a validated departure CANDIDATE, not START. Slots 0..4, combined operator+cargo count1..5, exact original selected cells, one type/cell, no repeated operator, at least one operator (existing B selection rule), rank claim must exactly match account source. The LOCAL fixture can express explicitly provisioned ranks for tests; there is no upgrade/issuance/cost endpoint. A subsequent source upgrade produces a new candidate, never mutates an already captured one. No writes to old selection, receipt, loadout, investment or run snapshot.

Errors: `combat_b_refit_source_unavailable`, `combat_b_refit_source_invalid`, `combat_b_rank_revision_conflict`, `combat_b_refit_selection_conflict`, `combat_b_rank_conflict`, `combat_b_refit_slot_mismatch`, `combat_b_refit_ownership_invalid`; existing B selection errors propagate. Malformed external/source objects fail strict schemas. These are INTERNAL errors, no HTTP status mapping is issued by this contract. Consumers do not invent public routes or credentials.

## State and accepted-source owner

`new BCarriageBuffRuntime(departure, initial)` takes explicitly supplied initial `{contextId,mode:"EXTERIOR"|"INTERIOR",cars:[{slot,body:"NORMAL"|"BROKEN",actor:"UP"|"DOWN"|"ABSENT"}]}`. Original authority must bind unique fixed `contextId` to its operation; never generate a new context on reconnect. State covers every departure slot exactly once. CARGO requires ABSENT; OPERATOR cannot be ABSENT. No implicit normal/up defaults. Per-type ranks are frozen in departure; inconsistent duplicate-type ranks reject.

`transition({eventId,expectedRevision,kind:"BODY"|"ACTOR",slot,value})` or MODE with no slot atomically changes only its owned operating source state, then increments operating revision. Parent HP/down/mode owner reports authoritative events; this kernel neither owns nor changes HP/maxHP, occupants, loadout, restoration duration, cargo rights or cooldowns. It cannot restore HP, reset CDs, trigger catch-up actions, revive actors, convert cargo or grant rewards. The breaking-hit damage owner captures DEF BEFORE reporting BROKEN; the kernel does not recalculate that hit.

`accept({eventId,expectedRevision,slot,kind,ability,timing,target,direct,originalEligible})` captures immutable bonus source. `kind` is BASIC/ACTIVE/ULTIMATE (direct damage kinds), SENTRY, COMMANDER, DERIVED, INTERCEPT, HEAL, SHIELD, REPAIR, ITEM, OVERHEAL, EXPIRY_HEAL, RETURN, SUPPORT3. `ability` is BASIC/ACTIVE/ULTIMATE/INTERCEPT/EXTERNAL, separating ordinary heal/shield skills from their ultimate versions. `timing` is TIME_COOLDOWN/INTERCEPTION_PHASE/NONE: TIME_COOLDOWN requires ACTIVE, INTERCEPTION_PHASE requires INTERCEPT. Untimed ACTIVE gets no skill haste. BASIC/ACTIVE/ULTIMATE/INTERCEPT kind must match ability; HEAL/SHIELD require ACTIVE or ULTIMATE; other kinds require EXTERNAL. `direct` marks original direct effect, not a derived effect; `originalEligible` comes from the trusted original ability/target authority, never from user claims. Targets are ONE enum: STRUCTURE/ATTACHED/CLIMBING/APPROACH/ROOFTOP/ENEMY_TRAIN_BODY/ENEMY_TRAIN_PART/ENEMY/NONE. BASIC cannot use NONE. No visual classification heuristics, new target capability, interception geometry or reservation policy.

Source result: `{version,sourceId,slot,instanceId,type,rank,operatingRevision,damageBps,supportBps,skillHasteBps,interceptionHasteBps,kind,ability,timing,target}`. `sourceId` is JSON serialization of `[version,contextId,accountId,instanceId,eventId]`, maximum4096 characters, not a legacy capped offense source ID. Do not parse it by colon or reinterpret it as a catalog ID.

NORMAL enables sources. BROKEN disables NEW bonuses; living occupant baseline actions remain allowed. DOWN disallows new occupant actions and occupant DEF; NORMAL body DEF persists. CARGO has no actor bonuses, but NORMAL BCB06 body DEF persists. INTERIOR has no approved spatial mapping: no new actions in this kernel, and current DEF bonuses are zero. Existing accepted sources can still be read (already committed effects remain original-owner responsibility). EXTERIOR return reevaluates fixed original slots/states; no healing/reset or relocation.

Events share one scoped unique ID registry. Exact duplicate action or transition replays original result with no revision/effect duplication, even after state changed. Changed same ID, stale revision, capacity or malformed transition rejects before mutation. Accepted actions do not increment operating revision; revision belongs to operating state changes. A maximum1024 journal entries rejects overflow with `combat_b_journal_capacity` before any kernel state mutation; actions and state transitions SHARE this capacity. Exact existing replay is allowed at capacity. `capacity()` returns detached `{limit:1024,recorded,remaining,scope:"BOUNDED_LOCAL_NOT_FULL_RUN"}` for the coordinating owner. This is NOT an approved gameplay/action/attack-speed cap. Long five-actor runs can normally reach it, so this kernel must not be directly wired into unlimited live/full-run execution. Do not leave parent HP/state committed when the buff event was rejected: the coordinating owner must preflight/atomically coordinate both state owners and terminate the bounded validation before publishing any unrecordable event. There is no safe node rollover/full-run checkpoint compaction implementation here. Required follow-up BEFORE node/full-run binding: authority-owned node lifetime/rollover and checkpoint/retention policy, retained action/effect/receipt identities, cross-node active-effect restoration and nonduplicated replay. Costs/capacity cleanup are not delegated to View. No automatic ID reset, record deletion, unlimited memory growth or new context on reconnect. Restore schema rejects stored journal/actions over1024; live overflow, exact replay at capacity and restored overflow/state-preservation are exercised.

`snapshot()` returns `{version,departure,initial,journal,actions}`. `restore(snapshot)` replays version-pinned events and compares rebuilt bonus sources exactly; tampered source, duplicate stored events, unknown version or inconsistent state fails. Detached output changes do not mutate internal state. This is a buff-source journal, NOT a full run checkpoint or snapshot authentication. The enclosing persistence/restore authority validates ownership/receipt/operation/version and preserves the existing old run snapshot. Original action budget/stats/recipients/duration/expiry remain frozen by their existing action/effect owner; this kernel captures only its contribution and never reissues HoT/shields. Arithmetic calls are pure and do not themselves apply HP or deduplicate a physical hit; downstream damage/shield owner keeps that responsibility.

## Calculation integration

- `damage(eventId, numericDefenseInput)` multiplies the ORIGINAL unrounded rational base by `(1+C)` once, then calls actual existing `resolveNumericDefenseBudget`. C adds eligible BCB01/04/07 plus slot0 STRUCTURE2000bps. Original capped outgoing/equipment/mark, numeric DEF weakening/penetration and DR remain in their owners. Final ordinary floor is once before shield/HP. R1 breakthrough front100→135; R5→155. R5 firepower front basic100→150, not156. Derived/SENTRY/COMMANDER and ineligible targets get no C, including front. Use original base, never feed this boosted final damage into another direct-buff calculation. Derived effect uses DERIVED (bonus0).
- `support(eventId, originalUnroundedBudget)` applies `(1+BCB05)` once only to HEAL/SHIELD direct eligible actor effects. Returns exact rational and final projected floor; no target/recipient-count/range changes, no clipping, overheal conversion or shield issuance. HP514×18%×1.20→111.024→111; do not pass an already floored92. Original heal/shield recipient/lifetime/replacement owner follows. REPAIR/ITEM/COMMANDER/OVERHEAL/EXPIRY_HEAL/RETURN/DERIVED get0 bonus.
- `time(eventId, originalTime, originalSameGroupHasteBps)` returns exact base/(1+same-group existing haste+applicable BCB haste). Timed ACTIVE ability uses BCB02 independently of whether its effect deals direct damage; INTERCEPTION_PHASE uses separate BCB03 I, also independent of `direct`. The caller supplies ONLY existing skill H for ACTIVE, ONLY interception I for INTERCEPT; no automatic attack speed/skill haste cross-copy. Other abilities add0. No invented base time, haste cap, logical tick length, ultimate charge, supported target or concurrency. Original timing owner applies subsequent eligible groups/final tick ceil and preserves already running phase/CD. Actual timer/phase rebinding is OUTSIDE this kernel, not completed merely by this division.
- `defense(slot,"BODY"|"OPERATOR")` captures current eligible flat addition. `resolveBuffDefenseStat(originalFlat, originalPercentBps, capturedBuffFlat)` adds to the existing flat DEF term THEN applies original percent group. It does not accept already final-percent DEF as the flat input. Parent stat owner supplies other growth/percent ordering; original DEF-dependent abilities may consume eligible final DEF. No maxHP/DR% or shared body/operator budget.
