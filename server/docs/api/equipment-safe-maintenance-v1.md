Equipment mutations are permitted between nodes or in an eligible safe event while combat and travel are stopped. Opening a UI, READY, ACTIVE, or client pause alone is insufficient.

## Responsibility and private composition

`RunSafeMaintenanceStore` implements the existing `EquipmentSafeMaintenanceOwner`. It owns a derived eligibility journal and immutable original receipts, not clocks, HP, hazards, or map progress. `OperationMapStore` remains the authority for run/node/map revision. Inject `new RunSafeMaintenanceStore(db, originalRuntimeSource)` into `PinnedRunEquipmentStatContext`; no public endpoint, public START relaxation, or operating source registration was added.

`OriginalSafeRuntimeSource.prepare({accountId,runId,nodeId,mapRevision,reason})` must observe ORIGINAL owners, return `{evidence:{sourceId,sourceRevision,combatStopped:true,travelStopped:true,residualHazards:0,safeEventId:string|null}, assertions:D1PreparedStatement[]}` and fence every observed original row in the same DB batch. Assertions must abort on stale/changed clock, hazard, safe-event, or authority evidence. Never accept this object from a client or synthesize unconditional assertions in production. Safe-event eligibility additionally requires original event ID; noncombat event kind alone is not proof. No operating source exists yet.

Internal ENTER: `{eventId,kind:'ENTER',expectedMapRevision,expectedRevision,nodeId,reason:'BETWEEN_NODES'|'SAFE_EVENT'}`. Initial eligibility revision0. BETWEEN_NODES requires current original READY after at least one traversed node; SAFE_EVENT requires current original ACTIVE noncombat node plus trusted original safe event. Both require ORIGINAL stopped clocks and settled hazards. Internal EXIT: `{eventId,kind:'EXIT',expectedMapRevision,expectedRevision,nodeId}`; closes eligibility without resuming any original clock. State receipt is `{version,revision,mapRevision,nodeId,mode:'SAFE'|'CLOSED',reason,evidence}`.

Commit fences active account/run, unchanged original snapshot/map revision and previous exact journal bytes, observation assertions, then writes journal and receipt in one batch. Same event/body replays stored receipt without new observation, including terminated runs; changed body conflicts. Journal receipt UPDATE/DELETE is blocked. `prepare` requires active run, SAFE journal, matching current node/map revision, re-observed identical source evidence; returns assertions for the ORIGINAL equipment transaction. Clock resume, map movement, explicit EXIT, terminal run, or source revision changes invalidate a prepared equipment mutation. No historical source backfill.

Map movement makes old SAFE eligibility obsolete. A later eligible ENTER with a changed map revision re-proves clocks/hazards and replaces the old derived state with journal CAS. Old proof never permits the new node. ENTER at the same still-SAFE map revision is rejected. Other holds are preserved; this owner does not release reward/augment/maintenance holds.

Errors are ActivityError409 with `equipment_safe_` prefixes: run_not_found, run_not_active, source_unavailable, evidence_invalid, source_changed, map_conflict, not_safe, already_safe, revision_conflict, revision_exhausted, event_conflict, state_conflict. Validation shape errors remain schema validation errors. Failed batch changes nothing; original replay remains authoritative after result uncertainty.
