# Isolated current-service source capture v1

Internal module contract `community.active-source.v1.20261010`; approval `docs/superpowers/plans_categories/11_WEBSITE_COMMUNITY.md#community-retirement-purpose-approved-20261010`.

`CommunityActiveSourceStore(DB)` owns one current source per content. It is not a public API or a replacement authorization service. No production reader/writer currently consumes this store.

- `backfill(contentId)` explicitly validates original creation receipt/date/descriptor and current CREATE/EDIT/HIDE/RESTORE/LOCK/UNLOCK renderer proof, current ACTIVE account/public-author eligibility and exact same-batch content/source/previous-source CAS. Unknown legacy or AUTHOR_DELETED fails. Source time is reverified after guard construction. Existing row is replaced, not appended to history. Capture may return409 if state changes after commit; callers must compare current state, never infer rollback from that conflict alone.
- `read(contentId)` reads the captured minimal source, validates strict canonical shape/current state hash/revision/kind/parent and current descriptor hash, then rechecks current content/source. It does not authorize publication or restore eligibility. After current revision changes it rejects stale capture; it never falls back to old history.
- `compareLegacy(contentId)` compares active capture with strict existing creation/render validation. Old source missing means failure, not successful comparison. Explicit capture alone does not authorize deleting history.

Stored canonical snapshot fields: contractVersion/contentId/revision/kind/parentId/createdAt/updatedAt/rendererVersion/stateHash/descriptorHash. No body/title/actor/accountId/reason/command key/receipt is copied. Hash/reference metadata remains subject to purpose and reidentification limits; it is not anonymous. Exact former command, actor, receipt and source-time guards are used transiently at capture and are not copied into this current table.
