# World boss durable LOCAL rail/geometry journal v1

Contract: `world-boss.rail-journal.v1.20261002`. Rail v3 and geometry v1 remain unchanged. Scope `LOCAL_DURABLE_TRIAL`, input provenance `TRUSTED_LOCAL_TRIAL`. This is a separate internal repository contract; no new public URL, operational migration, start, health application, reward, or deployment.

## State ownership and actual connection

`WorldBossRailJournal` reads the actual persisted `world_boss_local_rail_attempts` rail owner via a single SQL LEFT JOIN. The source row owns attempt/version, definition, clock, availability frame, original receipts, logical result. A separately persisted geometry head owns pinned profile, accepted samples, selected route, crossing events and attack evidence. Every mutation coordinates both owners and an immutable journal entry in the same D1 batch and owner revision. This is actual SQL storage and restore, not an in-memory/mock success.

`combat-authority.ts` is policy only. `combat-host-report` and `combat-coop-status` apply to ordinary co-op reports/display and cannot supply operational world-boss movement authority. No operational world movement producer currently connects this journal. Internal `advance` accepts validated trusted LOCAL trial samples; this does not prove server-generated production movement. That adapter and full-attempt/multi-round ownership remain prerequisites. Existing motion data/pins and route receipts are preserved.

## Internal interfaces

- `attach(attemptId, expectedOwnerRevision, profile, initial)` adopts an existing LOCAL row only before the attached round has any route receipt/result, with initial sample at the exact source frame/rail clock and before attack impact. Geometry reference is exactly JSON `[attemptId, roundId]`, content version and route match. Attack impact must be within original lock/resolve window. Repeated exact adoption returns the original acknowledgement. Earlier-round original receipts are adopted with their complete account/key/digest/receipt provenance and remain replayable after attachment. Adoption does not increment original owner revision.
- `command(accountId, originalV3Command, now)` delegates permission/window/revision to the existing v3 domain. Participant comes from persisted definition; callers must retain actual existing auth/session checks before this internal interface. Client availability, clock, samples, snapshots and definitions are never part of the v3 DTO. New commands require exact current accepted geometry sample time; route selection and original route receipt commit together. Original key/account/body replays original receipt even after time/revision advance. Other round without geometry fails closed.
- `advance(attemptId, expectedOwnerRevision, frame, sample)` is trusted internal LOCAL ingress, never a player upload. Schema-valid frame and exact sample timestamp, strictly next sequence, bounded interval/speed/acceleration and trapezoid displacement are required. The exact impact sample must be recorded; skipping it is rejected. Original availability controls existing cancellation behavior. Normal result uses `bindGeometryResult` without altering v3 result; cancelled/skipped result has no success evidence binding.
- `read(accountId, attemptId, optionalContentVersion)` is read-only. It returns `{version,status,inputProvenance,ownerRevision,frame,rail,geometry,binding,entries}`. Each entry contains version/revision, original request digest/key, original receipt or movement acknowledgement, original availability frame/sample, new crossing/attack events, optional original result binding, previous hash and state hashes. No HP/score application is performed.

Acknowledgement: `{version, ownerRevision, sampleSequence}`. Original route receipt: unchanged v3 `{commandId,roundId,acceptedRevision,acceptedAt,route,internalAction}`. Owner revision covers storage commits and is distinct from v3 logical revision. New contract consumer must not interchange them.

## Atomicity, isolation and replay

Load validates source identity/status/revision and strict frame, canonical restored rail/motion, selected sample matching original route receipt, head binding and hash-linked journal. One joined head/source snapshot is read, then immutable entries restricted to that head revision; a concurrent append cannot tear the read. Every original frame is retained in its entry. Current head hashes bind the actual restored owner states.

CAS checks source revision and exact source text, plus attached head revision/hash and exact head state texts. Transaction order: guard, append entry, update geometry head, update source rail, clear guard. SQL triggers reject UPDATE/DELETE of historical journal rows (`rail_journal_append_only`), including changes attempted between a load and commit. Failure rolls all changes back. Lost commit acknowledgements recover by reading the persisted original entry. Duplicate exact requests create no new journal entry; changed request body conflicts. Fresh caller auth remains external and required on replays.

After attachment a SQL fence rejects existing standalone LOCAL rail writers with `rail_journal_writer_required`; they must use this transaction coordinator. Existing local HTTP v1 can still read the source row, but its old standalone command writer cannot mutate an attached attempt. No existing HTTP/v3/geometry files are changed; adopting an old HTTP attempt silently is forbidden. Unattached old HTTP attempts keep their old contract. A future separately versioned HTTP adapter must preserve existing auth/local isolation and invoke this coordinator. Missing attachment returns unavailable, not trial success. No detach/auto-migration contract is provided.

## Errors and outstanding dependencies

Internal `LocalRailError`: 403 `rail_attempt_forbidden`; 404 `rail_local_attempt_not_found`; 409 `rail_definition_conflict`, `rail_local_owner_revision_conflict`, `rail_journal_state_conflict`, `rail_command_key_conflict`, `rail_journal_key_conflict`, `rail_journal_frame_sample_conflict`, `rail_journal_sample_sequence_conflict`, `rail_journal_impact_sample_required`, adoption errors; 503 `rail_journal_not_attached`, `rail_journal_state_invalid`, `rail_journal_round_unavailable`, `rail_journal_sample_clock_required`, `rail_authority_frame_unavailable`, revision exhaustion. Existing v3 domain role/window/route errors remain unchanged. Schema/motion invalidity or storage failure is thrown and must never be translated to success. There is no new HTTP error mapping yet.

Consumable now: separately pinned durable read fixtures, original receipts, same-revision geometry/events/result evidence, storage restart/replay semantics. Still required: operational world movement producer, versioned authenticated journal HTTP consumer adapter, remaining-round geometry lifecycle, supported defense/shield/HP owner binding, operational approved values and actual integration. These are not prerequisites for this LOCAL single-round storage verification, and this verification does not clear those gates. Screen connection remains after approved final art.

Run SQL `apps/game-api/local/world-boss-rail.sql` then `world-boss-rail-journal.sql` only in a dedicated LOCAL database. Do not run these on DEV/PRD. No deployed router references the journal.
