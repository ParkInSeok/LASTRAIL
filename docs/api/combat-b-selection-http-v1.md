New LOCAL SQL apps/game-api/local/combat-b-selection.sql creates combat_b_selections, combat_b_selection_receipts, combat_b_selection_guard and explicit fixture catalog. Selection+receipt saved in one D1 batch with CAS, actual ownership, catalog document/revision, active session+account and access/session expiration recheck. Database clock is SQLite millisecond julianday expression; no fractional unixepoch test override. Duplicate/competing write retries at most4 then409; all writes roll back on guard/receipt failure. Receipt updates are immutable, account key foreign keys retain account ownership/cascade lifecycle. No wallet/economy/account mutation/run write.
Lost ACK may return503 after actual commit: repeat identical key/body to obtain original response, or GET to observe saved revision. 409 revision/catalog conflict → GET/reconcile and a new user command/key; do not silently rewrite accepted old request. 401/403 → stop writes/retries until existing authentication is renewed. No automatic retry timer/cache/pagination.
B saving is an independent next-selection record and may occur while an old run exists; it never changes active run's original START/snapshot/A loadout/investment/equipment/receipt. It does not activate this record inside the ongoing run. B START integration, authorized snapshot generation, target/stat/geometry/interception/effects remain unimplemented and startReady stays false.
