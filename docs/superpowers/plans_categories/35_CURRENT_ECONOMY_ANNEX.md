## 신규 12노드 고위험 반복 보상 v01 — 2026-09-28 / 승인 대기

사용자 ‘다음 ㄱㄱ’에 따른 상세 기획. 목적은 위험도 I의 승인 경제를 보존하면서 상위 위험도의 성장 재화 보상을 정의하고, 적 난이도·기존 위험도·첫 보상을 혼합하지 않는 것이다. **이 절은 신규 수치 제안이며 운영 지원/실기 균형 검증 완료가 아니다.** 직전 주간 코어 우편 만료 예외는 별도 승인 대기를 유지한다.

### 1. 확인한 원본과 적용 범위

[반복 경제 v04](#permanent-repeat-core-economy-v04)의 신규 일반/스토리 12방문·실완료 웨이브 N·정상 개인승리 V를 기본으로 한다. 지정 Server checkout의 server/packages/balance/src/index.ts:250 이후 기존 launchRunRewardsConfig는 I/II/III/IV/V=8000/10000/12000/14500/17500 bps이고, 작전별 10000~18000 bps 및 구 15wave 산식을 별도로 갖는다. [49 구 위험도 계약](49_SERVER_API_CONTRACTS.md#source-77f48c0fb91c5e38)은 구 버전 호환 근거다. 해당 소스에 위험도 타입/계수가 존재하는 것만으로 신규 12노드 II~V 입장·전투·정산이 지원된다고 판정하지 않는다.

새 위험도 I는 승인 기준 1배이므로 구 I=0.8을 곱하지 않는다. 진행 중인 구 작전은 출발 당시 원정의/권리/보상 산식을 유지하며 이번 표로 소급 계산하지 않는다. 신규 보상 정의는 기존 버전과 구별하여 발행해야 한다. 원START에는 지원 작전/모드/위험도·전투/보상 정의와 버전을 고정한다. 실행 시 현재 활성 버전을 다시 조회해 바꾸지 않는다.

### 2. 추천 배율과 대안

**추천 A: I 1.00 / II 1.20 / III 1.40 / IV 1.65 / V 2.00.** 첫 시험용으로 상위 투자에 보상 차이를 주되 V를 반복 성장 재화 2배로 제한한다. 실 플레이 시간·실패율 자료에서 도출한 최적값이라는 뜻은 아니다.

| 위험도 | 반복 5종 배율 | 정수 bps | 직전 단계 대비 증가 |
|---|---:|---:|---:|
| I | 1.00 | 10000 | 기준 |
| II | 1.20 | 12000 | 20% |
| III | 1.40 | 14000 | 약16.67% |
| IV | 1.65 | 16500 | 약17.86% |
| V | 2.00 | 20000 | 약21.21% |

대안 B는 구 배율을 I로 정규화한 1/1.25/1.5/1.8125/2.1875다. 구 상대비율을 보존하나 새 성장 경제에서 V 공급이 더 커지고 구 산식의 적합성이 확인되지 않아 자동 계승하지 않는다. 대안 C는 모든 위험도 보상 동일이며 고위험을 선택할 성장 보상이 약해 이번에는 추천하지 않는다. 무조건 상위 위험도가 시간당 최적이라는 보장도 하지 않는다.

### 3. 계산·지급 계약

각 재화의 수량은 **floor((웨이브 단가×N + 승리 가산×V)×riskBps/10000)**로 계산한다. 위험도 배율은 합계에 한 번 적용하고 재화별 최종 수량에서 한 번 내린다. 중간 웨이브마다 반올림/지갑 지급하지 않는다. N은 원작전에서 검증된 완료 웨이브 수이며 일률 15나 17로 고정하지 않는다. 최종보스 3페이즈는 총 1wave이고 미완료 페이즈를 분할 지급하지 않는다.

| 재화 | 웨이브 단가 | 승리 가산 | 위험도 적용 |
|---|---:|---:|---|
| 지휘관 XP |20|160|적용 |
| 요원 EXP |25|275|적용 |
| 크레딧 |10|130|적용 |
| 부품 |2|16|적용 |
| 데이터 |1|13|적용 |

신규 반복 5종에는 구 작전 진행도 배율·구 실패 계수·구 웨이브 배율을 추가로 곱하지 않는다. 정상 패배는 V=0, 실제 N에 같은 위험도 배율을 적용하는 안이다. 포기/취소/기술 무효는 기존 정책대로 반복 지급 0이며, 미확정 결과는 확정 대기다. 정상 패배를 포기로 임의 분류해 기지급 권리를 회수하지 않는다. 실패 반복이 최적 파밍으로 관찰되면 배율/전투 부담 수정안을 별도 검토한다.

아래는 N=17·승리 1회의 산술 예시이며 모든 경로가 17wave라는 뜻은 아니다.

| 위험도 | 지휘관 XP | 요원 EXP | 크레딧 | 부품 | 데이터 |
|---|---:|---:|---:|---:|---:|
| I |500|700|300|50|30|
| II |600|840|360|60|36|
| III |700|980|420|70|42|
| IV |825|1155|495|82|49|
| V |1000|1400|600|100|60|

IV·N=5 정상 패배는 165/206/82/16/8이다. IV·N=16 승리는 792/1113/478/79/47이다. 16wave 요원EXP는 (400+275)×1.65=1113.75→1113이며 웨이브/승리 가산을 각각 내린 뒤 더하는 방식은 금지한다. N=0 패배는 모든 재화 0이다. V=1은 실제 승리/필수 목표 완료를 독립 검증해야 하며 클라이언트가 N이나 승리 플래그만 제출했다고 보상을 생성하지 않는다.

### 4. 증가하지 않는 보상과 협동

- 주간 3승의 승리 카운트는 위험도와 무관하게 개인 1승, 권리는 SPECIAL_CORE 2개로 동일하다. V 한 번을 5승으로 계산하거나 코어를 4개 지급하지 않는다. 만료 예외 승인 여부는 본 배율과 독립이다.
- 스토리 사건 첫 보상·특수코어·유한 크리스탈/티켓/조각 권리는 기존 원권리와 수량을 유지한다. 기존 계정+작전+위험도의 일반 재료 첫 권리도 별도 계약으로 보존한다. 이번 배율을 첫 보상에 곱하거나 새 위험도마다 사건 첫 코어를 재생성하지 않는다. 신규 위험도 첫 재료 표가 없다면 임의 새 표를 생성하지 않는다.
- 일반/엘리트 작전 중 장비 수량·희귀도·슬롯/합성·최종 장비 미지급은 승인 14 정책을 유지한다. 위험도 V라고 장비 드랍 개수나 고등급 확률을 함께 올리지 않는다. 상점 가격·증강 선택·오프라인·패스·월드 보상에도 적용하지 않는다.
- 협동은 개인별 기존 결과 자격으로 정산한다. 지원된 동일 위험도의 완주자는 같은 산식을 적용하고 2인이라는 이유로 반씩 나누거나 파티 배율을 추가하지 않는다. 도중 이탈자의 새 완주 권리 없음, 잔류자 정상 승리만 V=1. 완주 후 전달 단절은 원적격 결과를 복구한다.
- 기존 보상 preview/claim 및 원장/영수증 경로를 사용한다. 계정+원결과 권리의 중복방지와 광고 추가 보상 대상은 기존 승인 범위를 유지한다. 이 안은 광고 배수 확대를 승인하지 않는다.

### 5. 지원·입장·화면 경계

II~V는 **수치 제안 상태**다. 실제 지원 행은 작전ID·solo/coop·risk·전투 정의/원H/B·보상 정의·필수 목표·클라이언트 지원 버전·검증 근거가 함께 확인되어야 한다. 위험도 배율을 적 HP/공격력 배율로 재사용하지 않는다. 보상 표만 준비되었다고 모든 고위험 입장을 허용하지 않는다.

기존 계정 해금/입장 자격을 확인하여 적용하고 새 지휘관 레벨·전투력·특정 요원·승급III/훈련5 보유 제한을 임의 추가하지 않는다. 해당 프로필의 실제 입장 계약을 확인할 수 없으면 지원 대기로 남긴다. 구 계약의 로마 위험도와 정수1~5 필드는 명시적으로 변환하고 미지원 값을 I로 대체하지 않는다.

기존 출격 화면에서 선택 위험도와 ‘반복 성장 보상 1.65배’처럼 적용 범위를 표시한다. 코어·첫 보상·장비까지 늘어난다는 인상을 주는 ‘모든 보상 1.65배’는 사용하지 않는다. 실제 경로에 따라 N이 달라지므로 출발 전에 17wave 예시를 확정 지급 수량으로 표시하지 않는다. 결과 화면에는 서버가 확정한 원위험도·각 보상 줄을 표시하고 현재 선택 위험도를 가져오지 않는다. 미지원 단계는 기존 지원 불가 상태로 처리하며 새 시안 제작을 미리 요청하지 않는다.

### 6. 비교 검증과 발행 조건

수치 계약 검증: I 기존 승인값 동일, 각 단계 산술/최종 내림, 0wave, 정상 패배/포기/미확정 구분, 지원 범위 밖의 위험도 거절, 원START 뒤 활성 정책 변경 불변, 중복 claim의 추가 지급 0, 2인 개인 권리/전달 단절, 첫 권리/주간/장비 비간섭을 확인한다. 구 15wave 보관 작전이 새 표로 바뀌지 않는 회귀 사례도 포함한다.

게임성 비교는 같은 지원 맵·편성·성장·장비 시작조건·AUTO·입력 규칙으로 위험도별 전투를 먼저 비교하고 실제 적격 진행군을 별도로 본다. 클리어율/피해/회복 부담/완료시간/실완료N, 재화별 시도당·시간당 획득, 정상 패배 반복과 정상 완주의 차이를 기록한다. 서로 다른 재화를 임의 합산한 전투력·총가치를 만들지 않는다. 구버전 플레이 데이터로 신규 프로필 통과를 주장하지 않는다.

단순 동일 N 승리만 비교할 때 시간당 보상의 상대값은 위험도 배율÷소요시간 비율이다. V가 I보다 시간이 2배면 2배 보상이어도 시간당 동일하다. 실패를 포함하면 Σ각 시도 확정보상÷Σ해당 시도시간으로 별도 계산해야 한다. 빠른 고의 패배가 정상 완주를 지속적으로 앞서는 결과, 지원 성장군에서 클리어 자체가 성립하지 않는 결과는 발행 전 보완 대상으로 남긴다. 아직 실기 표본이 없으므로 임의의 승률 합격선이나 ‘밸런스 완료’를 선언하지 않는다.

### 7. 승인 대상과 작업 인수

승인 대상은 **신규 반복 5종의 I/II/III/IV/V=1/1.2/1.4/1.65/2, 정상 패배에도 실제 N에 같은 배율, 재화별 최종 한 번 내림, 신규 반복표에 구 작전 진행도 배율 추가 없음**이다. 위험도별 적 전투 수치·계정 해금 변경·신규 첫 재료 표·모든 단계 운영 개방은 이번 승인 대상이 아니다.

현재 문서/소스 정적 대조 및 산술 검증만 수행했고 실기/지갑/API 검증은 미수행이다. 승인 후 Server는 기존 S-02/S-05 정의에서 신규/구 보상 버전과 지원 행을 연결하고, 선행 충족 때 U-04/P-04에 원정의·계약·QA를 전달한다. 실제 소비/표시 영향이 확인될 때 해당 역할 작업을 추가하며 준비 전 실행 큐 선등록은 하지 않는다. 다음 상세 기획은 고위험 **전투 부담/적 수치·실제 해금 계약**의 원본 확인과 미정 부분 보완이다.

### 4. 누적과 수령 산식
근무 배치 상태/랭크는 서버 계정 상태가 소유한다. 변경 완료 서버시각과 근무 revision을 기준으로 근무 구간을 기록한다. 배치/해제/강화/교체는 지급·수령 기준시각 초기화가 아니다.
권고 산식(재화 r):
`reward[r] = floor(baseHourly[r] × currentStoryMultiplier × Σ(eligibleSeconds[j]/3600 × (1 + crewBonus[r,j])))`
현재 스토리 진행의 상한/배율을 수령에 적용하는 기존 정책은 유지한다. 신규로 구간별 기록하는 것은 근무 효과이며 과거 스토리 단계별 생산으로 몰래 바꾸지 않는다. 구간별 반올림 없이 재화별 합계에서 최종1회 내림. 고정 정밀도/최대 누적값은 Server 계약에서 검증한다.
**보관창 세부 추천:** L=마지막 성공 수령시각(없으면 원계정 생성시각), N=서버 현재시각, C=현재 원정책 보관상한. 지급 대상 시간은 [L,min(N,L+C)). 그 범위에 실제 존재한 근무 구간만 교차 합산한다. 상한에 도달한 뒤 더 좋은 요원을 넣어도 가득 찬 과거 보상의 효율이 올라가지 않는다. 이 시간창 선택은 기존 총시간식에 새로 필요한 정책이며 승인 대상이다.
현재 보관상한이 증가할 가능성이 있으므로 현재 상한까지만 남기고 나머지 근무 이력을 미리 삭제하지 않는다. 미수령 구간 중 지원 최대상한12시간 내 변경 이력을 보존한다. 재시도·조회·로그인·화면닫기·배치·강화는 L을 바꾸지 않는다. 성공 수령은 원 수령 거래가 기준시각/리비전·지갑·영수증을 함께 갱신한다. 최소600초 전 수령 불가와 빈 수령의 기준시각 불변도 유지한다.
