# LAST RAIL | 배경·컷신 스타일 가이드

작성일: **2026-09-21**. 작업 범위: 공통 가이드 3종 중 두 번째. 상위 품질·세계관은 [16](16_ART_STYLE_GUIDE.md), 인물의 공통 외형은 [17](17_OPERATOR_COMMON_STYLE.md), SD 전투 표현은 [19](19_SD_COMBAT_MODEL_TRANSLATION.md)를 따른다.

**상태:** 승인된 아트 방향을 배경·장면 제작에 구체화한 설계 문서다. 아래 환경군·컷 구성·해상도 후보는 새 제작안이며, 새 지역·스토리·전투 목표·컷신 수·보스 페이즈의 확정을 의미하지 않는다. 기존 게임 규칙과 실제 콘텐츠 ID를 먼저 확인한다. 단, §8의 DAILY/ALWAYS(ON)/OFF 3단계와 실제 전체화면 재생 중 전투 배속 0은 2026-09-21 사용자의 후속 지시로 확정되었다. 후속 사용자 정정에 따라 OFF는 연출 삭제가 아니라 이전 제안의 요약 연출이다. DAILY의 반복 사용도 요약으로 연결한다. 하루 한 번의 세부 집계와 초기값은 04의 권장안이며, 길이·자산·제작 방식도 별도 표시한다.

## 1. 장면의 한 줄 방향

> **붕괴한 철도·산업 문명의 거대한 공간 안에서, 열차와 사람의 생활감이 중심으로 남는 고품질 2D 장면. 전투에서는 정보가 먼저 보이고, 비전투에서는 같은 세계의 정적·관계·스케일을 더 깊게 보여준다.**

첫 번째 릴스의 장대한 원근·높낮이·구조물 레이어를 참고하되 유적/성역 자체를 복사하지 않는다. 두 번째 릴스의 인물 중심 조명·따뜻한 동료 장면·고요한 대비를 LAST RAIL의 객차·정비·정차 상황으로 재해석한다. ‘포스트 콜랩스’가 모든 장면을 갈색 먼지로 덮거나 휴식·식물·물·밝은 낮을 금지하는 뜻은 아니다.

정확한 붕괴 원인·미공개 세력·캐릭터 관계를 새 CG 한 장으로 확정하지 않는다. 환경군을 만들었다고 그 지역이 출시 맵에 추가된 것으로 적지 않는다.

## 2. 같은 화풍, 서로 다른 표시 밀도

| 사용처 | 우선 정보 | 표현 방식 | 금지할 혼동 |
|---|---|---|---|
| 외부 전투 배경 | 적 접근·선로·포격·열차 진행 | 원근과 큰 형태, 절제된 디테일, 분리된 동적 개체 | 홍보용 한 장 그림을 실제 전투로 사용 |
| 내부 전투 객실 | 5인·적·배치·공격 범위·장치 상태 | 플레이 면을 비우고 앞/뒤 구조 분리 | 객실 전경 소품이 전투 위치를 지속 가림 |
| 노드/이벤트 화면 | 사건 종류·선택지·위험·보상 | 환경은 맥락, 선택 정보는 별도 UI | 그림 속 글자로 확률/보상/선택 상태 고정 |
| 이야기 CG | 인물의 감정·관계·장면의 상황 | 풍부한 재질·빛·전경과 심도 | CG에서만 새 장비·캐릭터 설정을 무단 추가 |
| 궁극기·지휘관 스킬 컷신 | 실제 승인된 행동과 인물/열차의 규모 | ALWAYS 및 DAILY 첫 재생은 표준 전체화면·전투 정지, OFF와 DAILY 반복은 요약 연출(전체화면이면 동일 정지) | 자동 액티브·패시브·파생 효과까지 전체화면으로 확대 |
| 웹/로딩 키비주얼 | 첫인상·세계의 규모·주인공 | 큰 구도와 별도 텍스트 안전영역 | 실제 플레이처럼 보이게 허위 UI 합성 |

전투와 CG는 다른 세계가 아니라 같은 원본 설계를 다른 정보량으로 보여주는 것이다. 객실 구조·인물 복식·대표 장비의 일관성을 유지하고, 디테일과 조명 강조만 달리한다.

## 3. 배경 환경군 — 제작용 분류안

황무지 철도와 폐산업 구역은 기존 세계/기획의 용어를 따른다. 나머지는 이 문서에서 제안하는 **장면 모듈 분류**이며 독립 지역 해금이나 출시 개수 확정이 아니다.

| 환경군 | 대표 큰 형태 | 재질·빛 | 캐릭터와 게임 정보 보호 |
|---|---|---|---|
| 황무지 철도 | 선로의 긴 축, 무너진 전주, 낮은 잔해, 먼 능선 | 모래·흑철·먼지, 따뜻한 낮과 차가운 그림자 | 모래와 실루엣의 밝기를 분리, 위험 표식 근처 입자 밀도 축소 |
| 폐산업 구역 | 공장 프레임, 배관, 크레인, 냉각 구조 | 산화 금속·콘크리트, 작업등·증기 | 케이블과 배관의 가는 선을 전투 면 뒤에서 줄임 |
| 고가선·협곡·수변 철로 | 큰 교각, 높낮이, 계곡/바다, 철도 교량 | 습기·부분 녹·풀, 파란 공기 원근 | 첫 릴스의 스케일을 사용하되 선로의 실제 이동 연결 유지 |
| 정거장·보급/정비 공간 | 플랫폼, 도킹 장치, 리프트, 적재 랙 | 작업 금속·천막·라벨, 중성 조명과 따뜻한 작업등 | 각종 이벤트 장면의 공통 공간으로 재사용; 아이템 결과는 UI에서 표시 |
| 객차의 생활·지원 공간 | 침상, 보급 상자, 식탁, 창, 작업대 | 관리된 천·수리 부품, 창빛·실내등 | 휴식 CG는 풍부하게, 전투 버전은 동선·판독 면 비우기 |
| Arcana 산업 잔재 | 차폐 링, 촉매 장치, 균열 봉쇄 구조 | 공학 구조와 이상광의 대비 | 실제 마법을 보존하되 성역/종교 장식이 세계 전체의 기본값이 되지 않음 |

자연이 다시 자란 교량·맑은 하늘·따뜻한 정차 장면은 사용할 수 있다. 다만 철도·산업 구조·인물의 작업 흔적을 남겨 다른 판타지 세계로 읽히지 않게 한다.

<a id="combat-background"></a>
## 4. 외부/내부 전투의 배경 규칙

### 4.1 상단 외부

[04 전투](04_COMBAT_RUN.md)의 실제 열차 편성 순서·거리·분기·포격 상태가 권위다. 배경 그림에 기관차와 객차 수를 고정해서 그리지 않는다. 진행방향 앞쪽 위협 공간을 확보하고 후방 추격과 분기 표식을 읽을 수 있게 한다.

큰 구조물은 전장 뒤에서 스케일을 만들고, 적이 이동하는 실전 경로의 명암·텍스처 대비는 낮춘다. 레일, 접근 차량, 실제 충돌물/위험물은 장식과 분리한다. 장식 차량을 실제 적과 같은 강조선·표식으로 그리지 않는다.

풍경 이동은 승인된 주행 거리와 연결한다. UI 애니메이션 시간을 풍경에 그대로 적용해 열차가 멈췄는데 선로가 진행하거나, 배속 설정만으로 거리가 바뀌는 인상을 만들지 않는다. 원경의 이동비율·안개 밀도는 연출값이며 실제 열차 속도를 바꾸지 않는다.

### 4.2 하단 내부

현재 분대가 있는 객차 내부 **한 칸**을 보여주는 기존 방향을 유지한다. 배경 패널의 가구 때문에 5인 배치 가능 공간을 줄이거나, 전체 객차를 동시에 펼치는 레이아웃으로 바꾸지 않는다.

벽·뒤쪽 설비는 후경, 전투 바닥은 판독 면, 앞쪽 난간/프레임은 전경으로 분리한다. 전경은 발과 표적 위치를 상시 가리지 않아야 한다. 고정 화면 장식의 불투명도를 낮추는 경우에도 충돌물이나 공격 가능한 장치를 같이 사라지게 하지 않는다.

포탑은 소속 전투 객실과 연결된 독립 개체다. 객실 파괴 때 잔여 포탑 HP와 무관한 전투불능 판정을 [04](04_COMBAT_RUN.md#turret-lifecycle)의 상태로 받아 표시한다. 화려한 재가동 그림이 실제 부활 판정이 되지 않는다.

### 4.3 명암 우선순위

**위험 예고·필수 상태 → 전투 인물/적/실제 투사체 → 상호작용 구조 → 배경 장식**을 판독 우선순위로 둔다. 실제 겹침 순서는 객체 구조에 맞춰 정하고, 모든 정보를 한 개의 최상단 발광 레이어로 해결하지 않는다.

경고색과 지역 팔레트가 겹치면 명도·테두리·패턴·움직임으로 의미를 보강한다. 붉은 경고등, 붉은 코트, 적 위험 예고가 모두 같은 빨간 면이 되지 않게 한다.

## 5. 조명·색·환경 상태

| 상황 | 권장 조명 구성 | 유지할 기준 |
|---|---|---|
| 낮/황무지 | 따뜻한 주광 + 중성/차가운 그림자 | 인물 기본 색을 읽을 수 있는 중간 명도 |
| 황혼/정차 | 낮은 측광·역광 + 객차 작업등 | 얼굴을 완전히 암부에 두지 않고 장비 윤곽 보존 |
| 밤/외부 | 차가운 환경광 + 한정된 전술등 | 검은 캐릭터 외곽과 선로 경계 유지 |
| 객실/생활 | 중성 기본등 + 작은 따뜻한 생활등 | 편안함 허용, 같은 재질·복식 논리 유지 |
| 전투 경고 | 상태 기반 경고등 + 짧은 충격광 | 상태가 해제되면 해제; 경고가 항상 켜진 배경으로 고정되지 않음 |
| Arcana 현상 | 환경광과 다른 제한된 이상광 | 위험·치유·장식 현상의 의미를 실제 효과와 연결 |

빛은 캐릭터를 설명하는 것이지 장비 위치와 색을 바꾸는 장치가 아니다. 밤 장면의 푸른 머리와 낮 장면의 검은 머리가 동일한 기본색에서 나온 것으로 읽히게 한다. bloom·먼지·렌즈 효과는 끌 수 있어도 핵심 표적/경고는 남도록 분리한다.

## 6. 레이어·모듈 구성

| 그룹 | 내용 | 변경 주체 |
|---|---|---|
| Sky / Far | 하늘, 먼 능선/도시 | 배경 연출 |
| Mid | 교각, 공장, 큰 지형 | 주행과 연결된 연출 |
| Playfield | 바닥·선로·객실 플레이 면 | 실제 전장 정의와 맞춘 표현 |
| Structures | 문·난간·장치·전경 소품 | 정적 또는 명시된 상태 객체 |
| Train / Actors | 기관차·객차·요원·적·포탑 | 게임 상태 |
| Telegraph / CombatFX | 범위 경고·탄도·보호막·피격 | 실제 전투 이벤트 |
| Atmosphere | 안개·먼지·빛줄기 | 가독성을 침범하지 않는 연출 |
| UI | 이름·버튼·수치·선택 결과 | 실제 UI owner |

이 표는 논리 그룹이다. 모든 장면이 반드시 같은 수의 텍스처를 생성해야 한다는 규칙이 아니다. 공용 파츠를 사용하되 서로 다른 객실 타입을 아이콘만 바꾼 동일 장면으로 만들지 않는다.

표시할 수리·정상·손상·파괴 버전은 실제 상태 enum과 매핑한다. 상태 이름이 없는 연출용 중간 단계는 게임 상태로 추가하지 않고, 전환 효과로만 구분한다. 씬 결과·피해·보상·랜덤 노드를 그림에서 계산하지 않는다.

## 7. 이야기 CG와 관계 장면

전투 밖의 CG는 원화 품질을 보여줄 주요 영역이다. 다음은 장면 **후보**이며 제작해야 하는 신규 스토리 목록이 아니다.

| 장면 후보 | 보여줄 내용 | 장면이 새로 확정하면 안 되는 것 |
|---|---|---|
| 출격 전 플랫폼 | 다른 역할의 장비 점검·시선·거리 | 특정 인물의 계급·명령권·미공개 소속 |
| 전투 후 작업대 | 수리된 흔적, 무기 내려놓기, 피로와 대화 | 영구 부상·사망·해금 같은 새 서사 |
| 밤의 객차 | 창 밖 차가운 풍경과 내부 따뜻한 빛 | 항상 안전한 세계·불필요한 친밀도 시스템 |
| 큰 철도 구조물 앞 정차 | 작은 인물/열차와 거대한 잔존 인프라 | 새로운 지역이 반드시 플레이 가능하다는 광고 |
| 위협 관측 | 전방 공간, 준비 자세, 센서/시선 방향 | 그림만으로 새 조작·표적 지정 기능 생성 |

다인 장면에서는 중심 행동 하나를 먼저 정한다. 모든 인물이 정면으로 서서 무기를 든 카탈로그 구도를 기본값으로 삼지 않는다. 현재 작전에 선택한 인물을 보여주는 장면이라면 실제 5인 구성과 일치시키고, 고정 홍보 로스터 이미지는 게임플레이 캡처와 구분한다.

따뜻함·휴식·자연은 생존 세계와 양립할 수 있다. 조용한 장면까지 강제로 위협·연기·상처를 더해 감정 폭을 없애지 않는다.

## 8. 스킬 컷신: 하루 한 번 / 항상 표시 / 요약 연출

**사용자 확정:** `DAILY / ALWAYS(ON) / OFF` 세 모드로 구분한다. ALWAYS는 매번 표준 전체화면, DAILY는 그날의 첫 재생 조건을 만족하면 같은 표준 전체화면을 사용하고 이후 요약한다. OFF는 이전 제안의 요약 연출을 사용한다. 실제 전체화면 재생 중에만 전투 유효 배속 0을 적용한다.

설정 의미·하루 집계·정지·입력·스킵의 전문은 [04 §14](04_COMBAT_RUN.md#skill-cinematic-policy)에 둔다. 여기서는 제작/구도를 정의한다. **직전의 OFF 무표시·부분 컷인 제거 해석은 최신 정정으로 폐기**한다. OFF에서는 요원의 부분 컷인·지휘관의 짧은 명령/전장 표현·별도 허용된 초토화급의 짧은 요약 컷신을 사용한다. 초토화 요약을 전체화면으로 재생하는 경우에만 일반 부분 요약과 달리 전투를 정지한다.

### 8.1 세 모드와 제작 대상

| 행동 | ALWAYS / DAILY 표준 재생 | OFF / DAILY 반복 요약 | 제작 중심 |
|---|---|---|---|
| 요원 궁극기 | 얼굴·대표 무기·핵심 동작의 전체화면 컷신 | 짧은 부분 캐릭터 컷인 + SD 궁극기 모션과 실제 FX | 캐릭터 고품질 원화와 인물 정체성 |
| 지휘관 스킬 | 명령 수신→장치 작동→전장 연결의 전체화면 컷신 | 짧은 명령 표시 + 실제 장치·표적·상태 FX | 열차·객차·방어 장치·명령 대상 |
| 별도 허용된 초토화급 | 대형 장치의 준비·작동·규모를 보여주는 전체화면 컷신 | 짧은 전용 요약 컷신 + 실제 발사·탄도·명중. 전체화면 사용 시 전투 정지 | 장갑열차의 기계적 규모 |
| 기본 공격·자동 액티브·패시브 | 새 컷신 대상 아님 | 동일 전장 모션·FX | 실시간 전투 모델 |
| 파생 보조 포격·방벽 | 원래 연출 또는 전장 FX. 독립 컷신 재귀 없음 | 실제 추가 효과만 | 현재 효과 상태 |

DAILY와 ALWAYS는 **같은 전체화면 자산**을 사용한다. 재생 빈도 설정 때문에 하루 한 번 전용 영상을 별도로 만들지 않는다. DAILY에서 이미 본 스킬은 OFF와 같은 요약 연출을 사용한다. 동일 원화를 요약에 재사용할 수 있으나 표준 전체화면을 단순 고속 재생해 요약을 대체하지 않는다. 초기 기본값 DAILY 및 스킬별 하루 첫1회는 [04 §14.6 권장안](04_COMBAT_RUN.md#cinematic-daily-policy)으로 구분한다.

정확한 재생 길이는 실제 스킬별 장면 구성에서 결정한다. 요약 연출의 기존 비교값은 요원 부분 컷인 약0.8~1.2초, 일반 지휘관 명령 표시 약0.2~0.4초, 별도 허용된 초토화 요약 약2~3초다. 이는 확정된 스킬 시전시간이나 표준 전체화면의 길이가 아니다. ALWAYS는 반복 사용도 표준 전체화면이고, 사용자가 스킵할 수 있다.

### 8.2 전체화면 요원 궁극기 — 캐릭터 중심

공통 구성은 `고유한 실루엣/얼굴 등장 → 대표 무기·손·시선과 핵심 행동 → 화면 방향을 실제 전장에 연결 → 원래 HUD 복귀`다. 두 번째 릴스의 얼굴·머리·재질·인물 중심 조명 품질을 여기서 크게 보여준다. 실제로 일어나지 않은 처치·적 수·피해 수치를 고정 영상으로 보증하지 않는다.

Reina 예시는 포니테일·딥레드 코트·권총을 유지한다. 전체화면을 이유로 새 소총·변신·추가 타격을 만들지 않는다. 현재20~29의 개인 장면 본문과 교차 검토 보완을 수록했다. 얼굴만 교체한 동일 원화로10명을 대체하지 않고 공통 전환/프레임만 재사용한다. 개인 장면은 스킬 효과·횟수·이동을 새로 확정하지 않는다.

### 8.3 전체화면 지휘관 스킬 — 열차 중심

오른쪽 지원 버튼3개에 실제 매핑된 지휘관 스킬은 각각 대응하는 전체화면 연출을 준비한다. 공통 베이스를 공유할 수 있으나 공격·방어·수리·기동 등 실제 기능이 식별되어야 한다. 미확인 스킬 이름·장치·직접 피해를 임의 확정하지 않는다.

공통 구조는 `명령 수신 → 허용된 장치/객차/출력부의 반응 → 실제 기능을 설명하는 작동 → 전장 복귀`다. 지휘관의 미정 얼굴/성별/복식을 새로 만들어 필수 주인공으로 삼지 않는다. 수리 스킬에 공격 포격을, 실제 방벽이 없는 스킬에 방벽을 그리지 않는다.

초토화급은 규모를 크게 표현할 수 있지만 **포탑별 궁극기는 만들지 않는다.** 파괴된 객실·전투불능 포탑이 정상 작동하는 그림은 허용 상태와 대조한다. 총력전 보조 포격·이동요새 방벽을 독립 컷신으로 무한 발동시키지 않는다.

### 8.4 OFF·DAILY 반복 — 요약 연출

요원 궁극기는 얼굴·상반신·대표 무기가 읽히는 짧은 부분 컷인을 사용하고, 실제 SD 궁극기 모션·발사·명중으로 시선을 이어준다. 일반 지휘관 스킬은 짧은 명령 접수 표시와 실제 장치 작동·회복·방어·기동 FX로 요약한다. 이 두 부분 연출 동안 전투는 계속 진행한다.

요약 화면은 지원 버튼3개·핵심 위험 예고·분기/스로틀 입력을 가리지 않도록 위치와 크기를 검수한다. 겹치는 요약 표시는 장식 프레임을 축소/통합할 수 있지만 실제 스킬 효과와 경고를 생략하거나 전투를 지연하지 않는다. 요약 레이어가 화면 뒤의 조작을 뜻하지 않게 가로채지 않게 한다.

별도 허용된 초토화급은 이전 제안대로 준비·작동·전장 연결을 짧게 압축한 전용 요약 컷신을 사용한다. 전체화면으로 보여줄 때에는 전투배속0·입력 차단·스킵·안전 복귀를 표준 전체화면과 동일하게 적용한다. 이는 모든 일반 지휘관 스킬의 OFF를 전체화면으로 만드는 허가가 아니다.

요약 연출로 스킬의 실제 시전·조준·비행시간·타격 횟수를 줄이거나 피해·보상을 새로 만들지 않는다. 전체화면 자산과 얼굴·손·무기·빛 레이어를 공유할 수 있으나 요약의 안전 크롭과 타이밍은 따로 제공한다. 분리 원본을 재사용할 수 있는 상황에 독립 원화 두 벌을 무조건 요구하지 않는다.

### 8.5 제작 방식과 납품

**2D 모션 일러스트 + 실제 전장의 SD/장치 모션·FX**를 기본 시제품 제작안으로 둔다. 전체화면은 화면 점유 방식이며 반드시 MP4나 신규3D 파이프라인을 뜻하지 않는다. 분리 원화·제한된 카메라/파츠/빛·음향을 조합하고, 도구/패키지는 기존 프로젝트와 실제 검증 후 선택한다.

스킬별 납품에는 전체화면 장면 구성(DAILY/ALWAYS 공용), OFF·DAILY 반복용 부분 컷인/명령/초토화 요약 구성과 실제 전장 동작/FX, 분리 원본, 실제 skillId와 안정적인 컷신 그룹 매핑, HUD·카메라 복귀점, 첫 가시 프레임·스킵/오류 종료점, 자산 revision을 포함한다. 실제 ID는 확인하고 일반 자산 revision을 일일 시청 초기화 키로 쓰지 않는다.

개인 바이블은 인물의 표준 전체화면·부분 요약 컷인과 실제 SD 동작을 담당하고, 날짜·시청 기록 전문은 복사하지 않는다. DAILY의 시청 시작 표식을 제작물에 연결하는 세부는 04의 권장안이 승인된 뒤 구현한다.

### 8.6 재생·검수 경계

실제 전체화면 재생 중에는 전투 시계를 멈추고 presentation clock만 진행한다. 표준 전체화면과 초토화 요약 전체화면에 동일하게 적용하며, 요원 부분 컷인·일반 지휘관 명령 요약에서는 전투를 계속 진행한다. 전투가0이어서 컷신도 정지하거나, 영상이 없는데 전투만 멈추는 경우 모두 불합격이다. 스킵·자산실패·백그라운드·점검·복원은 [04 §14](04_COMBAT_RUN.md#cinematic-input-recovery)를 따른다.

실제 전투와 OFF에서는 위험/필수 정보가 우선이다. 전체화면에서는 스킵·안전 메뉴·필수 서비스 오류 안내를 접근 가능하게 한다. 세 모드와 스킵 여부가 같은 시뮬레이션 입력의 실제 피해·비용·보상을 바꾸지 않아야 한다. 재생시간은 달라질 수 있고 서버 실시간은 계속 진행한다.

## 9. 캔버스·레이어 납품 — 후보 규격

실제 게임 root **720×1280**은 [04](04_COMBAT_RUN.md)의 화면 기준이다. 위 원본 해상도는 이번 제작 비교안이지 원격 번들/메모리 예산 승인값이 아니다. 확대 보기와 축소 실사용 화면을 둘 다 확인한다.

필요한 논리 레이어는 BG_Far, BG_Mid, Playfield, Character_A/B, Prop, Shadow, Light, Atmosphere, FX, Foreground다. 사용하지 않는 빈 레이어를 의무로 만들지 않는다. 작은 카메라 이동을 고려한다면 가려진 배경과 인물 뒤쪽 형태를 복원해 구멍이 나지 않게 한다.

텍스트·공지·확률·보상·버튼·캐릭터 이름을 배경에 구워 넣지 않는다. 소스 원본, 분리 레이어, 합성 확인본, 사용처/크롭 가이드, 권리·출처·승인 기록을 함께 관리한다. 영상 원본이나 발췌 프레임은 게임용 납품 자산에 포함하지 않는다.

## 10. 첫 제작 순서안

## 궁극기 컷신 준비·메모리·재생 실패 상세 — 2026-10-20 / 신규 제안
Plan 소유. 컷신 전용 제작 착수에 맞춘 다음 설계이며 구현/새 품질 옵션 승인 아님. 기존04#combat-resource-lifecycle-approved-20261019 및04#skill-cinematic-policy·18의 오리진형/스킵 계약 유지. 목표는 컷신 품질을 확보하면서 전투 중 다운로드 대기·효과 지연·중복 발동을 만들지 않는 것이다. 첫 제작 대상 닉스→이브, 카일/레이나 보류, 세라 이번 제작 제외.

### 선택안과 책임
전원 컷신 상시 상주는 초기 비용이 크고, 사용 버튼 이후 준비는 전투 대기를 만들므로 기본안은 **실편성의 작은 요약 자산 우선 준비 + 현재 사용 가능한 표준 컷신만 제한 예열**이다. 실제 예산/파일 형식 확인 전 동시 보유 개수나 MB 상한을 임의 고정하지 않는다. 표준을 전편성 상주할지 순차 예열할지는 동일 기기 측정 후 선택하며 준비되지 않은 표준 때문에 스킬을 막지 않는다.
행동 소유자는 궁극기 수락/효과를, 연출 조정자는 표준/요약/대체 선택과 hold 수명을, 기존 자산 소유자는 검증된 버전의 준비/대여/반환을 맡는다. 재생기가 피해/비용/치유/드론 생성 명령을 발행하지 않는다. 새로운 전역 관리자를 기본 구조로 추가하지 않는다.

### 사전 준비와 자산 상태
- 출격 준비의 실제 편성/콘텐츠 버전으로 필요한 요약·표준 ID를 찾고 유효한 로컬 자산을 재사용한다. START 확정 응답과 달라진 부분만 다시 준비한다. 편성 바뀌면 이전 준비 세대를 취소하되 공유 자산을 파괴하지 않는다.
- 전투 필수 모션/예고/최소 FX를 먼저 준비한다. 컷신은 선택 연출이므로 표준 실패를 전투 필수 실패로 승격하지 않는다. 요약도 준비되지 않으면 실제 전장 모션/효과를 사용한다.
- 원천 버전·자산 ID·파일 검증 상태·현재 소비 세대를 함께 확인한다. 파일 존재와 재생 준비 완료를 구분한다. 준비 완료는 필요한 리소스 및 최초 표시 가능한 프레임을 확보한 상태다.
- 실제 패키지 형식은 제작 결과와 Unity 지원 경로로 정한다. 영상/레이어 애니메이션 중 하나를 문서만으로 강제하지 않는다. 지원하지 않는 코덱/색·alpha는 실패로 기록하고 임의 재생 성공 처리하지 않는다.
- 게임플레이 API를 컷신 클릭마다 조회하지 않는다. 자산 취득 요청과 게임 상태 API는 별도 집계한다. 외부 다운로드가 필요한 배포 구조라면 기존 다운로드 동의·네트워크 정책을 따른다. 이번안으로 새 대용량 자동 다운로드 권한을 만들지 않는다.

### 실행 시 선택과 실패
| 조건 | 표시 | 전투 처리 |
|---|---|---|
| ALWAYS/DAILY 표준 대상 + 표준 준비 완료 | 표준 전체화면 | 기존 안전 경계에서 자기 hold 획득, 별도 연출 시계 |

부분 요약과 기존 별도 허용 전체화면 요약의 hold 규칙을 혼동하지 않는다. 재생이 진행되지 않는 정지를 감지할 때에는 준비/재생 시작/프레임 진전/종료를 구별하고 검증된 정상 길이·기기 조건에 맞는 감시 기준을 사용한다. 일률적인 임의 초 제한을 전투 규칙으로 넣지 않는다. 감시 실패에도 공통 종료는 멱등이며 메뉴의 다른 hold를 해제하지 않는다.
DAILY 시청 인정 시점은 기존04 원계약을 재사용한다. 자산 미준비를 정상 시청 완료로 임의 기록하지 않으며 준비 완료 뒤 지난 궁극기를 뒤늦게 재생하지 않는다. 같은 사용의 실패 후 요약→표준 승격 재생도 없다.

### 메모리·교체·화면 수명
압축 파일의 디스크 보관과 디코드된 화면/텍스처 상주를 분리한다. 공유 배경·효과는 동일 ID/버전으로 대여하고 캐릭터마다 전체 복제하지 않는다. 현재 재생 자산은 사용 중 임의 회수하지 않으며 메모리 부족 시 미사용 예열부터 반환한다. 다음 재생은 준비 상태에 따라 대체한다.
종료 시 재생/음향/화면 소비 중지→callback 세대 격리→소유 인스턴스/렌더타깃 반환→자산 대여 반환. 재사용 보관은 측정 예산과 owner가 있는 범위만 허용한다. 매번 강제 GC/전체 캐시 삭제 금지. 동일 run 내 재사용 이득과 컷신 연속 사용 peak를 함께 측정한다.
백그라운드/해상도 변경은 기존 앱 hold·렌더 복구 계약 사용. 렌더 복구 불가 시 안전 종료하며 과거 스킬을 재요청하지 않는다. 재접속은 현재 원전장 상태로 복귀하고 지난 컷신은 다시 재생하지 않는다. 구버전 다운로드/로드가 늦게 끝나면 현재 캐릭터/계정/씬에 붙이지 않는다.

### 사용자 표시와 개발 진단
전투 중 컷신 다운로드 팝업·기술 오류·메모리 수치를 띄우지 않는다. 정상 대체는 전장 연출로 자연스럽게 이어진다. 준비/다운로드 안내가 필요한 경우 기존 출격 준비/설정 흐름을 재사용하며 새 설정 탭은 추가하지 않는다. 오류가 원게임 재개까지 막는 경우에만 기존 복구 안내를 사용한다.
DEV만 자산 버전·표준/요약/대체 이유·준비시간·재생 시작/종료·hold 획득/해제·scope별 메모리와 해제 결과를 복사 가능한 형태로 확인한다. PRD는 기존 승인 오류 수집 규칙으로 정제된 중요 실패만 전송하며 토큰/파일내용/사용자 식별 원문은 넣지 않는다. 정상 대체마다 서버 로그를 무한 생성하지 않는다.

### 첫 검수와 담당 경계

Cutscene 담당은 승인 원본·독립 레이어/영상·길이/전환·정상/요약 산출물을 소유, Unity는 기존 로더/연출 조정/hold·Player 검수, Server는 실제 필요한 기존 콘텐츠 버전/원행동 응답만 소유한다. 컷신 재생 전용 게임 API를 임의 신설하지 않는다. 이번은 설계 제안 저장이며 실행큐 등록·실제 리소스 포맷 변경·압축·Player 시험 없음.

## 궁극기 연속 발동·컷신 순서·요약 중첩 상세 — 2026-10-20 / 신규 제안
목표: 여러 궁극기가 확정되어도 누가 사용했는지 읽히고 전투 판정·입력·일시정지가 뒤섞이지 않게 한다. 기존04#cinematic-input-recovery의 사건 승인 순 직렬재생, 연속 전체화면 사이 전투tick0, DAILY 차례별 재확인, 요약축소/통합, 입력저장금지 기준을 구체화한다. 신규 세부 표현은 제안이며 앞 #ultimate-resource-ready-proposal-20261020도 미승인 유지. 원행동 우선순위/대상선정/자동궁극기 기능을 추가하지 않는다.

### 1. 순서와 식별
원행동 owner가 이미 수락한 사건만 표시 대상으로 받는다. 계정/run/노드 세대와 원사건 ID로 중복을 제거하고 같은 사건 재수신으로 영상을 다시 넣지 않는다. 순서는 원사건 순번이며 도착 callback 시각·요원 등급·화력·화면 슬롯순으로 재정렬하지 않는다. 순서 정보가 없는 경우 연출 View가 임의 순번을 생성하지 않고 기존 사건 스트림의 순서 계약을 사용한다.
전체화면은 하나씩 재생한다. 동시 화면분할은 얼굴/손/기체 가독성을 떨어뜨리고 단순 최신 한 개만 남기는 방식은 ALWAYS 정책을 바꾸므로 채택하지 않는다. 대기 목록에는 원사건 참조와 표시정보만 두며 전체 영상/전장 snapshot을 항목마다 복제하지 않는다. 미승인 입력을 예약하거나 hold 중 게임플레이 입력을 저장하지 않는다.

### 2. 연속 재생과 스킵
현재 표준 종료 시 같은 안전 경계에서 다음 확정 표시를 검사한다. 다음도 전체화면이면 전투tick이 끼지 않도록 hold 이전을 보장하되 각 표시 작업의 종료는 한 번씩 처리한다. 단순 release 후 다음 프레임 acquire로 전투가 잠깐 진행되는 구조를 쓰지 않는다. 입력 차단도 같은 연속구간에서 유지한다. 마지막 전체화면 뒤에는 자기 hold만 반환하고 다른 메뉴/점검 hold가 남으면 전투를 재개하지 않는다.
스킵 버튼은 **지금 재생 중인 한 편만** 종료한다. 다음 편까지 자동 스킵하거나 궁극기를 취소하지 않는다. 버튼을 누르고 있는 동안 다음 편이 연쇄 스킵되지 않도록 새 입력 edge가 필요하다. 더블탭의 이전 표시 세대 입력이 다음 편으로 전달되지 않는다. 이번안에 별도 ‘모두 스킵’이나 자동 설정 변경은 추가하지 않는다.
표시 모드는 원행동 승인 때 캡처한다. 재생 중 설정 변경은 이후 새로 승인된 행동부터 적용하고 이미 확정된 대기항목에 소급하지 않는다. DAILY만 자기 차례에 기존 스킬별 시청 기록을 재확인한다. 첫 가시 프레임 전 실패/실제 시작 후 스킵의 시청 여부는04의 최신 승인 기준을 소비한다. 대기 등록 자체로 시청 기록을 남기지 않는다.

### 3. 사용자 표시
전체화면은 기존 스킵 위치를 유지하고, 다른 확정 표준이 남았을 때만 작은 ‘다음: 요원 이름’ 표시를 제안한다. 해당 이름은 현재 사건의 기존 표시 데이터에서 읽고 새 API를 호출하지 않는다. DAILY 판정/자산 준비에 따라 변경될 수 있으므로 확정되지 않은 총 재생 편수·남은 초를 보여주지 않는다. 다음 표시가 요약으로 바뀌거나 종료되면 이름 안내도 갱신/제거한다.
이 표시는 관람 안내이며 클릭 가능한 스킬 예약 목록이 아니다. 클릭/드래그 재정렬·대상 변경·게이지 차감 없음. 원화/대표 장비/스킵·필수 오류 안내를 가리지 않도록 독립 텍스트로 두고 영상에 굽지 않는다.

### 4. 부분 요약이 겹치는 경우
전투는 계속 진행하며 요약을 순서대로 다 볼 때까지 효과를 기다리지 않는다. 기본안은 확대 인물 컷인 한 개를 우선 표시하고, 겹쳐 수락된 다른 행동은 동일한 기존 요약 영역의 작은 초상/이름으로 통합한다. 사용 순서를 유지하고 동일 이름이어도 서로 다른 원사건을 잘못 중복 제거하지 않는다. 이미 화면에서 지난 사건을 긴 장식 대기열로 뒤늦게 재생하지 않는다.
실제 지원 버튼·위험예고·HP/다운 표시가 우선이다. 자리가 부족하면 장식 초상을 생략하고 실제 전장 모션/효과를 유지한다. 실제 탄·총구·영역 위치를 빈 공간으로 옮기지 않는다. 작은 표시의 노출시간/최대 열 수는 실기기 화면 검수에서 확정하며 새 전투시간으로 사용하지 않는다. 전체화면과 부분 요약이 같은 경계에 섞이면 원사건 순서는 유지하되 부분 요약 때문에 새 hold를 만들지 않고, 화면 아래 오래된 요약이 복귀 후 재출현하지 않게 한다.

### 5. 원효과와 예외
| 사례 | 표시 결과 | 보존할 원판정 |
|---|---|---|
| 닉스→이브가 같은tick에 수락 | 원순서대로 표준, 또는 각 모드에 맞는 요약 | 닉스 영역/이브 장치 사건의 원시간과 순서 |
| 첫 표준 스킵→둘째 표준 | 현재 편만 종료, 둘째 정상 시작 | 추가tick/추가게이지 소비0 |
| 한 항목 자산 실패 | 해당 영상 안전 종료/기존 최소전장효과, 다음 유효항목 진행 | 원궁극기 1회, 큐 전체 실패/재시전0 |
| 수혜자 변경·부분 성공 | 현재 확정 상태와 실결과만 전장에서 표시 | 영상에서 임의 부활/기체복제/성공 대상 추가0 |
| 노드 종결/작전 만료/계정 전환 | 해당 세대의 현재·대기 장식 종료 | 기존 종결/복구 규칙 우선, 원효과 취소를 View가 결정하지 않음 |
| 백그라운드/안전메뉴 | 기존 앱/메뉴 정지 규칙 적용 | 자기 컷신 종료가 다른 hold를 해제하지 않음 |
| 재접속 | 과거 장식 큐 재생 없이 현재 전장 복원 | 원행동 상태/영수증 재사용, 다시 사용하지 않음 |

이미 발동한 요원이 다운됐다는 이유로 비용을 돌려주거나 발사된 탄을 없애지 않는다. 반대로 원행동이 취소된 경우 성공 컷신을 새로 시작하지 않는다. 큐가 소유하는 것은 표시 수명뿐이다.

### 6. 수용·담당
Unity는 기존 원사건 스트림/연출 조정자의 직렬재생·세대·hold·입력 수명으로 구현, Cutscene 담당은 표준/요약 안전영역과 전환 시작/끝을 제공한다. Server의 기존 행동 순서 계약을 재사용하고 연출용 신규 승인 API를 만들지 않는다. 새 상세안 승인/선행 준비 전 실행큐에 넣지 않는다.
필수검수: 닉스→이브 및 역순, 같은 사건 중복 전달, DAILY 동일 스킬 첫 시작/실패/반복, 현재스킵/길게누르기/더블탭, 설정변경 전후 수락 사건, 첫/둘째 자산 실패, 전체화면+요약 혼합, 메뉴hold중첩, 노드종료/세대변경, 재접속. 동일 초기상태·tick입력으로 ALWAYS/DAILY/OFF/스킵의 비용·HP·장치/영역 수·효과 사건을 비교한다. 표준 사이 전투tick0, 컷신 실시간의 delta몰아처리0, 화면 가림/입력누출0을 실제Player에서 확인한다. 이번턴은 원문 대조·상세안 작성만 수행했고 구현/재생 검수는 하지 않았다.

## 궁극기 음향·전투음 전환 상세 — 2026-10-20 / 신규 제안
Plan 소유. 기존 개인 콘티의 음향 cue와04 presentation clock·전체화면 hold·요약중 전투진행,18 승인 ready-sequence 계약을 구체화한다. 목표는 궁극기 고유 인상을 살리면서 실제 위협/발동을 소리로 오인하지 않고 스킵·실패 뒤 음향 상태를 복원하는 것. 새 음성 녹음/합성·라이선스 구매·외부 음악 수집·전용 설정 메뉴 신설은 이번 제안에 포함하지 않는다. 기본 앱 채팅 알림음과 무관한 게임 전용 설계다.

### 1. 표시 방식별 믹싱
전체화면은 기존 BGM의 재생 위치를 유지하면서 상대 음량을 낮추고 컷신 전용 효과음을 중심으로 한다. BGM을 매번 처음부터 다시 시작하지 않는다. BGM 완전 정지는 연결감이 끊기고 모두 원음량 유지는 경쟁하므로 완만한 음량 전환을 기본 제안으로 선택한다. 정확한 감쇠량/전환 시간은 실제 음원과 기기 검수에서 확정하며 임의 dB를 승인값으로 삼지 않는다.
전투 정지 동안 새 전투 사건 소리를 생성하지 않는다. 이미 재생 중인 짧은 실제 타격 잔향은 자연 종료, 전투 시간에 묶인 지속장치 루프는 기존 owner에 맞춰 정지/복귀한다. 환경 바람·철도 소리는 장식 환경 bus에서 낮추되 전체 AudioListener 정지로 UI/스킵까지 멈추지 않는다. 특정 미들웨어 도입은 요구하지 않는다.
부분 요약은 위험 예고·실제 발사/명중·사용자 입력 피드백을 우선한다. 짧은 정체성 cue만 쓰고 큰 정점음/긴 잔향/전장 전체 볼륨 급변을 피한다. 여러 요약이 겹치면 실제 효과음을 보존하고 장식 cue를 축소한다. 장식이 생략됐다고 실제 사건을 늦추거나 뒤늦게 소리 대기열을 재생하지 않는다.

### 2. 닉스·이브 첫 제작 cue
| 요원/장면 | 소리의 의도 | 금지/확정 경계 |
|---|---|---|
| 닉스 진입·촉매 근접 | 가늘게 흐르는 공명, 열린 타원의 공간감 | 발사/피해 성공음 아님 |
| 닉스 공간 확장·손 이동 | 낮게 퍼졌다 모이는 곡선 질감 | 적 끌어당김·시간정지·심박 정지 효과를 암시하지 않음 |
| 닉스 경계 닫기 | 짧고 명료한 정렬음, 긴 잔향은 복귀 전에 감쇠 | 실제 영역 tick음은 원tick 사건만 발생 |
| 이브 얼굴·장갑 지시 | 작은 조작/확인 cue | 시스템 오류 경고음과 구분, 지휘만으로 발사음 없음 |
| 이브 기체 응답·정점 | 승인된 동일 기체의 구동/강화 응답 질감 | 실제 존재 분기에 맞춰 사용; 없는 기체의 엔진/추가 기체 다중음 금지 |
| 이브 전장 복귀 | 지휘 cue 종료 후 현재 장치 루프에 합류 | 원드론 발사 주기 초기화/장식 사격 추가 없음 |

두 요원 요약은 진입 식별 cue 하나와 짧은 마무리 중심. 표준 오디오 전체를 배속해 겹쳐 넣지 않는다. 위는 제작 지시용 음향 성격이며 실제 음원 제작 완료를 뜻하지 않는다. 최종 음성 미승인 상태에는 무대사로도 완결되는 편집을 사용하고 placeholder 음성을 최종 asset으로 배포하지 않는다. 향후 음성을 사용할 경우 승인 대사/권리/기존 음성 설정을 확인한다.

### 3. 발동음의 소유와 중복 방지
장갑 조작·상징 수렴·전환 공명은 presentation 소유, 실제 탄 발사/명중/치료/영역tick/장치 생성은 원사건 소유다. 컷신 타임라인에 실제 성공음을 복제하지 않는다. 같은 실제 사건이 원전장과 컷신 복귀 경로로 재수신되어도 원사건 ID·효과종류·해당 대상/실제 하위hit 식별자로 1회 재생한다. 다단/다중대상을 한 사건이라고 잘못 합쳐 정상음을 제거하지 않는다.
영상에 최종 BGM/음성/SFX를 하나로 굽기보다 기존 음량 분류로 개별 제어 가능한 형태를 우선한다. 무음 영상/분리트랙 또는 동일한 제어가 가능한 기존 형식을 사용한다. 타이밍 cue와 원전장 소리가 구별되는 납품 목록을 작성하고 고정 형식/엔진 패키지를 새로 강제하지 않는다.

### 4. 연속 재생·스킵·오류
- 표준 A→B: A의 장식 루프/예약 cue는 종료하고 B 시작. 중간에 BGM을 정상음량으로 올렸다 다시 낮추는 출렁임 없이 연속 연출 구간의 믹스 상태를 유지한다. A 음성이 B에 겹쳐 이어지지 않는다.
- 현재편 스킵: 해당 표시가 소유한 음성/장식/예약 cue만 종료. 클릭 잡음 방지용 짧은 감쇠가 필요해도 게임 hold 종료나 다음편 시작을 기다리게 하지 않는다. 전투음/메뉴음 전체 일괄 stop 금지.
- 재생/디코드 오류: 자산 실패 공통종료에서 자기 음향 조정 토큰도 반환한다. 실제 스킬 소리를 다시 발생시키지 않는다. 음향만 누락된 경우 영상/원전투를 실패로 취소하지 않으며 정제된 진단에 남긴다.
- 메뉴/백그라운드: 기존 앱·메뉴 정책의 음향 제어와 컷신 조정을 독립 소유. 컷신이 끝났다고 다른 정지/감쇠를 해제하지 않는다. 복귀 시 현재 시각 이후 cue만 재생하고 정지 중 지나간 소리를 몰아서 재생하지 않는다.
- 사용자 음량/무음 변경: 기존 설정 owner의 최신 값 위에 상대 믹스만 적용한다. 종료 시 시작 때 저장한 절대 음량을 덮어써 사용자의 변경을 되돌리지 않는다. 무음에서도 모든 장면·스킵·원효과가 정상 동작한다.
- 노드/계정/표시 세대 변경: 구 cue callback을 격리하고 자기 루프/대여 참조를 반환. 재접속 시 지난 대사/정점음/발사음을 다시 들려주지 않는다.

### 5. 검수와 역할
Cutscene 담당은 장면별 cue표/독립트랙·실사용 음원 출처/임시·최종 구분·표준/요약 타이밍, Unity는 기존 오디오owner/믹서·원사건 중복방지·hold/세대 수명·설정 복구를 소유한다. 원음 파일을 빌려쓰는 소비자가 공유 음원을 파괴하지 않는다. 실제 사용권 미확인은 후보로 남긴다.
닉스→이브와 역순, 표준→요약, 연속스킵, 음원없음/디코드실패, 전장 발사와동시발동, 메뉴hold/백그라운드, 무음·SFX/BGM 기존설정 변경, 노드전환/재접속을 실제 지원 기기에서 검사한다. 잔류루프0·동일실제사건 중복0·사용자설정복원 오류0·위험예고 식별·전환 클릭/과도음량·모바일스피커/헤드폰 가독성을 확인한다. 단순 파형 정상이나 테스트 PASS를 청취검수 완료로 간주하지 않는다. 이번턴은 상세안 작성만 했으며 실제 음원 생성/청취/Player검수·작업큐등록 없음.

## 모바일 컷신 화면비·안전영역·터치 복귀 상세 — 2026-10-20 / 신규 제안
기존18 안전크롭/인물왜곡금지 및04#cinematic-input-recovery를 구체화한다. 목표는 실제 지원 화면에서 핵심 포즈와 조작이 보이고 스킵 직후 의도하지 않은 전투 입력이 발생하지 않는 것이다. 새 가로모드/태블릿 지원·화면회전 기능을 이번안으로 추가하지 않는다. 현재 지원 범위를 Unity 설정/실기기로 확인한다. 음향 첫후보 제작 승인은 유지하며 앞 음향 믹싱 전체안은 여전히 제안이다.

### 화면 구성 원칙
화면을 무조건 가득 채우는 중앙크롭은 장비를 자를 수 있고, 전영상을 같은 축척으로 축소하면 인물/표시가 작아지므로 **핵심 인물 구도 보존 + 독립 배경 확장**을 우선 제안한다. 기존 배경에 확장 여지가 없으면 승인 색/재질의 여백으로 안전하게 맞추며 인물을 가로로 늘리거나 없는 배경을 런타임에서 임의 생성하지 않는다. 중앙크롭은 해당 장면의 핵심 영역을 보존하는 범위만 허용한다.
화면 전체 장식 영역과 실제 safe area를 구분한다. 배경/장식 광은 노치 뒤까지 이어질 수 있으나 얼굴·대표 손동작·대표 장비의 필수 부분은 해당 장면의 보호영역 안에 둔다. 스킵·다음요원·필수 오류 안내는 safe area 내부의 독립 UI다. 영상에 문구/스킵버튼을 굽지 않는다.
모든 컷에서 전신/양손을 억지로 보이는 기준은 아니다. 눈 클로즈업은 눈, 장비 클로즈업은 해당 손과 장비 접점, 정점은 얼굴·양손·대표장비를 보호한다. 의도한 클로즈업 잘림과 화면비 때문에 생긴 잘못된 잘림을 구분한다.

### 닉스·이브 장면별 필수 영역
| 대상 | 보호할 영역 | 조정 가능 영역 |
|---|---|---|
| 닉스 눈/촉매 근접 | 눈과 열린 타원 개구, 왼손 그립이 나오는 컷에서는 접점 | 바깥 곡선 장식·배경 가장자리 |
| 닉스 경계 닫기 정점 | 얼굴·왼촉매·오른손 경계 제어 | 망토 끝 일부/상징 공간 외곽, 원화 검토 범위만 |
| 이브 장갑 지휘 | 눈/모자 정체성 컷과 장갑 손목 연결 | 주변 배경광 |
| 이브 기체 응답 정점 | 인물 지휘손·얼굴과 실제 동일 드론의 양 포드/중심 | 기체 주변 장식 공간; 포드를 잘라 다른 구조로 보이게 하지 않음 |
| 부분 요약 | 작은 화면에서도 식별 가능한 얼굴/대표동작 | 장식배경/긴 잔광 |
컷신 담당은 장면별 보호영역·안전크롭 범위를 정규화 좌표와 비교 이미지로 제공한다. Unity는 그 범위와 현재 safe area로 배치하며 임의 중심 추정으로 장면 전체를 매번 다른 위치에 놓지 않는다. 픽셀 수치는 실제 산출물/화면 측정 후 기록한다.

### UI와 화면 변화
스킵 버튼은 기존 입력 최소크기/폰트/대비 정책을 재사용하고 배경 광의 밝기에 묻히지 않게 독립 바탕을 둔다. 빈 투명 장식 영역이 전장 입력을 임의 가로채는 버튼으로 작동하지 않는다. 전체화면의 게임플레이 차단은 기존 연출 Controller가 담당하며 영상 사각형의 우연한 크기에 의존하지 않는다.
다음요원 안내가 길어도 스킵 영역을 침범하지 않는다. 허용 너비 안에서 이름을 줄바꿈/레이아웃 조정하고 실제 이름을 다른 이름으로 대체하지 않는다. 표준 영상에서 재생 중인 주체와 다음 주체를 구분한다. 요약은 위험 예고·지원/분기·HP/다운 정보를 우선하고 공간이 없으면 승인된 장식축소 규칙을 따른다.
지원되는 창 크기/해상도/safe area 변화가 발생하면 현재 연출 시각을 유지한 채 배치만 재계산한다. 영상·음향을 처음부터 재생하거나 DAILY 기록/원행동을 재확정하지 않는다. 크기 변경이 렌더 복구 실패로 이어지면 승인된 단일 종료·전장 대체 경로를 사용한다. 지원하지 않는 화면 회전을 새로 허용하지 않는다.

### 터치 시작·스킵·복귀
- 전체화면 진입 당시 진행 중인 게임플레이 포인터 입력은 기존 입력 owner의 취소 경로로 정리한다. 손을 떼었을 때 원래 버튼 클릭으로 완성하지 않는다. 기존 Controller 처리 재사용, View에 스킬 실행 코드를 복제하지 않는다.
- 스킵은 같은 표시 세대에서 버튼 안에 새로 시작된 유효 입력만 받는다. 영상 시작 전부터 누르고 있던 손가락, 밖에서 시작해 들어온 드래그, 화면 배치 변경으로 버튼이 손 밑에 이동한 경우는 자동 스킵하지 않는다.
- 스킵 후 해당 포인터의 남은 이동/떼기 이벤트는 전장/다음 컷신에 넘기지 않는다. 다른 손가락도 차단 중 시작된 입력이면 전투 명령으로 예약하지 않는다.
- 전투 복귀 후 새로 시작된 정상 터치는 바로 받는다. 오입력 방지를 이유로 고정 몇 초 전투 조작 금지나 추가 전투 hold를 만들지 않는다. 기존 메뉴/점검 차단은 그대로 유지한다.
- 요약 연출은 기존 전투 입력을 막지 않는다. 장식은 비상호작용, 실제 허용 UI만 자기 입력을 소비한다. 지원 버튼을 누르는 도중 요약이 나타나도 다른 명령으로 바뀌지 않는다.
- 입력/레이아웃 구독은 표시 수명에 맞춰 등록·해제한다. 풀 재사용 시 중복 콜백, 구표시 세대 스킵, 계정/노드 종료 뒤 재호출을 차단한다.

### 검수·담당·승인 경계
현재 지원 기기의 좁고 긴 화면/짧고 넓은 화면/노치·하단제스처 영역을 실제 값으로 목록화한다. 지원 미확정 기기를 합격 대상에 임의 추가하지 않는다. 각 장면의 시작/정점/끝과 전환 중간을 표준·요약으로 확인한다. 닉스 타원 개구와 손, 이브 장갑과 드론 양포드, 스킵 접근성, 긴 이름, 높은 장식 밝기, 배치변경을 비교한다.
입력 시험은 진입 전 누름 유지·밖에서 드래그·멀티터치·스킵 더블탭·스킵 직후 같은 위치 지원버튼·연속 두편·백그라운드 복귀·노드종료·풀재사용을 포함한다. 컷신 때문에 발생한 의도하지 않은 스킬/분기 입력0, 정상 새 입력 누락0, 원효과/비용 변화0을 실제Player에서 확인한다. 에디터 비율 미리보기와 실기기 터치 검수를 분리한다.
Cutscene는 자기 장면 원화/보호영역·안전크롭 비교를, Unity는 기존 View 배치/입력 Controller/수명·실기기 검수를 담당한다. 이 상세안은 신규 제안이며 실행큐·실크롭 변경·코드수정·기기검수를 수행하지 않았다. 승인 후에도 최종 자산 소비는 기존 선행완료 후속 규칙을 따른다.

## 컷신·효과음 조합 버전과 수정본 교체 상세 — 2026-10-20 / 신규 제안
목표는 컷신 길이/장면 수정 뒤 구음향이 섞이거나 재생 도중 원본이 바뀌는 것을 막는 것이다. 기존 자산준비/실패대체·원행동독립을 유지한다. 현재 Audio manifest-v01은 runtime_ready=false·청취미수행이고 닉스 QA도 원화/보드 미승인이다. 따라서 지금 파일들을 운영 승인 조합으로 발행하는 설계가 아니다. 원본 확인은 이 두 자료의 관련 범위이며 전체 제작물 재검수 아님.

### 1. 조합을 지정하는 원본
파일명 ‘최신’ 검색으로 자동 결합하면 장면이 어긋나고 모든 파일을 매수정 복제하면 낭비가 크다. 기존 자산 manifest를 재사용해 **승인된 영상/레이어 버전 + cue표 버전 + 음원 참조 버전**을 하나의 불변 조합으로 지정하는 방식을 제안한다. 같은 음원은 해시/ID로 재사용하며 조합마다 원본 WAV를 복사하지 않는다.
조합 기록의 필수 의미는 요원·궁극기 식별, 표준/요약 구분, 장면/자산 버전, cue표 버전, 독립음원 ID/해시, 재생 조건(이브 기체 유무 등), 기준 시간축·실길이, 요구 소비기능, 시각/청취/동기화 승인 근거다. 정식 runtime ID가 미확인이면 임의로 이름을 ID로 발행하지 않는다. 기존 정식 매핑과 연결 후 확정한다. 새 wire 필드명/API/패키지 도입은 실제 소비구조 확인 후 최소 변경한다.
제작 후보/개별승인/조합검수완료/실Player소비완료를 구분한다. 해시 일치는 파일 무결성 근거이며 시각 품질·사용권·실행 승인을 증명하지 않는다. 다음날 파일명만 바뀌어도 검증되지 않은 새 조합을 자동 사용하지 않는다.

### 2. 수정 종류별 재검수
| 변경 | 재사용 가능 범위 | 필요한 확인 |
|---|---|---|
| 원화 색/미세 윤곽만 변경, 장면시각 동일 | 검증된 cue 시간·독립음원 | 해당 장면 시각/alpha·새 자산 무결성, 실제 소비 참조 |
| 장면 길이/손동작/전환시각 변경 | 변경 없는 독립음원 | cue 시작/끝·중첩·스킵·표준/요약 동기화 재검수 |
| 음량/음색 편집 | 동일 타이밍을 검증한 영상 | 청취·경계/잔향·기존설정별 믹스 및 변경분 실제동기화 |
| 기체 존재/생성 성공 등 분기 변경 | 무관한 분기 | 조건과 cue 포함/제외, 실패/전장복귀 대조 |
| 표준만 수정 | 독립 요약의 무변경 근거가 있을 때 요약 | 새 표준의 관련 검수; 요약을 무조건 배속 재생성하지 않음 |
동작 정점이 바뀌면 길이 총합이 같아도 시간 변경으로 취급한다. 문서 길이를 바꾸는 것으로 실제 파일 길이·cue 검사를 대신하지 않는다. 구원본/승인근거 보존, 미승인 후보를 승인 파일 경로에 덮어쓰지 않는다.

### 3. 현재 재생과 새 조합
원행동 수락 후 실제 표시 준비를 할 때 지원 가능한 검증 조합을 선택하고 해당 표시 작업 동안 고정한다. 같은 표시에서 영상은 v2, 소리는 자동검색한 v3으로 갈아끼우지 않는다. 컷신 큐는 작은 조합 참조만 보유하고 원본 전체 복제 금지. 실제 발사/치료 등 원사건에는 영향을 주지 않는다.
새 조합은 준비/검증 후 안전한 표시 경계에서 다음 미선택 작업에 사용한다. 이미 선택·준비한 대기항목은 자기 조합을 유지하고 재생 중 교체하지 않는다. 다운로드/디코드 완료가 늦으면 현재 작업에 끼워넣지 않는다. 구조합 참조는 마지막 사용자가 반환한 뒤 기존 캐시/수명 정책으로 정리한다.
원 START 콘텐츠 버전이나 소비 계약이 구버전에 고정된 경우 그 경계를 우선하며 새 시각 조합을 강제로 섞지 않는다. 재접속에서 과거 영상 재생을 위해 구파일을 다시 받지 않는다. 현재 전투의 필요한 자산만 기존 복구계약으로 준비한다.

### 4. 누락·불일치·되돌림
표준 조합 불완전/미지원이면 승인된 요약 또는 최소 전장 효과로 대체한다. 같은 요원의 임의 다른 버전 음향으로 빈 부분을 채우지 않는다. 음원만 누락되고 해당 시각 조합이 무음 재생 가능하게 검증됐다면 시각만 진행하며 음향 누락을 진단한다. 무음이 전투정보 손실을 만드는 자산은 독립 시각 신호부터 보완한다.
되돌림은 호환·검증된 이전 조합을 다음 안전한 표시 경계에 선택하는 것으로 정의한다. 이미 실행된 궁극기/비용/DAILY/효과 상태를 되감지 않는다. 심각한 재생 오류는 현재 표시를 승인된 안전종료로 닫고 원전장으로 복귀한다. 이번안이 원격배포·파일삭제·운영버전 변경 실행 권한을 추가하지 않는다.
일반 사용자는 버전/해시/manifest 오류를 보지 않는다. DEV에 선택조합·차단/대체이유·실길이/소비기능·관련 QA를 복사 가능한 형태로 남긴다. PRD 중요오류는 기존 정제/중복집계 정책을 재사용, 새 상시조회·무한로그 없음.

### 5. 담당 간 인수와 합격
Cutscene는 장면/표준·요약/분기·시간표 변경을 자기 QA에 기록하고 Audio는 그 정확 버전에 맞는 cue/음원 참조와 청취·미검수 상태를 기록한다. Unity는 두 제작 원본을 임의 수정하지 않고 검증된 조합을 기존 로더/연출owner에 연결한다. 통합 담당 Plan은 승인/실Player 근거를 확인한다. 제작 세션 사이 자동폴링·중복원장 없이 필요한 작업 시 기존 문서를 확인한다.
첫 검수는 닉스·이브 각각 표준/요약·이브 기체유무, 길이변경·같은길이내정점변경, 음원누락/해시불일치/구소비기능, 대기/재생중 새버전완료, 스킵/오류, 이전조합 복귀로 구성한다. 실제 선택조합/화면/소리·원사건수를 함께 비교한다. 소리 파일 숫자검사만으로 영상동기화/실청취 통과라고 하지 않는다. 선행자산/조합검수 미완료는 후속 정의에 유지하고 실행소비 큐를 미리 완료하지 않는다.

## 컷신·음향 통합 시사회와 피드백 상세 — 2026-10-20 / 신규 제안

별도 운영 서비스/어드민 신규페이지 대신 **기존 컷신 검토 페이지에 음향 조합 미리보기 추가**를 제안한다. 새 갤러리/사용자 콘텐츠/운영 API·계정 기능은 만들지 않는다. 웹 미리보기는 제작 검토용이고 실제 Unity Player 검수를 대체하지 않는다.

### 화면과 기본 흐름
닉스/이브를 선택하고 표준/요약 및 이브 기체 분기를 고른다. 화면 상단에 후보 조합 버전과 ‘원화 후보/콘티 애니매틱/최종 영상’ 중 실제 상태를 표시한다. reference-only 보드 조각을 시간배치한 경우 ‘콘티 애니매틱·최종 인물 동작 아님’을 숨기지 않는다.
중앙에는 영상/레이어와 해당 cue조합, 아래에는 재생·정지·처음부터·현재시점·음량·무음·전체한편 스킵을 둔다. 처음 열 때 자동소리 재생 없음. 사용자의 재생 입력으로 준비된 같은 조합을 시작한다. 실제 전장 복귀가 없는 웹에서는 ‘복귀 예시’임을 명시하고 게임 실행 성공으로 표현하지 않는다.
부가 패널은 장면 목록/선택 구간 반복/배경 밝고어둡게·지원화면비 비교/이전 후보 A-B 비교. 기본화면은 현재후보 재생을 우선하고 기술 항목은 접어 둔다. 사용자가 소리를 듣는 동안 다른 cue 미리듣기를 누르면 기존 미리듣기는 종료하여 중복재생을 막는다. 후보 전환 때 이전 인스턴스/소리도 종료한다.

### 시간·소리 동기화
하나의 표시 시각을 기준으로 영상과 cue를 소비한다. 별도 HTML audio 여러 개를 동시에 눌렀다는 이유로 동기화 완료로 보지 않는다. 파일 로드 중에는 해당 검토 재생 준비 상태를 명확히 표시하고 불완전한 조합을 정상시청으로 기록하지 않는다. 이는 제작 페이지의 파일 준비 표시이며 전투 정보창의 조회로딩 UI를 복원하는 정책이 아니다.
드래그/장면 이동 시 기존 루프/잔향을 종료하고 새 시점에 맞는 상태만 복원한다. 탐색했다고 과거 단발 cue를 연속 재발생시키지 않는다. 구간 반복은 정확한 해당구간만 재생하며 매회 음향 인스턴스를 누적하지 않는다. 느린재생은 영상동작 분석용으로 기본 무음, 정상속도 청취와 구별한다. 음향을 변속해 들은 결과를 원음 품질 승인으로 사용하지 않는다.
A/B 비교는 같은 화면비·음량 설정과 비교기준을 유지한다. 시간표가 달라졌으면 원시간 동일 위치와 같은 장면 위치가 다름을 표시한다. 서로 다른 정점을 같은 시각으로 강제 보정해 동기화 문제를 숨기지 않는다. 실파형·음량 수치는 필요 시 기술패널에서 확인, 청취평가를 숫자로 자동대체하지 않는다.

### 수정 의견 복사
‘현재 장면 의견’으로 요원/표준요약/기체분기/조합버전/장면/시각/화면비와 사용자가 쓴 의견을 한 묶음으로 복사한다. 예: ‘닉스 · 표준 · 후보조합… · 05 · 3.42초 · 촉매가 손에 가려짐’. 비밀경로/토큰/계정정보는 포함하지 않는다. 이미지 캡처를 지원하면 같은 버전/시각으로 표시하고 자동 외부 업로드하지 않는다.
모바일 클립보드가 지원되지 않으면 읽기 전용 텍스트 선택·전체선택으로 복사할 수 있게 한다. 복사 성공 피드백은 실제 클립보드 성공일 때만 표시한다. 의견 작성/복사를 제작 담당에게 전송하거나 승인한 것으로 취급하지 않는다. 사용자가 채팅에 전달한 실제 의견을 기존 QA에 반영한다.

### 승인 범위
원화/콘티, 장면 동작·전환, 효과음 음색·크기, 영상과 소리 동기화, 실제Player 연결을 구분해서 기록한다. 웹 페이지에서 전부 자동합격/‘승인 완료’ 버튼 하나로 일괄 승격하지 않는다. 사용자 명시 승인과 해당 조합 버전을 기존 담당 QA에 기록하고 정량검사·자체검수와 별도 표시한다.
‘좋다’가 특정 장면/소리에 대한 평가면 그 범위를 기록하며 전체요원/모든분기 승인으로 확대하지 않는다. 원승인 보존, 이후 수정본은 변경 범위와 필요한 재검수를 기존 AV교체 규칙대로 표시한다. 페이지 열람/끝까지재생/다운로드 자체는 승인 근거가 아니다.

### 구현 경계·검수
Cutscene가 기존 시사회 페이지/영상시각을 소유하고 Audio는 정확 cue/파일조건을 공급, 상대 원본을 중복 생성/편집하지 않는다. Unity는 최종 검수된 조합의 실제Player 경로를 별도 검증한다. 이 제안 승인 전 역할 작업큐에 추가하지 않는다.

### 설정과 적용 범위
기존 연출 설정에 ‘컷신 연출 강도: 기본 / 줄이기’ 한 항목을 제안한다. 섬광/카메라 각각 여러 슬라이더를 두는 방식보다 조작이 간단하며, DAILY/ALWAYS/OFF로 요약만 강제하는 방식과 달리 표준 컷신을 감상할 수 있다. 기존 동등 설정이 있으면 재사용하고 중복 메뉴를 만들지 않는다. 첫값은 기본, 사용자가 선택한 값은 기존 로컬 설정 owner의 수명으로 보존한다. 새 서버 조회/계정 전체 설정 API를 만들지 않는다.
DAILY/ALWAYS/OFF는 표시 빈도/표준요약, 연출 강도는 장식 표현의 차이다. 강도를 줄여도 일일 시청기록·스킵·표준/요약 선택·스킬능력·길이/hold 계약은 바뀌지 않는다. 음량은 기존 BGM/SFX 설정을 따르며 이 옵션이 소리를 임의로 끄지 않는다.
범위는 궁극기 컷신과 부분 요약의 장식 카메라/광/입자다. 실제 전장 카메라·탄 경로·사거리·판정·필수 위험예고는 바꾸지 않는다. 이번안으로 일반전투 새 화면흔들림/히트스톱을 만들지 않는다.

줄이기 자산이 미준비면 검증된 낮은강도 요약, 없으면 최소전장효과로 대체한다. 선택값을 몰래 기본으로 되돌리거나 과거 영상을 재생하지 않는다. 컷신 종료/스킵과 동일 멱등종료·자기hold 해제·원효과한번 계약을 사용한다. 전체화면 시작 후 안전종료의 시청기록은 기존04 규칙을 따르며 새 초기화를 만들지 않는다.

### 검수·승인 경계

## 궁극기 전용 음악·전투 BGM 연결 상세 — 2026-10-20 / 신규 제안

### 전용 음악을 어디서 쓰는가
표준전체화면에서는 검수된 요원 전용 짧은 테마를 사용하고, 부분 요약에서는 전투 BGM을 유지하는 안을 추천한다. 매요약마다 테마를 겹치면 음악이 자주 끊기며, 컷신에서도 전투곡만 쓰면 전용테마 제작의 활용이 줄어든다. 표준/요약 음악 후보는 시사회에서 모두 비교하되 요약음악 파일이 존재한다고 운영적용을 자동 확정하지 않는다.
전용테마는 인물 정체성 표현이다. 이브 기체없는 분기에도 지휘 테마는 가능하지만 엔진/생성성공 효과는 실제 분기만 사용한다. 닉스 테마는 공간/경계의 인상을 주며 실제 tick/적 처치 신호를 대신하지 않는다. 새 대사/음성 녹음은 요구하지 않는다.

### 음악 설정과 소유
전용테마는 기존 BGM 설정, 장갑/경계/구동 등의 효과는 기존 SFX 설정을 따른다. 별도 전용테마 슬라이더를 만들지 않는다. BGM0/SFX유지일 때 음악 없이 효과음만, SFX0/BGM유지일 때 테마만, 전체무음에서는 같은 영상/전투규칙으로 재생한다. 비교용 합성 mix WAV는 청취용이며 게임에서 BGM/SFX 개별설정을 무시하는 단일소스로 넣지 않는다. 독립 stem을 기존 오디오 소유자가 조합한다.
사용자 음량 변경은 즉시 기존 설정 owner에 반영하고 컷신 종료가 시작 당시 절대값으로 되돌리지 않는다. 연출강도 줄이기는 시각 설정이므로 음량을 자동 변경하지 않는다. 기존 메뉴/앱 중단에 따른 오디오 제어를 컷신이 일괄 해제하지 않는다.

### 진입·연속·복귀
표준 시작 시 준비된 전용테마가 있을 때만 전투 BGM을 낮추고 테마를 시작한다. 음악 미준비로 무음 대기를 만들지 않는다. 테마 없는 검증조합은 전투 BGM을 유지한 채 컷신 효과만 사용한다. 이미 재생 중 뒤늦게 준비된 테마를 중간 삽입하지 않는다.
전투 BGM 재생위치는 원음악 owner가 유지하며 화면전환마다 처음부터 시작하지 않는다. 기존앱 중단정책을 제외하고 음악 전용시계는 전투tick 정지와 구분한다. 컷신테마는 presentation clock과 같은시각으로 시작/중단/복구하고 전투배속에 따라 피치를 바꾸지 않는다.
연속 표준 A→B에서는 A테마의 소유재생을 종료하고 B테마를 시작한다. 전투곡 음량이 사이에 크게 복원됐다 다시 내려가지 않게 연속구간을 처리하되 두 요원 멜로디를 의도 없이 길게 겹치지 않는다. 팝방지 감쇠는 실제음원으로 검수하며 임의공통ms를 확정하지 않는다. 음악 끝까지 기다리려고 영상/hold를 연장하지 않는다.
최종복귀/스킵/오류 때 해당테마/예약cue만 종료하고 최신전투음악 상태로 돌아온다. 컷신중 원음악 상태가 보스/결과 등으로 변경됐다면 과거곡 snapshot을 복원하지 않고 기존 owner의 현재곡을 따른다. 닉스→이브→결과, 컷신중메뉴/노드종료 등에서도 동일하다. 음악을 위해 원전투상태를 되감거나 새사건을 만들지 않는다.

### 제작 인수·검수
기존 AV조합에 음악 stem의 버전/실길이·무음변형 가능·시작/종료·잔향 포함 여부와 BGM/SFX 구분을 기록한다. 원본/비교mix/게임용독립stem 역할을 구분하고 검사된 파일 해시를 재사용한다. 수치상 클리핑0은 좋은음색/동기화/최종음량 검수완료가 아니다. 정점음과 장갑/촉매 cue가 서로 가리는지 실제청취한다.
시사회는 SFX-only/테마추가 비교를 제공하고 게임 적용 추천안과 후보를 구분한다. 실제Player는 BGM/SFX 네조합, 표준/요약·연속두편/스킵/오류·테마누락·중간음량변경·메뉴/백그라운드·결과곡전환을 검수한다. 음악중복/잔류0, 사용자설정불변, 전투결과동일, 실제소리끊김/갑작스러운음량변화 여부를 확인한다.

### 화면 밖·가림·거리

객차/인물에시각적으로가려졌다고 소리를자동제거/필터링하지않는다. 시각가림과물리탄차폐,음향가림은별개다. 현재검증된음향가림자료가없으면 객차관통저역필터/벽두께시뮬레이션을추정하지않는다.
일반전투/환경소리는승인된실거리좌표·범위가있는경우에만거리감을준다. 화면픽셀거리나스프라이트크기를미터로환산하지않는다. 새사거리/적활성범위를소리감쇠로만들지않는다. 중요한예고는단순거리감쇠때문에없어지지않게우선순위와별도식별성을검수한다. 거리원천미확인은기존비공간표현으로남기고실측후설정한다.

## 배속·일시정지·앱 복귀 음향 상세 — 2026-10-21 / 신규 제안

### 배속에서 무엇을 바꾸는가
- 실제 발사·명중·회복 사건은 전투 시계를 따른다. 배속 변경 직후에도 실제 사건이 발생한 때만 음향 소비하며 별도 음향 타이머로 공격을 예측하지 않는다.
- BGM·궁극기 영상/테마·일반 단발 효과음은 원래 음높이와 길이를 유지한다. 전투 배속을 모든 AudioSource pitch에 곱하지 않는다. 따라서 높은 배속에서 소리가 더 겹칠 수 있으며 기존 중요도/동시 사건 묶음 규칙으로 처리한다.
- 소리 표현을 묶거나 생략해도 실제 피해·회복 사건은 모두 처리한다. 밀린 단발을 대기열에 쌓아 나중에 재생하지 않는다. 중요 위험/상태 신호를 일반 총성에 묻히지 않게 한다.
- 이동·충전·영역 등 지속음은 실제 소유 상태의 시작/종료에 맞춘다. 소유 상태가 배속으로 빨리 끝나면 소리도 종료하되, 음높이 변화나 새 변형음은 해당 자산별 승인 없이는 추가하지 않는다.

## 전투 음원 준비·공유·노드 전환 해제 상세 — 2026-10-21 / 신규 제안
04#combat-resource-lifecycle-proposal-20261019의 기존 자산 범위/소유·해제 계약을 음향에 구체화한다. 목표는 첫 타격 재생 지연과 전투 왕복 후 잔류 재생/메모리 누적 방지. Plan은 본 절과 인계를 소유하며 Unity는 기존 로더/카탈로그/재생 소유자, Audio는 승인 원음/루프 경계·정확 파일 공급을 맡는다. 신규 로딩 프레임워크·일괄 압축/streaming 전환·메모리 상한을 확정하지 않는다. 이미 승인한 C 실제 연결을 이 제안 승인 대기로 막지 않는다.

### 준비·공유 범위
| 범위 | 제안 |
|---|---|
| 공통 UI | 실제 여러 화면에서 사용하는 승인 UI음만 기존 공용 수명으로 재사용 |
| 현재 전투 | 확정 편성/적/지원 사건에 필요한 승인 짧은 음원을 진입 준비에서 확보. 첫 명중마다 파일 로드하지 않음 |
| 현 노드 환경·음악 | 실제 선택 노드의 곡/환경음만 준비, 미선택 경로 전체 선로드 없음 |

동일 자산 ID/버전은 로더의 기존 공유 참조로 재사용한다. 재생 인스턴스가 여러 개인 것과 음원 데이터가 복제된 것을 구분한다. 새 화면별 캐시나 같은 WAV의 이름만 다른 복사본을 만들지 않는다. C는 승인 단독 원음만 매핑하며 C+BGM 비교합본/ABC는 review-only다. 원본 파일과 역사 후보는 보존하되 실행 카탈로그에 불필요한 직접 참조를 남기지 않는다.

### 준비 지연·실패
실제 기본 사건의 승인 음원은 사전 준비를 시도한다. 사전 검사 누락과 실행 중 로드 실패를 구분하고 기존 누락 정책을 적용한다. 오디오만 실패했을 때 이미 확정된 공격·회복을 멈추거나 다시 실행하지 않는다. 늦게 로드된 명중음은 지난 명중을 보충 재생하지 않고 다음 실제 사건부터 사용한다. 음원 재시도 때문에 게임 API/START/보상 명령을 재호출하지 않는다. 중요한 경고의 기존 시각 신호는 유지한다.

### 전환과 반환
1. 기존 노드 종료 경계에서 새 재생 요청을 차단하고 구독/예약/구세대 콜백을 정리한다.
2. 실제 종료된 전투 루프와 노드 전용 소스를 정지·반환한다. 기존 승인 결과 전환에 필요한 소리만 해당 수명까지 유지한다.
3. 다음 장면의 준비된 자산으로 전환한다. 음악 전환 중 사용 중인 이전/다음 곡은 각 사용이 끝날 때까지 참조를 유지한다.
4. 이전 장면의 소유 참조만 반환한다. 공유 C/UI음이나 아직 재생 중인 다른 소유자의 곡을 함께 해제하지 않는다.
5. 취소 뒤 완료된 로드는 현재 장면에 붙이지 않고 자기 참조를 반환한다. 풀 반환 소스는 clip/루프/공간 설정/콜백 등 다음 사용자에게 새는 상태를 초기화한다.

앱 백그라운드는 장면 종료가 아니므로 전체 음원을 무조건 해제하지 않는다. 기존 앱 정책 아래 미사용 준비 자산만 반환할 수 있다. 메모리 압박 시에도 재생 중 자산/필수 원상태를 임의 파괴하지 않는다. 강제 GC/전체 unload를 매 타격·창 닫기·노드마다 실행하지 않는다.

### 짧은 효과음과 긴 음악의 설정 검토
짧은 반복 효과음은 첫 재생 지연/동시 재생 CPU를, 긴 BGM은 디코드 메모리·버퍼·끊김을 측정해 기존 import/load 설정의 유지 또는 변경을 선택한다. 원본 MP3/WAV 확장자만으로 런타임 메모리나 최적 방식을 판단하지 않는다. 모든 음원을 무조건 streaming 또는 무압축 상주로 통일하지 않는다. 승인 원음은 보존하고 플랫폼용 변환본은 원본·설정·버전을 추적한다.
