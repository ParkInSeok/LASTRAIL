## 2. 40종 정책과 실제 풀 연결

참조 기준은 `AUGMENT-UNIFIED-POOL-POLICY-20260915.md`와 **`AUGMENT-POOL-40-POLICY-20260915.md`**다. “32/40 기획 카드를 구현된 것으로 seed하지 않는다”는 문구는 미구현 카드를 완료로 가장하지 말라는 제한이며, 32종으로 축소 확정했다는 근거가 아니다.

**[U1 확정] 이미 기획한 풀을 새 선택·리롤에 연결한다.** 풀의 최종 총량을 다시 임의 선택하지 않는다. 첨부물에는 전체 카드 목록·효과 코드·테스트가 없으므로 40종 전부 구현 완료를 선언하지 않는다. 연결 시 실제 효과·보유 중첩·역할 적격성·카탈로그 버전 갱신 규칙까지 확인한다. 조건에 따라 유효 후보가 없을 수 있다는 정상 경계는 남는다. [R31](00_INDEX.md#r31) [U1](00_INDEX.md#u1)

## 3. 선택·리롤 도메인

| 항목 | 규칙 |
|---|---|
| 예산 | **J07 최신 정정 승인(2026-09-21): 카드(슬롯)마다 무료3회 + 추가1회.** FREE 소진 뒤 적격 EXTRA를 사용한다. 광고/영구권으로 추가 슬롯을 각각 만드는 것이 아니다. |
| 교체 | 현재 표시된 3장을 제외한 적격 후보에서 균등 index 추첨 |
| 과거 후보 | 이전 등장 후보의 재등장 가능 |
| 교체 후보 없음 | 잔량 미소모 |
| 추가 승인 | 승인 target 결속을 확인하고 비동기 승인 뒤 revision/state를 다시 검증 |
| 상태 소유 | 후보·잔량·revision·최종 선택·원요청 결과를 하나의 aggregate가 관리 |
| 경쟁·복구 | 동일 key single-flight, 다른 본문/key 탈취·SELECT/REROLL 경쟁 방지, 원결과 복구 |

2026-09-21 사용자 “기획에도 카드마다 1회 인거로 맞춰서 수정”에 따라 무료와 추가 잔량 모두 카드(slot)별로 관리한다. 슬롯별 무료3회를 선택화면 전체의 총3회나9회 일괄버튼으로 임의 변경하지 않는다. 실제 교체 입력·slotId·DTO는 기존 구현과 대조한다. 새로운 증강 grant에서만 각 슬롯의 무료3회와 EXTRA 1회 예산이 초기화되고, 화면 재열기·웨이브 전환·재로그인으로 초기화하지 않는다.

| 광고 스위치 | 유효 광고 스킵 구매권 | 해당 카드 무료분 소진 뒤 카드별 추가1회 |
|---|---|---|
| OFF | 없음 | 제공하지 않음. 무료분과 선택/확정은 정상 |
| ON | 없음 | 유효 광고 완료·서버 검증 뒤1회 |
| OFF 또는 ON | ACTIVE | 광고 없이 상품 사용승인 뒤1회 |
| 어떤 값이든 | UNKNOWN | 상품권을 임의 가정하지 않음. 권한 재조회·원결과 복구, 기본/무료기능 보존 |

광고와 상품은 **각 카드의 동일한 추가1회 예산을 사용하는 대체 승인 경로**다. 한 카드에서 광고와 상품을 각각 사용해 추가2회를 얻지 못한다. 세 후보 카드는 각각 독립 예산을 가지므로 한 카드의 사용이 다른 카드의 잔량을 줄이지 않는다. OFF라고 남은 EXTRA 예산을 강제 소비/삭제하지 않으며, 같은 grant의 해당 slot에서 교체가 실제 확정될 때 한 번만 소비한다. 리롤로 카드 내용이 바뀌어도 해당 slot의 잔량은 이어진다. 기능이 미구현/점검/종료 상태이면 구매권도 이를 우회하지 않는다. 교체 후보가 없으면 무료·추가 잔량을 소비하지 않고, 광고 시작 전에 대상과 교체 가능성을 확인한다. 광고 완료 후의 유효권리 복구는 원승인에 결속해 보존한다.

Unity는 엄격한 snapshot 검증, 계정/수명 fencing, SELECT/REROLL 원요청 직렬화와 독립 journal CAS를 사용한다. 과거 receipt snapshot으로 현재 revision을 낮추지 않는다. 테스트용 내부 checkpoint를 untrusted client 복원 입력으로 받지 않는다. [R31](00_INDEX.md#r31) [R32](00_INDEX.md#r32)

## 4. 증강 선택 중 전투 정지

**[U1 확정] 증강 선택 중 전투와 열차 주행을 완전히 정지하고, 선택 결과와 실제 효과 적용 확인 뒤 재개한다.** 공격·이동·투사체·지속 피해·회복·게임플레이 쿨타임이 진행하지 않으며 UI는 별도 시간으로 표시할 수 있다. 분기 선택 시간 규칙과 혼용하지 않는다.

`CONFIRMED`는 선택 결정이지 효과 적용 완료가 아니다. 후보/잔량/revision/receipt 저장과 실제 효과 적용 영수증을 원자적으로 연결할 경계가 필요하다. 선택 응답만 받은 상태에서 먼저 전투를 재개하지 않는다. 정지 정책은 이번 결정이고 실제 hold/resume 연결 완료 보고는 아직 없다. [U1](00_INDEX.md#u1) [R31](00_INDEX.md#r31) [R32](00_INDEX.md#r32)

## 5. 구현 연결 범위

서버의 `solo-augment-selection-v1`은 메모리 도메인·내부 checkpoint이며 issue/read/reroll/select/checkpoint/restore와 ExtraApprovalPort를 제공한다. Unity는 독립 Controller/View/Presenter와 테스트용 3카드 화면까지다. 공개 HTTP 응답이나 실제 전투 완료로 취급하지 않는다.

남은 연결은 실제 map issuer, 검증된 카탈로그/효과, D1 transaction·실제 디스크/Keystore journal, 공개 DTO/API·인증, hold/resume, 실제 SSV/영구권 승인 adapter, 최종 독립 원화/등급 자산이다. OFFLINE/COMBAT/REROLL의 provider 거래 유일성·계정/환경/기한·회수 순서도 실제 adapter/DB로 검증해야 한다. 연결 전 **`REROLL UNSUPPORTED`**를 유지하며 정책 승인만으로 AVAILABLE로 바꾸지 않는다. [R31](00_INDEX.md#r31) [R32](00_INDEX.md#r32)

## 6. 협동과 회수된 원문

`COOP-UNIFIED-AUGMENT-CHOICE-20260916.md`의 교대 담당·직렬화는 기획 후보다. 예산 공유는 같은 지급의 **각 카드 슬롯별 무료3+추가1을 두 사용자가 공유**한다는 뜻이며, 모든 슬롯을 합쳐3+1이라는 뜻이 아니다. 솔로 규칙으로 확정하거나 45초/A를 운영 상수로 추가하지 않는다. 협동 권한·공유 잔량·기한·보상 소유권은 별도 후속이다.

전달 당시 첨부 목록에는 참조 이름만 있었으나 현재 로컬에는 `RUN-MAP-AUGMENT-EVENTS-20260916.md`, 통합/40종 정책, 협동 선택 전문이 존재한다. 구형 보장 횟수·선로 선택 결합과 최신 정책의 대체 관계를 대조한다. 원문 확보와 실제 효과·맵·협동 구현 검증은 별개다. [R31](00_INDEX.md#r31) [R32](00_INDEX.md#r32)

## 7. 버전 및 지휘관 영향

카탈로그 배포·클라이언트 버전 호환·채널 분리는 [08](08_BALANCE_RELEASE.md)를 따른다. 지휘관 스킬을 직접 바꾸는 증강은 [09 §8](09_COMMANDER_PROGRESSION.md)의 명시된 효과 종류와 결합한다. 포탑 궁극기 효과를 새로 요구하거나 삭제한 증강 보장을 재도입하지 않는다. 참조된 실제40종 카드의 개별 수정 여부는 원문·코드를 대조해야 한다.

[U5] 상위 특성은 출격 전의 기본 전투 규칙, 증강은 작전 중의 확장 선택이다. [09 §7](09_COMMANDER_PROGRESSION.md#capstone-rules)의 승인된6종과 실제40종 효과 간 호환/중복을 대조한다. 특정 증강이 없으면 상위 특성이 동작하지 않는 구조나 삭제한 증강 횟수 보장을 만들지 않는다.

## 8. 광고 OFF와 공식 위키·확률 공시 — U7

광고 허용과 무료/추가 리롤 예산은 다른 정책이다. **J07/J08 승인:** [10 §2](10_LIVEOPS_NOTICES.md#off-benefits)의 BASIC_ONLY는 비보유자에게 적용한다. ACTIVE 구매권은 광고 ON/OFF와 무관하게 원상품 사용승인으로 각 카드의 동일한 추가1회 리롤을 제공한다. 무제한 무료 지급이나 광고1+상품1 중복 예산은 없다. 승인된 정책을 실제 provider/DB 연결 완료로 취급하지 않는다.

공식 위키·확률 공시는 [11](11_WEBSITE_COMMUNITY.md#odds)의 공개 snapshot을 사용한다. 실제 적격 풀·중복 제외·리롤 조건·고정된 버전별 정책을 표시하고, 기획된40종을 모두 구현됐다고 노출하지 않는다. 확률의 후보 개수/조건을 생략하거나 광고 OFF를 증강 보장 재도입으로 연결하지 않는다.


## 9. U9 점검 중 선택·리롤

점검으로 선택 화면을 벗어나도 서버가 이미 발급한 후보·잔량·선택 결과를 다시 추첨하지 않는다. [12](12_SERVICE_MAINTENANCE.md#recovery)의 점검 gate가 별도로 유지되는 동안 증강 선택 종료만으로 전투를 재개하지 않는다. 원 SELECT/REROLL의 확정 여부는 원키·계정·grant로 확인하며, 일반 점검을 구형 작전 폐기 예외로 취급하지 않는다.


## 10. 장비·인챈트·맵과의 경계

[13](13_EQUIPMENT_ENCHANTMENTS.md)의 장비/인챈트는 개별 장착자 성장, 증강은 작전의 큰 규칙 변경을 담당한다. 고유효과16종·독립 인챈트16종을 증강40종 카탈로그의 일부로 잘못 합치지 않는다. 같은 trigger를 쓰더라도 effect source/대상/중첩·재귀 규칙을 분리한다.

실제 랜덤 이벤트 배치와 증강 이벤트 상대 가중치는 [14](14_MAP_EVENTS_DROPS.md)에서 연결한다. 증강 보장 삭제는 원래 보장에 사용하던 stage 카운터를 eventInstanceId 단위 중복 방지로 바꾸는 정책이지, 서버 발급 검증 제거가 아니다. 무료/추가 리롤은 J07/J08과 §3을 따른다. 실제 slot별 wire 확인은 구현 작업이며 이미 승인된 광고/구매권 정책을 다시 미정으로 되돌리지 않는다.

### 1. 사용자 흐름과 완료 경계

### 2. 데이터 원천과 확정 응답
- 후보/리롤 잔여/보유 효과는 기존 응답과 소유 Model에서 즉시 표시한다. 카드 상세 열기·닫기·결과 재열기 자체로 조회하지 않는다. 기존 per-card free3+extra1 계약 및 균등 후보/추천 없음 유지.
- 확정 명령은 서버가 실제 run/선택 기회·현재 후보·권한·비용/횟수·중복을 검증한다. 클라이언트 캐시가 서버 검증을 대신하지 않는다.
- 응답은 기존 계약으로 원선택 식별·확정 효과 및 정의 버전·변경된 보유 상태/관련 버전·처리 결과를 전달한다. 기존 필드에 매핑하고 누락 의미/삭제/미공급을 구분한다. 전체 계정 덤프를 요구하지 않는다.
- 충분한 성공 응답 후 결과 확인 GET·재개 전용 호출은 추가하지 않는다. 실제 응답 유실/버전 불일치/재접속은 기존 원키 복구 경로를 사용하며 정상 조회 절감과 분리 집계한다.
- 화면은 Controller에 선택 의도를 전달하고 Model 상태 통지로 갱신한다. 화면별 직접 효과 실행·HP 계산·보유 목록 임의 가산 금지. 화면 세대 변경 뒤 늦은 응답은 현재 View를 직접 변경하지 않되 유효 거래 결과는 소유자가 처리한다.

### 3. 새 효과의 전투 적용
흡혈 획득 뒤 새 독립 공격은 기존 승인 비율/무상한 기준을 사용한다. 획득 전 시작한 공격/탄의 고정 정의는 유지한다. 생명 역류의 아군 치료는 즉시 적용하고 초과 치료에 의한 적 공격만 생명탄을 사용한다. 치료가 명중을 기다리도록 바꾸지 않는다.
같은 지속 시전의 남은 tick은 원부모 정의와 잔여 예산을 유지한다. 새 독립 시전부터 최신 병용 정의를 적용한다. 기존 보호막의 잔량/만료·이미 소모된 예산을 새 획득으로 복원하지 않는다. 동적 수혜 조건과 명중 시 방어는 기존 판정 시점 규칙을 유지한다.
다중 발사 EN17·관통은 인챈트이며 증강 후보로 재분류하지 않는다. 실제 장착된 인챈트가 있는 시험에서 증강과의 조합을 검증한다. 보조탄/관통 적중의 원피해 귀속과 실제 흡혈은 기존 정식 원천을 사용하며 추가 발사 수로 예상 회복을 역산하지 않는다.

일시정지·점검·앱 복구 hold는 각각 소유자가 해제한다. 선택 완료로 다른 정지를 해제하지 않는다. 재접속은 서버/로컬 권위 계약과 검증 checkpoint에 따라 선택·적용 복구·전투·결과 중 실제 단계로 돌아가며 최신 화면처럼 보이게 임의 이동하지 않는다.

### 5. 결과 기여와 노드 전환
흡혈은 실제 회복 HP, 생명 역류는 실제 적 HP 피해와 별도 보호막 피해, 초과 보호막은 실제 흡수량을 기존 단위별로 표시한다. 생성/공격 소비/흡수/만료는 분리한다. 피해·회복·방어를 한 점수로 합산하지 않으며 보상을 추가 지급하는 근거로 사용하지 않는다.
노드 종료 owner의 마지막 확정 사건까지 포함하고 종료로 취소된 탄/예약은 제외한다. 최종 보유 조합으로 획득 전의 기여를 다시 계산하지 않는다. 정상적으로 측정한 0은 ‘이번 전투 발동 결과 없음’, 미측정은 ‘기록 없음’, 부분 복원은 실제 기록 범위를 표시한다.
다음 노드에는 승인된 보유·지속 정책에 맞는 상태만 전달한다. 임시 상태를 전부 유지/삭제하는 새 규칙을 만들지 않는다. 이전 노드 결과 상세 수명과 구독을 끝내되 기존 복구에 필요한 영수증/checkpoint는 보존한다. 원시 사건 로그를 화면마다 누적 복제하지 않는다.

## 리롤 전후 카드 입력·상세 내용 일치 상세 — 2026-10-21 / 신규 보완 제안
기존 리롤·SELECT revision 검증/한 grant 변경명령1개 규칙을 유지한다. 새 리롤 횟수/후보가중치/확인팝업/서버API를 추가하지 않는다. 목적은 리롤 직후 같은 자리에 나타난 다른 카드를 사용자가 의도치 않게 선택하거나, 옛 설명을 읽고 새 카드를 확정하는 일을 막는 것이다. Plan 본절, Unity 입력/표시, Server 기존 revision권한 경계 소유. 이번은 제안만이며 실행큐 없음; 승인된 통합 구현은 계속한다.

### 입력과 후보 교체
- 카드 누름 시작 시 현재 grant/slot/후보 식별과 표시 revision을 입력 문맥으로 묶는다. 손을 뗄 때 후보가 바뀌었으면 그 입력을 취소하고 새 입력을 기다린다. 원요청에 필요한 기존 필드를 재사용하며 별도 보유 원장을 만들지 않는다.
- 리롤 명령 진행 중에는 같은 grant의 SELECT/다른 슬롯 리롤을 실행하지 않는다. 카드 설명 읽기는 허용하되 현재 확정된 기존 후보를 표시한다. 비용·횟수·새 후보를 낙관적으로 확정 표시하지 않는다.
- 성공 응답이 Model에 반영된 뒤 카드 이름·설명·아이콘 참조·조합 설명·남은 횟수·선택 payload를 같은 상태로 갱신한다. 표시 갱신 중 입력으로 이전 후보를 확정하지 않는다.
- 리롤 버튼 터치 종료가 새 카드 선택으로 이어지지 않도록 기존 입력 소비를 사용한다. 멀티터치/키보드/패드도 같은 Controller 명령 경로를 따른다. 새 애니메이션 제작/완료 신호를 판정 경계로 삼지 않는다.

### 상세창과 포커스
교체된 카드의 상세창이 열려 있다면 새 후보의 상세로 함께 갱신하고 본문 스크롤을 처음으로 돌린다. ‘후보가 변경되었습니다.’를 해당 상세 안에 짧게 표시하는 안이며 추가 확인 모달은 만들지 않는다. 다른 슬롯 상세는 내용과 스크롤을 유지한다. 새 효과명이 갱신되기 전에 확정 입력을 허용하지 않는다. 포커스 위치는 유지할 수 있지만 누른 채 유지된 키/터치로 새 후보가 선택되지는 않는다.
후보 동일성이 유지된 순수 횟수/명령 상태 갱신은 불필요한 스크롤 초기화·내용 깜빡임을 만들지 않는다. 장면 재진입은 기존 소유 Model의 현재 후보를 표시하며 후보 생성/리롤 소비를 다시 하지 않는다.

### 오래된 응답·복구
서버의 원후보/revision 검증은 클라이언트 입력 취소와 별개로 유지한다. 이미 바뀐 후보를 요청하면 다른 후보를 대신 확정하지 않는다. 충돌 응답에 검증 가능한 현재 상태가 충분하면 재사용하고, 부족하거나 결과 불명확하면 기존 복구 경로만 사용한다. 현재 UI를 과거 리롤 응답으로 되돌리지 않는다. 원키 재시도는 새 리롤이 아니며 같은 결과/소비를 복원한다.
광고/추가권 처리 중에도 기존 원target/revision·권리 복구 정책을 적용한다. 본 제안으로 유효한 추가권을 버리거나 재시청을 강제하지 않는다. 슬롯별 무료3+추가1 유지, 후보 없음은 기존 미소모 정책 유지.

## 증강 카드의 적용 대상·발동 조건 표시 상세 — 2026-10-21 / 신규 제안
목표: 선택 전 현재 편성의 누구에게 어떤 행동에서 효과가 적용되는지 이해할 수 있게 한다. 후보 적격/균등가중치·치료요원 조건·실효과 규칙은 바꾸지 않는다. Plan 본 절, Unity 기존 카드/상세 표시, Server 기존 권위 후보·정의 계약을 소유한다. 이번은 상세 제안이며 실행큐 없음. 기존 증강 통합 구현의 추가 선행조건으로 삼지 않는다.

### 카드와 상세 구성
카드 앞면은 기존 효과 요약을 유지하고 적용 범위를 ‘요원’, ‘열차’ 등 원정의가 실제 지원하는 분류로 짧게 표시한다. 명칭만으로 모든 공격/요원에 적용된다고 확장하지 않는다. 상세는 효과 설명→적용 대상→발동 조건→현재 보유 조합/제약 순서로 배치한다. 새 평가점수·추천·자동정렬을 추가하지 않는다.
적용 대상은 현재 작전 편성 중 원정의에 맞는 요원 이름과 기존 초상으로 표시한다. 초상 부족 시 이름을 표시하고 새 원화 제작을 요구하지 않는다. 열차 전체 효과를 요원 전체 적용으로 표시하지 않는다. 특정 요원 대상 선택이 없는 카드에서 초상을 누른다고 적용 대상을 바꾸지 않는다. 대상 목록은 읽기전용이며 효과 범위와 실제 수혜 대상이 다를 경우 문구에서 구분한다.

### 설명 예시와 구분
| 효과 | 설명 원칙 |
|---|---|
| 흡혈 | 원정의상 적격한 피해가 확정되면 피해 소유 요원이 회복함을 설명. 모든 간접피해가 적격이라고 추정하지 않음 |
| 생명 역류 | 치료 요원의 초과 치료로 적 공격이 발생함을 설명. 아군 치료는 즉시 적용. 획득 조건에 치료요원 기본공격 총구/공격형태를 추가하지 않음 |

‘적용 대상’은 현재 체력/적 존재로 매프레임 바뀌는 발동 가능 목록이 아니다. 일시 다운·만피·쿨다운은 후보/대상에서 제거하지 않는다. 필요한 경우 ‘초과 치료가 발생할 때’처럼 안정적인 조건을 설명하며 현재 발동하지 않는 원인을 확인 없이 단정하지 않는다. 발동 횟수/예상 DPS/예상 회복량은 실제 계산 계약이 없으면 표시하지 않는다.

기존 실기여0/미측정/부분기록 구분을 유지하고, 현재 조건과 과거 전투 결과를 서로 다른 정보로 명확히 읽도록 한다. 새 실시간 진단화면·원시로그열람·효과판정 시스템은 신설하지 않는다. Plan 본절, Unity 기존 기여상세/표시, 해당 모드 전투권위 owner는 원결과를 소유한다. Server는 이미 소유한 저장/복구 경계만 보완하며 모든 타격을 서버로 새 전송하지 않는다. 기존 E2E 구현은 이 제안 대기로 막지 않는다.

### 표시 구조
기존 증강 상세의 ‘이번 전투 효과’에는 실제 확인된 기여를 먼저 표시한다. 일반 조건 설명과 결과기록을 나누어, 현재 만피/장비변경 사실을 과거 전체전투의 0 원인처럼 붙이지 않는다. 상시 배지/팝업/강제 확인을 만들지 않는다.
| 확인된 원정보 | 표시 예시/원칙 |
|---|---|
| 실제 기여가 있음 | ‘회복한 체력 7’처럼 효과별 기존 단위 유지 |
| 전체집계 정상·기여0 | 0과 ‘이번 전투에서 회복한 체력이 없습니다.’처럼 효과 결과를 설명. 발동시도 자체가 없었다고 단정하지 않음 |
| 실제원사건에서 만피로 회복0 확정 | 해당 기록 범위에 한해 ‘체력이 가득 차 실제 회복량이 없었습니다.’ |
| 생명탄은 생성됐지만 실HP피해0 | 생성/명중/HP피해를 구분. 불발·면역·차폐는 원이유가 있을 때만 안내 |
| 일부만 기록됨 | ‘재접속 이후 기록’ 등 실제 범위와 그 범위의 수치 |
| 집계/이유 미공급 | 기존 ‘기록 없음’ 또는 기여 수치만 표시. 원인을 만들지 않음 |

표의 숫자7은 문구 예시이며 밸런스 변경이 아니다. 기존 ‘이번전투 발동결과 없음’ 문구가 실제 발동시도0으로 오해될 때 위 결과단위 문구로 구체화하는 제안이다. 여러 이유가 있었으면 임의의 한 이유를 대표 원인으로 단정하지 않는다. 확인된 이유별 집계가 기존 원천에 있으면 접힌 세부에서만 제공하고, 없는 횟수를 HP차/현재 상태로 역산하지 않는다.

### 현재 조건 안내
‘체력이 부족할 때 회복’, ‘초과 치료가 발생할 때 적 공격’ 등 안정적인 원정의 조건은 항상 기존 효과설명에서 확인한다. 실시간 조건 표시가 필요한 경우 이미 원소유자가 제공하는 상태만 사용하고 UI 타이머/매프레임 판정복제를 추가하지 않는다. 일시 다운/만피로 증강을 미보유 처리하지 않는다. 수혜/발동원천 부재 확정과 데이터미공급을 구분한다.
효과가 적용 저장되지 않은 상태는 정상0 통계로 숨기지 않고 기존 선택복구 상태에서 처리한다. 반대로 통계 표시만 누락됐다고 원효과를 재설치하거나 보상/전투를 재실행하지 않는다.

### 데이터·수명
효과기여 Model의 현재노드/정의·소유자·확정사건 범위를 재사용한다. 원기록에 없는 이유 필드가 필요하면 담당자가 실제 producer 지원부터 확인한 뒤 필요한 집계만 기존 결과에 보완한다. 새 상세GET·매타격 업로드·화면별 원시로그 복제는 추가하지 않는다. 전투 종료 후 결과 snapshot은 고정하며 이후 현재HP/장비 변경으로 과거 설명을 다시 계산하지 않는다.
재접속 후 전체기여가 복원돼도 이유만 부분기록이면 전체기여 수치와 이유의 부분범위를 따로 표시한다. 다음노드에 이전이유를 남기지 않는다. 계정/run세대 변경·모달해제 후 콜백/구독은 기존 소유수명으로 정리한다.
