## 1. 핵심 이미지와 기존 역할

> **장치의 상태를 살피고, 필요한 곳에 손을 뻗어 전열을 준비하는 현장 엔지니어.**

기존 역할은 **Engineer / Facility Defense / Sentry**, 힘의 체계는 **Science**다. 기본 5인 중 한 명이라는 기존 정체성을 유지한다. 역할의 근거는 [17 §2](17_OPERATOR_COMMON_STYLE.md#roster)이며 실제 최신 코드의 개별 스킬을 모두 검증했다는 뜻은 아니다.

매력의 중심은 장비 수보다 무엇을 만져야 하는지 알고 있는 손과 시선이다. 평소에는 차분하고 실용적인 인상, 작업 중에는 눈이 문제 지점을 찾고 손이 따라가는 모습을 사용한다. 준비가 끝나면 작은 표정 변화로 자신감을 보여준다. 출신 기업·직급·과거 사건을 새로 정하는 개인 서사가 아니다.

기준 조합은 **스모키 브라운 단발 + 머리 위의 낮은 보호 고글 + 짧은 청회색 정비 재킷 + 밝은 이너 + 허리 장치 케이스 + 짧고 두꺼운 정비 공구**다. 긴 연구 코트보다 손과 허리를 드러내고, 대형 기계팔·거대한 백팩보다 얼굴을 살리는 방향이다.

### 1.1 Eve와 Cipher의 차이

| 비교 축 | Eve | Cipher와 구분할 기준 |
|---|---|---|
| 다루는 대상 | 손에 잡히는 장치·결합부·시설용 부품 | 정보 관측·해킹 중심과 구분 |
| 실루엣 | 허리·등 아래의 단단한 장비 덩어리 | 얇은 센서·단말과 구분 |
| 대표 행동 | 잡기·고정하기·조정하기·장치 준비 | 표적을 읽고 정보를 전달하는 행동과 구분 |
| 먼저 보일 정보 | 얼굴·공구를 쥔 손·장치의 물리적 형태 | 공중 패널과 데이터 문자가 주인공이 되지 않음 |

진단창이나 전자 장비도 사용할 수 있지만 패널 한 장을 손가락으로 누르는 모습만으로 Eve를 설명하지 않는다. **두 손이 실제 접점을 다루는 관계**가 핵심이다. Cipher의 전문은 [28](28_CIPHER_VISUAL_BIBLE.md)에 둔다.

## 2. 얼굴·표정·체형

### 2.1 얼굴

성인 여성 인상, 볼의 폭을 약간 남긴 부드러운 사각형에 가까운 타원형을 기준으로 삼는다. 턱 끝만 뾰족하게 좁히지 않는다. Reina의 정돈된 조준 인상과 다르게 관찰과 판단의 움직임이 조금 더 드러나게 한다.

| 부위 | 상세 설계 기준 |
|---|---|
| 눈 | 위 눈꺼풀은 비교적 곧고 아래쪽은 완만함. 크기보다 시선 방향이 또렷하게 읽힘 |
| 눈꼬리 | 크게 올리거나 내리지 않는 중립적인 방향 |
| 눈썹 | Reina보다 조금 두껍고 자연스러움. 집중에서 안쪽 변화가 읽힘 |
| 홍채 | 회색이 섞인 옅은 올리브 계열. 상시 발광 없음 |
| 코·입 | 작은 명암과 정리된 선. 입가의 긴장이 풀릴 때 미소가 읽힘 |
| 피부 | 관리된 얼굴을 기본으로 함. 기름 얼룩·반창고·흉터를 필수 표식으로 삼지 않음 |

중립에서는 시선이 분명하고 입에 과한 힘이 없다. 집중에서는 턱을 조금 내리고 작업 지점을 본다. 가벼운 긍정에서는 입가 한쪽이 약하게 올라가고 눈의 긴장이 풀린다. 피로·긴장에서는 눈꺼풀과 입 주변에 피로를 남기되 다른 인물처럼 얼굴을 변형하지 않는다.

**Iris와의 얼굴 비교:** Eve는 볼 쪽의 부드러운 폭과 자연스러운 눈썹, Iris는 하관의 안정된 폭과 수평적인 눈썹이 중심이다. 고글을 가린 얼굴에서도 같은 얼굴에 장비만 바꾼 인물처럼 보이지 않아야 한다. 머리·고글은 얼굴 개성을 대신하는 장식이 아니다.

### 2.2 체형·자세

극단적으로 마르거나 근육을 과장하지 않은 실무형 보통 체형이다. 팔과 어깨는 공구를 지지할 수 있게, 허리와 하체는 장비를 지닌 채 숙이거나 돌릴 수 있게 한다. 원화 **약 6.75~7등신**은 비교 출발값이며 실제 키·나이·스탯이 아니다.

기준 자세는 한쪽 다리에 과하게 기대지 않고 양발로 안정적으로 선다. 오른손 공구는 허리보다 조금 위, 왼손은 장치나 공구의 보조 지점을 받칠 수 있는 위치다. 어깨를 Kyle처럼 넓게 벌리지 않는다. 주 손·파지의 구체 형태는 실제 시안과 스킬에서 검수한다.

## 3. 머리·보호 고글

### 3.1 단발

턱선에서 목덜미 위 사이에 끝나는 스모키 브라운 단발을 사용한다. 앞머리는 인물 자신의 오른쪽으로 흐르는 큰 사선 면이다. 왼쪽 귀 주변은 귀 뒤로 정리하고, 오른쪽 볼 옆에는 조금 더 긴 머리 덩어리를 남긴다. 기본 자세에서 두 눈을 드러낸다.

후면은 둥근 뒤통수 볼륨과 짧은 끝선으로 읽힌다. 끝을 사방으로 뻗치지 않고 머리 본체·옆머리·앞머리를 먼저 잡는다. Reina의 긴 포니테일과 달리 얼굴 가까이에서 끝나는 단단한 외곽이 핵심이다.

### 3.2 고글과 움직임

정수리 앞쪽에 올린 낮은 산업용 보호 고글을 기준 외형으로 삼는다. 둥근 렌즈를 과장한 복고형보다 부드러운 모서리의 낮은 프레임을 사용한다. 렌즈는 투명하거나 약하게 착색된 재질이며 자체 발광하지 않는다. 밴드는 머리 뒤로 실제 연결한다.

기준 초상화와 전투 자세는 눈을 드러낸다. 고글을 내린 모습은 필요한 작업 포즈의 비교 대상이지 자동 전환 장비 기능의 추가가 아니다. 고글과 눈이 작은 화면에서 검은 띠 하나로 붙지 않게 한다.

머리의 흔들림은 짧게 한다. 몸이 멈춘 뒤 끝이 조금 따라오는 정도이며 긴 포니테일 같은 큰 관성은 주지 않는다. 고글을 크게 만들어 머리 전체를 장비 덩어리처럼 보이게 하지 않는다.

## 4. 복식·재질

### 4.1 짧은 정비 재킷

짧은 현장 정비 재킷, 밝은 기능성 이너, 작업 팬츠, 안정적인 부츠를 조합한다.

| 부위 | 설계 |
|---|---|
| 길이 | 허리 아래~엉덩이 윗부분. 허리 장비를 완전히 덮지 않음 |
| 앞판 | 중앙이 열려 밝은 이너가 보임. 스트랩으로 가슴을 복잡하게 가로지르지 않음 |
| 칼라 | 짧고 낮아 단발·턱선과 분리 |
| 어깨 | 작은 보강 패널. 전열용 대형 견갑 없음 |
| 소매 | 팔꿈치의 굽힘을 보여주고 손목에서 정리 |
| 장갑 | 손바닥·손등의 재질 구분과 손가락 파지 유지 |
| 팬츠 | 허벅지에 여유가 있고 발목으로 정리 |
| 무릎 | 작은 보강 면. 양쪽 거대 방호판 없음 |
| 부츠 | 발끝·뒤꿈치·밑창이 읽히는 낮은 작업 부츠 |
| 작업 패널 | 케이스 뒤의 짧은 보호 패널. 코트 자락·치마처럼 퍼지지 않음 |

Reina의 긴 흐름, Kyle의 흉부 방호와 다르게 짧은 상의 아래의 손·허리 장비·작업 자세를 중심에 둔다. 재킷 밑단·왼쪽 케이스·낮은 정비 팩이 같은 높이와 명도로 붙으면 배치를 조정한다. 곧바로 장비를 삭제해서 해결하지 않는다.

### 4.2 재질·마모

재킷은 무광 전술 직물, 밝은 보강 면은 조금 거친 작업용 직물이다. 케이스는 단단한 외장과 고무 모서리, 공구는 금속 헤드와 미끄럼 방지 손잡이로 구분한다.

마모는 장갑 손바닥·공구 결합면·케이스 모서리·무릎에 제한한다. 얼굴과 의상 전체를 같은 기름 얼룩으로 덮지 않는다. 직물 접힘·장갑 파지·금속 두께·몸에 고정되는 구조가 마감의 중심이다.

## 5. 대표 공구·장치

### 5.1 오른손 접촉형 정비 공구

한 손 손잡이 앞에 짧고 두꺼운, 모서리가 둥근 사각 헤드를 둔다. 앞면은 총구가 아니라 결합부에 맞닿는 오목한 작업면으로 구분한다. 엄지 위치에는 작은 조작 레버를 두고 손잡이·헤드가 한 덩어리로 뭉치지 않게 한다.

긴 렌치·거대한 망치보다 짧은 형태로 얼굴·손·장치를 같은 화면에 담는다. 미사용 시 오른쪽 허리 고정부에 손잡이가 드러나는 수납안을 비교한다.

**기본 공격 무기로 확정하지 않는다.** 공구에서 탄환·전격·치유광을 쏘거나 적을 타격하는 행동은 실제 공격 정의가 있을 때만 연결한다. 공구를 쥔 오른손과 장치를 받치는 왼손이 각각 무엇을 만지는지 보여준다.

### 5.2 왼쪽 허리 장치 케이스

얕고 단단한 외장, 손으로 여는 잠금부, 운반 손잡이를 가진다. 몸 바깥으로 크게 튀어나오는 가방보다 허리와 허벅지 바깥쪽에 가까이 붙인다. 부드러운 보급 파우치와 구분한다.

대표 작업 포즈에서 왼손은 케이스 또는 분리된 작업 부위를 받치고 오른손은 공구를 댄다. 손가락·잠금부·외장이 관통하지 않게 확대도를 제공한다. 케이스 수·크기는 센트리 보유량·설치 횟수·아이템 용량이 아니다.

### 5.3 낮은 정비 팩

등 아래~허리 위에 걸치는 낮고 납작한 팩을 기준 조합으로 사용하되, 정확한 부피는 시안 검수 대상이다. 머리 위 안테나나 거대한 원형 장치 대신 옆에서 두께가 읽히는 직사각형 본체와 짧은 고정부를 둔다.

머리 끝·칼라·팩 사이에 간격을 남긴다. 케이블은 몸 가까이 정리하며 무릎 아래나 옆 요원까지 늘이지 않는다. 모든 장비를 발광선으로 연결하지 않는다. 운반·보관의 인상이지 새 에너지 자원·공급 범위를 정하는 장비가 아니다.

### 5.4 센트리·배치 장치와의 연결

실제 장치가 확인되면 개인 장비와 잠금부·외장 재질·정비 흔적을 공유한다. 낮고 넓은 접지부, 분명한 작동 헤드, 점검 패널은 외형 비교 방향이다. 거대 포탑·로봇 펫으로 자동 확대하지 않는다.

설치형/비행형, 공격 헤드, 발사구, 전개 방식, 수, 크기, 유지·회수 상태는 실제 스킬·자산 확인 뒤 결정한다. 펼쳐진 센트리를 기본 필수 동반물로 고정하지 않는다. 시설 방어 역할은 수리·부활 능력을 자동 뜻하지 않는다. Eve의 센트리와 열차 포탑이 동일 생존 규칙을 쓴다고 가정하지 않는다.

색 계열과 면적 배치가 기준안이며 HEX의 실제 출력은 미검수다. 오렌지를 머리나 소매 전체로 넓히지 않는다. Kyle의 올리브·앰버와는 밝은 이너·짧은 재킷·단발·공구로 구분한다. 장치광이 없어도 구조가 읽혀야 하며 홍채·고글·공구·팩을 동시에 밝게 켜지 않는다.

<a id="views"></a>
## 7. 정면·후면·좌·우

좌우는 인물의 해부학적 좌우다.

| 방향 | 확인할 정보 |
|---|---|
| 정면 | 두 눈·왼쪽 귀 뒤 머리·오른쪽 옆머리·낮은 고글·밝은 이너·오른손 공구 |
| 후면 | 고글 밴드·목덜미 위 머리 끝·재킷 밑단·낮은 팩 고정부 |
| 왼쪽 | 정리된 귀 주변·케이스 두께/잠금부·왼손 지지와 손목 각도 |
| 오른쪽 | 옆머리 외곽·공구 파지·허리 고정부·헤드 작업면 |

팩이 머리와 붙거나 케이스가 팔꿈치의 모든 움직임을 막으면 수정한다. 비대칭 때문에 단순 반전을 기본 허용하지 않는다. 공구가 안 보이는 방향이라고 다른 손으로 옮기지 않고 원근과 가림을 설계한다.

<a id="sd"></a>
## 8. SD 전투 모델

필수 식별 요소는 **단발과 낮은 고글 / 짧은 재킷과 밝은 이너 / 허리·등 아래의 단단한 장비 / 짧고 두꺼운 공구 / 작업용 하체**다. 얼굴과 손·장치의 접점이 작은 화면에서도 남아야 한다.

고글 나사·공구 눈금·봉제선·작은 문자는 덜어낸다. 공구가 안 보인다고 대형 망치나 라이플로 바꾸지 않고 명도·각도·손과 헤드의 간격으로 해결한다.

규격은 [19 §3](19_SD_COMBAT_MODEL_TRANSLATION.md#prototype-spec)의 비교안을 참조한다. 3.25등신·480×480·몸체240px·표시96/128/160px를 Eve의 확정 제작값으로 승격하지 않는다.

독립 움직임 검토는 공구·양팔·짧은 머리 끝·허리 작업 패널을 중심으로 한다. 팩과 케이스는 몸통과 함께 움직일지 먼저 판단한다. 팔 뒤 재킷·케이스 뒤 허리·단발 뒤 목을 복원한다. 팬츠와 각 부츠는 해당 BackLeg/FrontLeg에 포함하며 [19 §5](19_SD_COMBAT_MODEL_TRANSLATION.md#layers)를 따른다.

## 10. 궁극기 전체화면 — 약 3초 비교안

> **문제 지점을 읽은 눈 → 장치를 다루는 손 → 준비를 마친 표정 → 실제 전장.**

| 비교 구간 | 장면 | 개인 정보 |
|---|---|---|
| 0.00~0.40초 | 얼굴·고글 접근 | 작업 방향의 눈, 단발, 정리된 표정 |
| 0.40~1.10초 | 손·공구 확대 | 왼손 지지와 오른손 공구의 물리 관계 |
| 1.10~1.80초 | 짧은 조작 | 작은 잠금·조절부 움직임. 무기 변형 없음 |
| 1.80~2.50초 | 상반신 대표 포즈 | 손은 안정되고 시선이 전장으로 올라감 |
| 2.50~3.00초 | 전장 연결 | 장치 방향·짧은 반응광에서 실제 동작으로 |

3초는 실제 시전시간이 아니다. 핵심 카메라는 공구 제품 자체보다 **손·공구·장치의 접점**에 가까이 들어간 뒤 얼굴로 이어진다. 단말 입력·점등만으로 끝내지 않는다.

몸통은 약한 3/4, 장치와 공구는 가슴보다 낮게 둔다. 공구가 턱·입을 가리지 않고 얼굴을 숙여 정수리만 보이는 구도를 피한다. 손의 작업과 눈의 판단이 함께 읽혀야 한다.

배경은 금속 프레임·작업등·짧은 케이블 그림자를 추상화한다. 얼굴과 손은 중성 작업등, 외곽은 약한 차가운 빛으로 분리한다. 특정 객차 번호·정상 포탑·필수 작업대를 고정해 실제 상태와 모순되지 않게 한다.

실제 궁극기 확인 전 센트리 다수 전개·전 시설 수리·파괴 포탑 재가동·거대 방벽·추가 포격을 결말로 넣지 않는다. 장면의 공구 조작은 원스킬과 별개인 피해·치유·자원 처리기가 아니다.

## 11. 요약 컷인

**약 0.9초 비교안:** 단발·고글·얼굴·공구가 있는 반신 등장 → 엄지의 짧은 조작과 시선 변화 → 공구 방향을 따라 전장 연결.

우선 남길 것은 얼굴·고글·공구 헤드·손이다. 팩과 케이스 전체를 넣으려고 인물을 작게 하지 않는다. 전체화면 분리 원화를 사용하되 요약 크롭·타이밍은 별도 설계한다.

Eve의 표준 전체화면과 OFF/DAILY 반복의 부분 요약은 [04](04_COMBAT_RUN.md#skill-cinematic-policy)·[18](18_BACKGROUND_CUTSCENE_STYLE.md#cinematic-scope)에 연결한다. 부분 요약은 위험 예고·작업 대상·지원3개를 가리지 않는다. 일일 집계·기본값은 개인 바이블의 승인 대상이 아니다.

## 12. 대표 원화·장면

**A. 기준 전신:** 얼굴·고글·재킷·허리 케이스·공구를 확인한다. 공구를 몸에서 조금 떼고 밝은 이너가 손·장비에 전부 가려지지 않게 한다.

**B. 소개 원화:** 정비 구역에서 장치 외장을 점검하는 장면. 한 손은 장치를 받치고 다른 손은 공구를 들며 얼굴이 보이도록 몸을 약하게 돌린다. 거대한 설비는 배경에서 규모만 보강한다.

**C. 이야기 CG:** 객차 작업대에서 소형 부품·분리 외장을 살피는 조용한 장면. 어깨·표정의 긴장을 풀되 같은 손·장비·헤어를 유지한다. 동료 관계·정비 미니게임·새 사건을 확정하지 않는다.

### 기존 정체성 대조와 판단

본 문서 §1–8·12–14의 중심은 얼굴·손·공구의 접점과 “장치의 상태를 먼저 읽고 필요한 곳에 손을 뻗는 현장 엔지니어”다. [32 최신 소개 후보](32_NARRATIVE_REFERENCE.md)의 작은 이상 발견/점검 결과 공유는 성격 표현 참고이며 미승인 서사다. 과거 의료 지원 소개는 역할 충돌 이력으로 사용하지 않는다. [17 최신 Eve 동작](17_OPERATOR_COMMON_STYLE.md#all-fifteen-production-design-animation-v01-20261008-eve)의 펄스 겸용 공구와 양손 지지·독립 센트리를 대조했다. 문서의 제작 후보와 실제 승인된 이브1 공격 시안을 구분하며, 이번 검토로 신규 공격·속성·장비를 확정하지 않는다.

- 큰 원화에서는 단발·고글·작업복·양손 공구로 직업을 읽을 수 있다. 이미 찌푸린 눈썹과 집중된 시선이 있으므로 “집중 표정이 전혀 없다”는 진단은 부정확하다. 준비 장면에서 발견→판단→조작의 고유 태도와 숙련자의 여유가 덜 드러난다는 것이 이번 해석이다.

## 이브 전투 드론·지휘형 엔지니어 상세안 v01 — 2026-10-13 / 설계 검토본

사용자 ‘엔지니어같은경우는 뭐 전투형 드론이 있다거나 이런거 있으면 강해보이고 개성있지 않겠어?’ → ‘상세기획 ㄱㄱ’에 따라 Plan_7 작성. 상세 기획 작성은 승인됐으며 드론 외형·비행 운용·신규 구현을 최종 확정한 것은 아니다. [전원 강함 확정](17_OPERATOR_COMMON_STYLE.md#combat-operator-strength-approved-20261013)과 기존 센트리 설치/강화 핵심을 함께 사용한다. 기존 [44 Eve 장치 계약 후보](44_COMBAT_DETAIL_CONTRACTS.md)의 ‘비행 드론 제외’와 본 안은 충돌한다. 채택 전에는 그 문구를 신규 승인으로 대체하거나 구현에 적용하지 않는다. 기존 이브1 공격v07·원화·역사 시안은 보존한다.

### 1. 캐릭터의 중심

**전장의 작은 이상을 먼저 읽고, 정확한 지시로 전투 드론을 움직이는 강한 현장 엔지니어.**

이브의 판단→짧은 조작→드론의 즉각적이고 힘 있는 대응을 한 흐름으로 보여준다. 강함의 근거는 장비 수보다 전장을 읽는 능력, 정밀한 장치 운용과 본인의 전투 대응이다. 드론 없는 상태에서도 승인된 공구 기본공격과 안정된 준비 자세를 유지한다. 드론을 바라보며 기다리기만 하는 수동적 인물로 만들지 않는다.

- 평소: 장치를 점검하며 말과 동작이 간결하다. 눈이 먼저 문제 지점을 찾고 손이 따라간다.
- 전투: 시선은 적·담당 구역을 읽고, 오른손 공구의 기존 조작부를 짧게 다룬다. 왼손은 하우징 지지 또는 기존 케이스 조작을 맡는다. 주 손은 유지한다.
- 성공: 과한 환호보다 조작을 마치고 공구를 낮추는 안정감, 짧은 입가 변화로 숙련자의 자신감을 보인다. 표정·말투 세부는 후보이며 새 과거사·직급은 추가하지 않는다.
- 개인 이미지의 세 중심: 얼굴/낮은 고글, 양손 공구의 정확한 접점, 이브가 지휘하는 독특한 드론. 모두 같은 크기·밝기로 경쟁시키지 않는다.

### 2. 드론의 대표 외형

작업명 **전투 드론 / 센트리 드론**. 발행 명칭·entityId·assetId는 아직 부여하지 않는다.

- 낮고 넓은 중앙 본체와 좌우의 짧은 밀폐형 부양 포드. 펼치면 위에서 얕은 갈매기형 외곽이 읽히고, 접으면 납작한 공업용 케이스 형태가 된다. 장난감 같은 얼굴·눈·귀는 두지 않는다.
- 전면 중앙에 짧고 두꺼운 단일 사격 헤드. 헤드와 본체 사이에 회전 결합부·작은 반동 경로를 보인다. 좌우 포드는 비행/안정화 구조이며 두 번째 발사구로 읽히지 않게 한다.
- 날개 같은 긴 판이나 드러난 거대 프로펠러 대신 짧은 포드와 보호 외장. 원거리에서 ‘흩어진 작은 부품’보다 본체·헤드·양측 포드 세 덩어리가 남는다.
- 접힘판, 잠금부, 고무 모서리와 조작 표식은 이브의 케이스·공구와 재질 언어를 공유한다. 구조는 이브 전용 장비로 읽히되 새 기업 로고·소속을 발급하지 않는다.
- 건메탈 본체/밝은 무광 보호판/제한된 노란 기능 표식은 색면 후보. 노란 표식은 기존 이브3 후보와 연결 가능한 비교안이며 대표색 확정이 아니다. 발광 없이도 헤드·포드·본체가 구분돼야 한다.
- 크기는 실제 전투 크기에서 이브의 얼굴·손을 가리지 않고 인접 요원·체력바·위험 예고와 겹치지 않는 범위로 비교한다. 정확한 크기·부양 높이는 설치 앵커와 화면 검수 뒤 결정한다. 거대한 기체로 강함을 대신하지 않는다.

### 3. 운용 기준선: 객차 고정 지점의 저고도 부양

본 v01의 상세 설계는 **객차에 고정된 논리 설치점 위에서 낮게 부양하는 한 기**를 기준선으로 삼는다. 부양 흔들림·헤드 회전은 표현이며 논리 사거리 중심·객차 소속·설치점은 움직이지 않는다. 드론은 열차와 같은 좌표계로 이동하고, 이브를 따라다니거나 객차를 옮겨 추격하지 않는다.

### 사용자 정정: 기본 활동 범위와 스킬 목적 이동 — 2026-10-15 / 확정

후속 사용자 ‘좋아 승인 다음 ㄱㄱ’로 직전 제시한 기본 활동(객차+소유 요원 주변)/스킬에 따른 적·아군 대상 이동/아군 접근 후 실드 전개 예시/요원별 효과·복귀 계약 분리를 승인했다. 이브 신규 실드 부여나 아래 최초 제시하는 세부 상태·취소·도착 시간까지 일괄 승인한 것은 아니다.

사용자: ‘기본 기동은 객차 주변 + 해당 드론을 갖고있는 요원 주변으로 제한’, 다만 보호막 제공 등 특정 스킬에 따라 적이나 아군 요원에게 이동 가능. **드론의 기본 활동 범위와 스킬 수행을 위한 출동 범위를 분리한다.** 이 결정은 아래 초안의 ‘담당 객차만/소유 요원을 따라가지 않음/다른 객차 이동 일괄 금지’를 해당 범위에서 대체한다. 모든 드론 요원의 설계에 적용하되 각 요원의 실제 스킬·기체 수·수치·종료 계약은 별도로 유지한다.

- 기본 활동은 소속 객차 주변과 소유 요원 주변이다. 두 주변 영역을 오갈 때의 유효 연결 경로도 명세하며, 주변 두 곳을 잇는다는 이유로 중간 전장 전체를 자유 활동 구역으로 만들지 않는다. 소유 요원이 합법적으로 이동하면 요원 주변 기준도 함께 갱신한다. 객차 소속/소유권 변경과 요원 추종 이동은 다른 상태다.
- 스킬이 특정 아군/적을 대상으로 요구하면 기본 활동 범위를 벗어나 해당 대상까지 실제 이동할 수 있다. 아군 실드 스킬은 대상 요원에게 접근→그 요원 위치에서 실드 전개, 적 대상 접근 스킬은 적에게 접근→원 스킬 효과 수행으로 연결한다. 객차 경계를 넘는다는 이유만으로 금지하지 않는다.
- 출동은 그 스킬의 유효 대상·시전/효과 사거리·경로·행동시간에 결속한다. 이동 허용이 무제한 적 추격이나 모든 스킬의 전장 전체 사거리를 뜻하지 않는다. 이동 중 다른 스킬/일반 사격을 병행할지는 각 스킬 계약에 명시하며 이브의 이동 사격 규칙을 지원 드론에 자동 복제하지 않는다.
- 운용 흐름은 기본 활동→스킬 대상 확정→대상에게 이동→효과 수행/유지→복귀로 제안한다. 대상 이동 시 추종·도착 판정, 도착 전 대상 사망/다운/이탈, 경로 불가·취소/타임아웃, 대상 재선택·비용/환급은 각 스킬에서 확정한다. 무조건 다른 대상에게 이전하거나 실패를 성공으로 표시하지 않는다. 효과 뒤 소유 요원 주변 또는 유효 객차 주변으로 복귀하는 세부 우선순위는 후속 설계다.
- 실드는 ‘도착 후 전개/도착 전 원격 적용/드론이 붙어 유지/드론 복귀 후 잔존’ 중 원 스킬이 정한 방식만 사용한다. 이번 사용자 예시는 **대상에게 가서 전개**하는 방식의 이동 허용 근거다. 보호막 수치·지속/파괴·중첩과 연결 유지 방식은 신규 확정하지 않는다.
- **이브는 현재 일반 전개/궁극기 동일 기체 강화**를 유지한다. 이번 정정으로 이브에게 보호막 스킬을 추가하지 않는다. 이브 기본 기동 영역은 객차+본인 주변으로 수정하며 공격 적격/범위와 실제 기동 위치의 연결은 B 원 정의와 대조한다. 다른 요원의 드론은 그 요원 능력에 맞춰 실드·공격·지원 출동을 설계한다.
- 저장/복원 경계에는 기본 활동 기준(소속 객차/owner), 출동 상태, 원 스킬 사건/대상ID·generation, 경로 진행/도착·효과 확정 여부, 복귀 기준을 추가한다. 발사/실드 등 효과는 도착 애니메이션이 아니라 권위 사건으로1회 적용한다. 대상 소멸·복원·풀 반환으로 중복 실드/피해를 생성하지 않는다.
- 확정은 기본 범위와 스킬별 적/아군 목적 이동 허용이다. 정확한 반경·속도·대상 추종 상한·도착 거리·복귀 우선순위·스킬별 취소/효과 유지 규칙과 실제 구현/검증은 별도 잔여다. 아래 다운 중 현 위치 제동 제안까지 일괄 승인한 것으로 해석하지 않는다.

### 1. 역할과 선택지

이브는 본인 공구 공격과 독립 드론을 함께 운용하는 강한 전투 엔지니어다. 드론의 핵심은 **객차와 이브 주변을 빠르게 기동하며 적격 표적에 지속 사격하는 한 기**다. 스킬 목적 출동은 위 사용자 정정에 따른다. 플레이어는 기존 편성·집중 표적·궁극기 시점으로 운용하고 새 비행 조이스틱/위치 클릭은 추가하지 않는다.

| 검토안 | 동작과 플레이 의미 | 필요한 변경/대가 |
|---|---|---|
| 고정 판정+시각 비행 | 기존 고정 개체 주변으로 그림만 이동 | 제작 비용은 작으나 보이는 위치와 피격 위치가 갈라짐. 사용자가 원하는 실제 기동과 동일시할 수 없음 |
| 담당 객차 내 실제 기동 / 본 상세 전개안 | 논리 위치와 기체가 함께 이동, 같은 담당 구역의 적에게 이동 사격 | 이동 경로·발사점·피격/복원 계약 필요. 다른 객차를 지원하지 못함 |
| 객차 간 추격·재배치 | 구역을 옮겨 적을 따라감 | 배치/방어구역/원객차 파괴·수명/사거리·성능 재설계 필요. 본 상세의 적용 범위 밖 |

위 표는 사용자 정정 전 대안 비교 이력이다. 현재 기본 범위는 객차+소유 요원 주변이며 스킬 목적 출동은 허용한다. 방어벽·치료·탄 요격은 이브 현행 스킬이 아니므로 추가하지 않는다. 다른 드론 요원은 그 요원의 승인 스킬부터 대조하며 이브 기체/수치를 공통 복제하지 않는다.

### 2. 기존 스킬→드론 동작

| 기존 능력 | 기동형 대응 | 유지할 판정 |
|---|---|---|
| 본인 근접/원거리 기본공격 | 양손 공구의 접촉 방전/단일 펄스. 드론 운용 중에도 원 행동 큐로 수행 | 드론 부재에도 공격 가능. 원 ATK·주기·사거리·모드, 무료 기절 없음 |
| 일반 설치 / 작업명 ‘전투 드론 전개’ | 공구 조작→접힌 한 기 전개→초기 발사점 확정→기동 사격 | 준비500/회수300ms·CD18초·수명12초·생성HP 최대HP50%·발당ATK40%/800ms |
| 궁극기 / 작업명 ‘집중 제어’ | 같은 기체의 냉각부 개방·헤드 안정화·v03 승인 강화FX·400ms 연속 사격 | 준비500/회수300ms·충전100·강화8초·ATK60%/400ms. 없으면12초 기체 생성 후8초 강화 |

작업명은 정식 skillId나 발행 문구가 아니다. 일반/강화 수치와 ATK 최초 효과 snapshot·강화 시 재snapshot 없음은 기존 계약을 유지한다. 일반 공격속도로 드론 주기를 단축하지 않는다. 강화는 이동속도 증가·새 탄종·추가 기체·광역 피해를 자동 제공하지 않는다.

### 3. 이동·사거리·표적의 분리

- 생성 때 원 소유 actor/물리 객차 instance/장치 generation을 고정한다. **원 설치점은 소속 기준으로 남고 현재 기체 위치는 실제로 이동**한다. 기본 활동 기준에 소유 요원 주변을 포함하고 합법적인 요원 이동을 반영한다. 소유권·객차 귀속은 추종 이동만으로 바뀌지 않는다.
- 이동 영역은 실제 객차/소유 요원 주변 geometry에 결속한 드론용 경로/체류점과 스킬이 허용한 대상 접근 경로다. 지붕 위와 측면 근처의 기동 가능 공간을 명시적으로 작성한다. 기존 등반 소켓·요원 보행영역을 무단 변경하거나 빈 공간을 통과 가능으로 간주하지 않는다. 스킬 목적 이동과 무제한 추격·픽셀 기반 판정은 구분한다.
- 효과 적격은 `현행 B 효과의 대상 적격 ∩ 해당 스킬의 허용 대상/범위 ∩ 효과 수행 위치의 실제 사거리/LOS`다. 기본 기동 범위와 스킬 목적 이동 허용이 효과의 적격 범위를 자동 확장하지 않는다. 이브 기존 객차 방어구역과 owner 주변 기동의 교차는 B 원 정의에 명시해야 하며, 미공급 범위/대상 단계는 구현 미지원으로 보류한다.
- 타깃은 기존 우선순위인 합법적 집중 표적→담당 객차 공격 실행/예고 적→기존 정렬·안정ID를 따른다. B의 APPROACH/ATTACHED/CLIMBING/ROOFTOP 적격은 해당 효과 원 정의를 확인한다. 모든 단계를 자동 허용하지 않는다.
- 유효 표적을 향해 기존 승인 공간 안의 사격 가능한 체류점으로 이동한다. 체류점 선택은 사격 가능 여부→필요 이동거리→안정 경로/체류점ID 순의 결정론 규칙을 제안한다. 렌더 프레임별 무작위 좌우 왕복은 하지 않는다. 경로가 없으면 현재 유효 위치를 유지하며 이동 실패를 공격 성공으로 바꾸지 않는다.
- 가까운 경로로 빠르게 이동→측면 기울기와 헤드 독립 정렬→이동 중 사격→표적 변화에 새 경로 선택으로 기동감을 만든다. 매 탄마다 의무 정지/출발을 넣지 않는다. 무의미한 배회보다 실제 표적 전환 때 방향 변화가 읽혀야 한다.
- 이동은 원 사격 예약표를 앞당기거나 초기화하지 않는다. 발사 시점에 유효 사격점/표적이 없으면 그 기회를 소진한다. 이후 몰아쏘기·무료 추가탄·회전 완료를 이유로 발사 예약 무한 지연 없음. 비행 자세는 발사 사건을 표시하며 판정 트리거가 아니다.
- 첫 생성은 사격 가능한 초기점이 있는지 효과 시점에 검증한다. 생성 시 첫 사격 기회 포함/만료 시 제외라는 기존12초15회 기회 기준을 유지한다. 표적 소멸·이동 중 사거리 이탈로 실제 명중 수는 줄 수 있으며 15회 적중을 보장하지 않는다.
- 수납 위치→초기점의 물리 전개 경로는 geometry와500ms 준비시간을 함께 검토한다. 긴 객차를 순간 횡단하거나 생성 전 피해를 표시하지 않는다. 준비시간 안의 경로를 공급할 수 없으면 전개 연출/앵커를 보류하며 준비시간을 몰래 늘이거나 줄이지 않는다.

### 4. 피격·강화·종료

이동하는 기체의 현재 논리 위치에 발사점·피격 기준을 결속한다. 높이의 잔진동/반동만 View 오프셋이다. 장치 공격 가능 적/범위효과 후보 참여·안정ID 동률·특별 도발0·방어0/보호막0·일반 요원 대상 공격의 후보 아님을 기존 기준으로 유지한다. 유도탄/고정 위치 위해/범위 공격이 이동 개체에 명중하는 방식은 해당 원 공격 규칙을 따른다. 단순 비행으로 공격 면역·탄 소거·회피율을 부여하지 않는다.

궁극기는 같은 장치의 남은 수명/HP를 보존한다. 강화 종료는 `min(효과시각+8초,기체만료)`이며 다음 예약 발사를 유지한 채 그 발사부터 강화 계수, 이후400ms 주기를 사용한다. 즉시 추가탄 없음. 강화 중 재궁극기 수락/소모0. 수락 후 준비 중 기체 파괴는 기존 대체 설치 규칙으로 효과 시점에 재검증하며 동시1기를 지킨다.

| 상태/사건 | 처리 제안 또는 유지 규칙 |
|---|---|
| 미설치→준비→생성 | 준비는 이브 행동 큐 소유. 수락/비용은 기존 공통 경로1회, 생성 확정 전 공격0 |
| 활성 | 이동 상태(체류/경로 이동)와 강화 타이머를 별도 관리. 이동 중 발사 가능, 모드 조합마다 독립 HP/시계 생성0 |
| 이브 다운 | 신규 발사 정지·수명/강화시간 계속 경과는 유지. 이동은 현 위치에서 제동·안정 부양하는 안을 제안, 다운 중 자동 표적 추격 없음 |
| 이브 복귀 | 유효한 기존 기체에서 미래 발사/경로 선택 재개. HP/수명/누적탄 새 지급0 |
| 기체 HP0/수명 종료/원객차 파괴/노드·작전 종료 | 원 종료 사유로 제거, 미발사 예약·이동/FX 해제. 객차 수리로 무료 재생성0 |
| pause/게임플레이 정지 | 이동·발사·수명·강화 동일 전투시계 정지. 배속은 원 시계에1회 적용 |

웨이브 전환은 기존 잔여수명 정책을 유지한다. B의 ‘파손 객차에서도 생존 요원 전투’와 ‘기체는 원객차 파괴 때 종료’는 서로 다른 개체 규칙이다. 이브 본인의 전투까지 멈추는 것으로 확대하지 않는다. 이미 발사한 탄의 HIT/MISS/소멸은 원 공격 계약으로 해소하고, 장치 종료로 피해를 다시 생성하거나 다른 적에게 이전하지 않는다.

### 5. 플레이 운영·약점·피드백

반복 흐름은 담당 객차 선택→자동 전개→집중 표적 지시→객차/소유 요원 주변 기동 사격→잔여수명을 보고 궁극기 강화→만료 뒤 다음 전개다. 강화 시점에 오래 머무를 강적을 고를지, 당장 위협적인 적을 먼저 제거할지 판단한다. 만료 직전 강화는8초를 다 쓰지 못하며 적격 범위 밖 표적을 기동 허용만으로 공격하지 않는다. 스킬 목적 출동이 있는 다른 요원은 대상 접근 시간과 효과 수행/복귀도 운영에 포함한다. 장치 파괴/소유자 다운/LOS 차단·이동 중 사거리 공백은 실제 손실이다.

이동 자체가 플레이 선택을 바꿨다고 문서만으로 주장하지 않는다. 고정형과 동일 조건에서 유효 사격점 확보/표적 전환 시간·발사 기회 손실·피격 결과를 비교해야 한다. 차이가 시각 배회뿐이면 ‘기동으로 새 전술 완성’이라고 보고하지 않는다. 증강/인챈트의 추가 투사체·관통·지원 효과는 원 카탈로그의 소환 적격/재발동 필터가 확인될 때만 조합하며 이번에 새 옵션을 발행하지 않는다.

기체 방향/짧은 이동 잔상·포드 기울기와 발사 반동을 구분한다. 목표 전환은 헤드 정렬과 단일 탄으로 표시하고 HP·남은 수명/강화·사격 정지는 독립 상태표시로 전달한다. 강화 v03 승인FX는 보존하되 이동 중 잔상/신규 FX는 별도 후보이며 승인된 효과로 오인하지 않는다.

### 6. 가림 방지·독립 리소스와 제작 재개 기준

Direction의 일반전개/접힘 외형 승인과 v03 강화FX 승인은 유지한다. v04 오른쪽 고정 위치는 참고 후보이며 최종 기동 경로나 앵커가 아니다. 새 인물 원화를 통째로 재생성하지 않는다. 기존 기체 통합 PNG를 독립 가동 파츠 납품 완료로 계산하지 않는다.

필요 구성은 인물/공구, 기체 본체, 가동 포드·접힘판/냉각판, 회전 헤드, 상태광, 총구 섬광/탄/명중, 부양 그림자와 동적 UI다. 가동·숨김·교체가 필요한 축을 독립 제어하고 PNG/아틀라스/절차적 FX 등 공급 방식은 제작자가 정한다. 필요한 숨은 접속면과 네 방향·기울임에서 보이는 면을 먼저 명세한다.

먼저 기존 승인 외형을 이용한 reference-only 기동 검토에서 **초기 전개→이동 중 사격→표적 전환→강화→다운 정지→종료**를 이어 보여준다. 얼굴/공구·다른 네 요원·적 예고·HP바 가림을 실제 화면 크기와 좁은 화면에서 검사한다. 후보 경로를 바꿀 때도 같은 논리 위치/사격점과의 연결을 표시한다. 화면 가림을 피하려고 View만 다른 객차로 순간 이동시키지 않는다. sorting/국소 투명화가 필요하면 해당 표현안을 따로 검토하며 적 경고와 입력을 숨기지 않는다.

추가 원화/전체 모션 재개 조건: 본 기동 범위의 사용자 채택, 기체 경로/초기점·표적과 피격 기준 확정, 기존 외형의 회전/기울임 가능 범위 대조. 이 조건 전 Direction 대기 기록을 완료/재개로 바꾸지 않는다. 정책 확인 후 원화별 제작·독립 구조 검수와 실제 Unity/gameplay 검수를 분리한다.

### 7. 소유권·경계·저장과 수용 사례

Plan은 기동/적격/수명 규칙, Direction은 파츠·주요 자세/전투 가독성, Unity는 geometry authoring과 표시 연결 및 일반 솔로 전투 도메인, 협동은 기존 단일 호스트, 월드보스는 기존 서버 판정을 따른다. Server는 출발 정의·버전·진행/결과 검증을 소유한다. ‘드론이니 전부 서버에서 계산’으로 현행 권위를 바꾸지 않는다. 모드별 지원은 별도 확인하며 일반 B 검토를 월드/내부전에 자동 전파하지 않는다.

필요한 경계 데이터는 원 정의/version/hash, ownerActor/객차 instance, 기체ID/generation, 원 앵커/현재 논리 위치·경로ID/진행도·마지막 step, HP/생성·만료·강화 종료, 원ATK snapshot, nextFire/순번, target ID/generation, 공격 eventId/원 발사점·확정탄, 종료 사유다. 이는 요구 의미 목록이며 실제 API 필드명/새 wire 버전/발행ID 확정이 아니다. geometry version/hash와 공간 단위도 원 규격에 결속한다.

Model이 HP/이동/발사·타이머의 단일 소유자다. View는 원 사건을 표시하고 Controller는 기존 스킬/집중 표적 명령에 바인딩한다. 재바인딩/풀 반환은 소유 구독·이동 보간/FX만 해제하며 도메인 공격을 재발행하지 않는다. 복원은 같은 위치/경로 진행·미래 예약·종료 세대를 보존하고 완료된 발사/HIT를 중복하지 않는다. 잘못된 경로·누락 geometry는 명시 오류이며 고정형으로 몰래 대체하지 않는다.

### 8. 승인·선행·현재 결과

기본 기동 범위는 **객차+소유 요원 주변**, 특정 스킬에 따른 **적/아군 대상 접근 이동 허용**으로 사용자 확정했다. 기존 수치 유지·현재 위치 피격/이동 사격 상세와 다운 중 현 위치 안정 부양 제안은 위 정정이 확정한 범위와 구분한다. 정확한 이동속도·가속·높이·체류점/반경·효과 사거리·전개/대상 접근/복귀 경로 치수는 geometry 원본 확인 후 별도 시험값을 제시하며 이번에 임의 숫자로 확정하지 않는다. 범위 결정이 곧 미공급 치수·B 대상 단계·구현 지원 승인은 아니다.

### 10. 스킬 목적 출동의 계약 틀 — 다른 드론 요원에도 적용할 설계 요구

동작은 **기본 활동→출동 수락→접근→효과 확정/유지→복귀**로 구분한다. 이브 일반 사격은 기본 활동 중 허용되며 궁극기는 본 기체 강화이므로 아군 방문 임무를 새로 만들지 않는다. 아래 표는 향후 공격·지원 드론의 명시 스킬에 필요한 설계 항목이다.

| 구간 | 각 스킬에서 정할 것 | 공통 중복 방지 |
|---|---|---|
| 수락 | 적/아군 적격·원 입력·시전 범위·기체 수·비용·기존 임무와 경합 | 같은 command/skill 사건 재수신으로 출동2회·소모2회 없음 |
| 접근 | 원 대상ID/generation·유효 경로·추종 가능 범위·도착거리/허용시간 | 새 적/새 요원으로 ID를 재사용해도 원 대상과 혼동하지 않음 |
| 효과 | 도착 후1회/유지형 여부·현재 적격 재검사·원 사거리/LOS·snapshot 시점 | 도착 모션/프레임/재바인딩이 효과를 직접 발동하지 않음 |
| 유지 | 대상 동행 여부·연결 거리·드론이 떠나면 효과 종료 여부·지속시간 | 드론 자체HP/실드HP/아군HP를 합치거나 보호를 중복 복제하지 않음 |
| 종료/복귀 | 성공·취소·대상 무효·시간초과·기체 파괴별 처리와 기본 활동 복귀점 | 종료된 임무의 늦은 도착/효과 사건을 다음 임무에 적용하지 않음 |

예: 아군 실드 드론은 그 요원에게 접근해 원 실드 효과를 전개한다. ‘이동 중 실드 미리 적용’, ‘보호막을 두고 복귀’, ‘대상 곁에서 유지’는 서로 다른 기능이므로 각 스킬이 채택한 하나를 명시한다. 현재 roster에서 승인된 해당 스킬을 확인하지 않은 채 새 지원 드론 요원이나 보호막 수치를 발행하지 않는다.

출동 대상이 이동하면 원 스킬 추종 범위 안에서만 경로를 갱신한다. 도착 전 사망/다운/퇴장/범위 이탈·경로 불가는 재검사하며 대체 대상/환급/복귀는 각 스킬 규칙에 따른다. 대상 무효일 때 무조건 다른 아군에게 실드를 주는 숨은 자동 구조 변경은 없다. 효과의 의미에 따라 다운 요원이 적격일 수 있으므로 모든 지원 스킬의 다운 대상을 일괄 금지하지 않는다.

### 11. 다음 시각 검토 단위·파츠 명세

신규16방향/전체 모션을 바로 만들기보다 승인 일반/접힘 기체와 승인 강화FX를 재사용한 **한 연속 동작 검토**를 준비한다. 장면은 ‘전개→owner 주변 기동 사격→표적 바뀌어 방향 전환→같은 기체 강화→owner 다운 정지/복귀→만료’다. 스킬 목적 아군 방문은 이브 미보유 실드 연출로 넣지 않고 별도 공통 설계 예시로만 보관한다.

- 회전 헤드/본체/좌우 포드·접힘판·냉각판·상태광·독립 탄/섬광/명중·그림자별 상태 입력과 표시 계층을 먼저 정의한다. 기존 통합PNG로 범위 후보를 볼 수 있으나 가동 파츠 납품으로 세지 않는다.
