## 2. 검사 방법과 범위

Python으로 실제 전달 디렉터리의 파일을 읽어 존재·UTF-8·제목/펜스·표 블록·명시 HTML 앵커를 확인했다. Markdown의 대괄호/괄호 링크에서 상대 경로를 추출하고, 전달 파일 또는 확보한10개 기준 텍스트에서 대상과 명시 앵커를 대조했다. 외부 URL 접속·전체 Markdown 렌더러 호환·실제 웹/앱 클릭 검사는 수행하지 않았다.

현재 업로드6개와 확보한 전체 텍스트3개는 조립 전 기록한 SHA-256과 재비교했다. 04·11은 전달 본문과 확보한 전체 추출 텍스트를 바이트로 대조했지만, 원본 라이브러리 Markdown의 raw바이트를 확보한 검사가 아니다. 18은 개인 컷신 참조/구도 요약만 보완했다.

00의 과거 검증 결과·R01~R32 출처 구간, J표, 아트 외 현행 정책 행,19의 규격/사건 연결,20·21의 무기 전문을 원본 사본과 비교했다. 변경된 상태 문구·색인·개인 보완은 현재 사용자 승인 범위에 맞춰 검토했다. 자동 문자열 검사가 모든 의미적 오류의 부재나 실제 스킬/자산 적합성을 증명하지는 않는다.

22~29는 원본 업로드 파일이 아니라 채팅의 상세안·보완·승인을 정리한 최신 전체 본문이다. 얼굴·헤어·복식/장비·팔레트·네 방향·SD·동작·전체화면/요약·산출물/검수·승인 경계를 포함했다. 대화문과 파일의 바이트 동일성을 주장하지 않으며, 공통 규칙은 담당 문서 참조로 정리했다.
