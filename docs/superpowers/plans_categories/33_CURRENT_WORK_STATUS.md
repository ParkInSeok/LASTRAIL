### 이미 있는 기반 — 새로 만들지 말 것

- 증강 View/Controller/Presenter와 엄격한 명령·수명 계약. 현재 `IAugmentSelectionPort`와 `IAugmentSelectionJournal`에 운영 adapter가 없다는 주석·호출 위치를 확인했다.
- 객차 피해 `CombatDamageRouter`: TransferBps=3000, 원 event 영수증·메모리 중복방지. 현재 주석상 producer 비활성·영속 복원 후속 경계.
- 서버 `solo-augment-selection.ts`의 독립 도메인, `ad-skip-routes.ts`의 OFFLINE/COMBAT 가용성 및 REROLL UNSUPPORTED.
- 보급 지급실패 후 재추첨 방지0038, 공용 재화 원화58·수량60·폭61, 편성53·공유 지원아이콘55는 후속 근거가 있는 기존 작업이다. 오래된 OPEN 행만으로 다시 미구현 처리하지 않는다.
- 기존 문의 접수/조회, 성장·출석·보상 및 balanceVersion 기반이 있다. 새 기획 이름으로 소유자/API를 중복 생성하지 않는다.

### 구현 전에 해당 부분만 결정할 사항

1. T18의 HP0 Gun 작동 후보와 객차 생존 필수 규칙 충돌.
2. 노드3선택과 물리 좌우 레버의 선택/확정 관계, 온라인 선택·전체화면 hold의 서버 시간 계약.
3. J04 전체 맵 길이·노드별 웨이브·제약/가중치의 최종 채택 여부. 랜덤 증강 지급은 이미 확정이며 다시 묻지 않는다.
4. 작전물자 시작량·가격·수급 후보, 보스/확장 이벤트 채택 범위.
5. World Raid 초기화 05KST/공통04KST, 출석 엘리트권 실제 아이템/풀 binding.

## 기획 변경 영향 대조 및 선행 작업 — 사용자 재점검 요청 반영

앞선 I01~I26과 화면 제작 목록은 시스템 기능을 나열했지만, 기획 변경이 다른 분야로 전달되는 선행 관계를 충분히 명시하지 않았다. 이 절이 작업 순서를 보완한다. 이번 대조는 최종 기획에 이미 있는 변경과 의존성을 추적한 것이며, 아래 미정 관계의 설계안·수치·새 콘텐츠를 승인한 것이 아니다. 2026-09-21 문서/현재 기록 점검이며 모든 코드·이미지·대사를 새로 실행·육안 검수 완료한 상태가 아니다.

### 1. 설계 선택과 공통 골격
세로 화면을 일괄 축소하면 정보/터치가 작아지고, 모든 화면에 같은 다열 틀을 강제하면 전투 조작과 컷신을 가린다. 제안은 공통 헤더·안전영역·입력층만 공유하고 본문은 화면 목적에 따라 구성하는 방식이다. 새 메뉴·상품·재화는 추가하지 않는다.
일반 화면 상단은 [뒤로 / 제목]과 [해당 화면 관련 재화]로 나눈다. 본문과 실행영역은 분리하고, 실행 버튼은 해당 상세영역 하단에 고정한다. 전체 화면 아래에 모든 화면 공용 실행바를 추가하지 않는다. 버튼 이동/레이아웃 전환 도중 이미 누른 터치를 새 버튼의 클릭으로 전환하지 않는다.

### 3. 안전영역·키보드·화면 비율
배경만 화면 끝까지, 제목·재화·닫기·확정·노즐·자막 등 정보/입력은 안전영역 안에 둔다. 좌우 노치/시스템 제스처 영역 변경 시 같은 화면 상태로 재배치한다. 창 크기/안전영역 변경은 재조회나 선택확정 사유가 아니다.
키보드가 열린 경우 입력 중 필드와 현재 입력용 확인/취소가 보이도록 본문을 이동/스크롤한다. 입력 초점·작성 내용 보존, 키보드 위로 전체 UI 축소 금지. 키보드 높이 변경과 접기만으로 서버 저장하지 않는다. 외부 결제/로그인/브라우저 화면은 OS 소유 정책을 따르고 게임 복귀 시 가로/원화면/원요청 결과를 복원한다.

### 4. 팝업 종류와 닫기 허용
- 단순 정보: 읽기용 상세는 같은 상세영역 교체를 우선한다. 모달이 필요하면 중앙 패널로 띄우고 X/뒤로로 닫는다. 바깥 터치 닫기는 읽기 전용 팝업에만 허용하며 그 터치는 소모한다. 상시 노출된 목록 옆 상세영역은 바깥 터치로 사라지지 않는다.
- 작은 확인: 명확한 행동명과 취소를 제공한다. 바깥 터치는 무시한다. 뒤로/X는 취소와 같은 처리이며 긍정 실행을 대신하지 않는다. 파괴/비용 명령에 기본 선택·뒤로로 긍정 실행 금지.
- 편집/문의/긴 설명: 넓은 패널과 본문 스크롤, 제목/X·현재 행동은 고정. 작성 내용이 있으면 기존 변경 유실 확인을 사용한다. 빈 읽기창 닫기에 확인창을 추가하지 않는다.
- 필수 결정/진행 제한: 증강 확정 같은 필수 단계는 X/뒤로로 미선택 통과하지 못한다. 기존 허용 경로만 제공한다. 인증/점검 등 서비스 전역 제한은 상위 입력층에서 제한 사유와 원복구 행동을 제공한다.
- 명령 처리 중: 출격/장착/보상은 원명령 Controller/복구 owner가 계속 관리한다. 닫기 가능 여부는 해당 기존 계약대로 표시하고, 허용된 표시 닫기를 서버 취소로 취급하지 않는다. 전송 후 재진입은 같은 요청/확정 상태를 보여준다.

### 5. 뒤로가기와 닫기 입력의 정확한 범위
Android 뒤로/Escape는 현재 최상위 입력 소유자가 아래 순서로 한 번만 소비한다.
1. OS가 키보드/외부 UI에서 소비했다면 게임으로 다시 전달하지 않는다. PC 편집 컨트롤이 Escape를 소비한 경우도 동일하다.
2. 최상위 게임 입력층에서 진행 중인 드래그/대상 선택이 있으면 그 조작만 취소한다. 아래 화면의 오래된 선택이 상위 모달보다 먼저 처리되지 않게 한다.
3. 최상위 상세/확인/편집 팝업의 닫기 요청으로 전달한다. 미저장이면 기존 확인을 표시하고 이번 입력은 종료한다. 닫기 불가 단계는 그대로 유지한다.
4. 팝업이 없으면 현재 화면의 기존 이전 경로로 이동한다. 목록→좁은 화면 상세라면 목록 복귀가 우선이다.
5. 최상위 로비는 임의 로그아웃/작전 포기/앱 종료를 실행하지 않는다. 전투의 뒤로는 기존 전투 메뉴 계약으로 처리하며 즉시 로비 이동/포기하지 않는다. 컷신은 기존 스킵 계약을 사용한다.
X는 자신이 속한 패널의 닫기 요청이고 Android 뒤로/Escape는 상위 입력 라우팅이므로 모든 입력을 무조건 같은 전역 pop에 연결하지 않는다. 최종적으로 같은 패널을 닫게 될 때는 그 패널 Controller의 동일 CanClose/RequestClose 처리에 연결한다. 취소/X/뒤로에서 저장·전송 코드를 각각 복제하지 않는다.
한 번 누르고 뗀 입력은 한 단계만 처리한다. 길게 누른 키의 반복 이벤트나 같은 터치 해제 이벤트로 부모까지 닫지 않는다. 빠르게 두 번 별도로 누른 입력은 전이가 완료된 뒤 유효한 다음 입력으로만 처리한다. 열기/닫기/재배치 중 시작된 손가락이 뒤쪽 전장/버튼을 실행하지 않게 pointer 소유권을 유지한다. 팝업 뒤 raycast와 키보드 명령은 차단하되 전체 앱 입력을 고정 시간으로 막는 임의 지연은 추가하지 않는다.

### 6. 표시 상태·명령·메모리 소유권
Model은 계정/run/버전별 확정 상태, Controller는 기존 명령·닫기/화면전환 조정, View는 표시와 입력 의도만 담당한다. 전역 팝업 관리자가 보상/장착 판정이나 통신을 소유하지 않는다. 기존 공통 입력/화면 관리자가 있으면 그 경계에 연결하며 기능마다 새 전역 관리자를 만들지 않는다.
