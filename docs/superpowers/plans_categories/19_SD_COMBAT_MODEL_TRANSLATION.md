# LAST RAIL | 원화 → SD 전투 모델 변환 규칙

> **최신 승인 2026-10-05:** 전투 요원은 SD 기본 정책을 대체하여 일반 비율·단순화한 실루엣·큰 전투 동작으로 제작한다. 과거 SD 비례/제작 기록은 역사 보존. [현행 리소스·모션 정책](19_SD_COMBAT_MODEL_TRANSLATION.md#normal-proportion-large-motion-approved-20261005)이 충돌하는 과거 지침보다 우선한다.

작성일: **2026-09-21**. 작업 범위: 공통 가이드 3종 중 세 번째. [16](16_ART_STYLE_GUIDE.md)은 상위 품질·세계관, [17](17_OPERATOR_COMMON_STYLE.md)은 10인 정체성, [18](18_BACKGROUND_CUTSCENE_STYLE.md)은 배경·연출을 소유한다. 실제 공격·상태·시간·장착·생존 규칙은 [04](04_COMBAT_RUN.md)와 [13](13_EQUIPMENT_ENCHANTMENTS.md)를 따른다.

**상태:** 2D 비픽셀 SD 전투용 설계안. 개인20~29의 큰 외형 방향·차별화 보완은 중립 전신 설계 기준으로 채택되었지만, 아래 비례·480px 캔버스·240px 몸체·128px 표시 시험값은 **시제품 비교용 제안**이다. 실제 PNG·리그·애니메이션·프리팹을 생성하거나 검수하지 않았다.

## 1. 변환의 정의

> **원화를 작게 줄이는 것이 아니라, 원화의 정체성을 작은 화면에서 다시 읽히도록 재설계한다. 고급스러운 형태·색·마감은 유지하고 미세 정보량을 줄인다.**

두 번째 릴스의 세밀한 눈·머리카락·주름을 전투 스프라이트에 모두 넣는 것이 목표가 아니다. 머리 형태·몸체 비율·코트 윤곽·대표 장비·핵심 색배치가 같은 인물로 읽혀야 한다. 원화와 SD는 공통 정체성 정보를 공유하고 제작 파일은 분리한다.

비픽셀 2D가 현재 기준이다. 과거 32/64/128px 픽셀 표, 디더링, 1픽셀 수동 작업, 정수배 확대 전용 규칙을 자동으로 되살리지 않는다. Aseprite·특정 생성 도구·3D 제작을 필수로 지정하지 않는다. 고품질 2D 출력과 반복 동작의 일관성을 검증할 수 있는 제작 방식을 선택한다.

## 2. 보존·압축·제외 매트릭스

| 원화 요소 | 반드시 보존 | 전투용으로 압축 | 별도로 분리/제외 |
|---|---|---|---|
| 얼굴 | 눈매 인상·홍채 대표색·표정 방향 | 피부 명암, 코/입의 작은 형태 | 피부 미세 질감·과도한 반사 |
| 머리 | 앞머리와 포니테일 등 2~3개의 큰 실루엣 | 잔가닥·윤기 면의 수 | 프레임마다 바뀌는 머리장식 |
| 몸체 | 체형 인상·자세·역할의 무게중심 | 팔/다리 길이와 손발 형태 | 콜라이더/사거리를 아트 크기로 임의 변경 |
| 의상 | 큰 코트 길이·상하체 색·대표 파츠 | 봉제·미세 주름·작은 버클 | 읽히지 않는 문구·반복 장식 |
| 무기/도구 | 종류·주 손·대표 기능부·실루엣 | 작은 배선·조각·표면 마모 | 다른 유형 무기로 교체 |
| 조명 | 기본 면과 재질 차이 | 기준 주광·짧은 엣지 강조 | CG에 고정된 강한 환경색·화염 반사 |
| 상태 | 실제 애니메이션 상태의 명료함 | 제한된 피격·준비·발동 강조 | HP·Ready·Down·세트표식을 원화에 bake |

각 요원의 전용 바이블에서 **필수 식별 요소 3~5개**를 지정한다. 변환 시 하나를 없애야 한다면 왜 필요한지 기록하고 정체성 비교를 다시 한다. 얼굴 디테일을 줄였다는 이유로 모든 요원을 같은 SD 얼굴로 통일하지 않는다.

## 3. 공통 시제품 규격 — 아직 최종 제작값 아님

| 항목 | 비교 시작값 | 의미/확정 조건 |
|---|---|---|
| SD 비례 | 약 **3.25등신**, 3.0~3.5 범위 비교 | 5인 배치와 표정/무기 공간을 함께 보고 결정 |
| 표준 몸체 높이 | 기준 요원 H=1.0 | 체형 후보는 대략 ±10% 비교. 키/성별/스탯 확정 아님 |
| 프레임 캔버스 | **480×480 RGBA** | 같은 애니메이션의 캔버스·원점 유지 |
| 중립 몸체 높이 | 발바닥~머리 본체 약 **240px** | 포니테일·긴 무기·FX는 별도 외곽 범위로 측정 |
| 발 기준점 | 좌상단 원점 기준 **(240,384)** | 고정 지면 접점용 시험값; 움직이는 발 하나의 끝점을 뜻하지 않음 |
| 기준 화면 시험 | 720×1280의 root에서 몸체 **128px** 높이 | 실제 카메라·객실에서 확인 후 결정 |
| 추가 표시 시험 | 몸체 96/128/160px | 세 크기에서 식별·겹침·정보 소실 비교 |
| 초상화 비교 | 실제 상태바 크기 + 64px 비교본 | 상태 UI 크기를 이 문서가 다시 정하지 않음 |

**파일 해상도, 캐릭터 몸체의 캔버스 점유, 화면 표시 높이는 서로 다르다.** 480px 파일을 무조건 화면에서480px로 보여주거나, 240px 몸체를 새 공식 키로 해석하지 않는다.

720×1280 root가 폭360에 비율축소되면128 논리픽셀 몸체는 약64 표시픽셀이다. 실제 물리 화면의 식별 검수가 필요한 이유다. root 기준과 실제 픽셀을 검사표에 따로 기록한다.

긴 장총·기관총·기술 장치가 캔버스를 넘으면 몸을 억지로 줄이지 말고 무기 분리나 프레임 여백 확장을 비교한다. 콜라이더·공격 범위는 별도 게임 정의다. 동일 프레임 규격 변경은 전 동작·메타데이터를 일괄 대조한다.

## 4. 방향과 비대칭

디자인 검토용 **정면·후면·좌·우 네 방향 보조도**를 먼저 맞춘다. 이것이 모든 동작을 반드시4방향으로 제작한다는 뜻은 아니다. 실전에서 필요한 방향·시점은 현재 내부전 카메라와 행동 상태를 확인해 정한다.

첫 전투 시제품은 현재 전장에 맞는 주 사용 시점 하나에서 만들고, 반대 방향을 비교한다. 원근이 있는3/4와 완전 측면을 혼합해 한 인물의 몸체 두께가 바뀌게 하지 않는다. 카메라가 확정되지 않은 상태에서 8방향 전 동작을 일괄 생성하지 않는다.

좌우 반전은 외형이 대칭이고 실제 무기/기능·장착 위치를 위반하지 않을 때만 허용한다. **주 손·탄 배출부·스코프·한쪽 장갑·패치·문자·비대칭 헤어는 단순 미러링 검수 대상**이다. ‘화면 앞팔’과 ‘인물의 오른팔’을 동일한 이름으로 혼용하지 않는다.

## 5. 레이어 분리는 움직임과 앞뒤 관계 기준

다음은 레이어/리그 설계용 논리 파츠다. 사용하는 도구에 따라 실제 파일 수는 달라질 수 있다. 프레임 애니메이션이어도 각 파츠의 연결과 가려진 형태를 일관되게 관리한다.

| 파츠 | 포함할 내용 | 분리 이유 |
|---|---|---|
| Shadow | 발밑 접지 그림자 | 인물 몸체와 별도로 위치·강도 조정 |
| BackHair | 포니테일·뒤쪽 머리 덩어리 | 몸체와 다른 관성·가림 |
| BackCoat | 몸 뒤의 코트 자락 | 다리와 다른 동작·앞뒤 정렬 |
| BackLeg | 기준 자세의 뒤쪽 다리와 그 부츠 | 걷기·자세 변화 |
| FrontLeg | 기준 자세의 앞쪽 다리와 그 부츠 | 걷기·겹침 순서 변화 |
| Body | 몸통·허리·함께 움직이는 벨트/파우치 | 중심 동작과 의상 연결 |
| RearArm | 뒤쪽 팔과 붙어 움직이는 손/장갑 | 무기/몸통과의 가림 |
| Head | 얼굴·귀·머리 기본형 | 시선과 작은 회전 |
| FrontHair | 얼굴 위 앞머리 | 얼굴 가림·머리 흔들림 |
| Weapon/Tool | 대표 무기 또는 사용 도구 | 조준·반동·배치 |
| FrontArm | 앞쪽 팔과 손/장갑 | 무기 파지 유지 |
| CombatFX | 발사·피격·스킬 효과 | 전투 사건과 결속 |
| StateOverlay | 실제 Down/상태 강조 | 현재 상태에 따른 독립 표시 |

다리와 부츠는 별도 움직임이 필요한 경우가 아니면 합친다. 보이는 파편만 잘라 파츠로 만들지 않고 **관절과 겹침 뒤에 속한 가려진 영역까지 복원**해 움직일 때 빈 구멍이 생기지 않게 한다. 검수 전 픽셀 팬게임의 레이어 수·좌표·필터를 통째로 가져오지 않는다.

Back/Front는 기준 포즈의 렌더 순서를 뜻한다. 리그·애니메이션에서는 실제 해부학적 left/right와의 매핑을 메타데이터로 보존하고, 방향이 바뀌었을 때 파츠의 물리적 정체성을 바꾸지 않는다.

## 6. 앵커와 기준점

| 앵커 | 담당 |
|---|---|
| Root / Ground | 전장 위치와 발 기준. 걷기 모션으로 실제 이동을 이중 적용하지 않음 |
| BodyCenter | 몸체 중심, 상태 오버레이 기준 |
| Head / UIAnchor | 얼굴·머리 위 표시 위치. 실제 UI는 별도 |
| HandGripMain / Sub | 무기 파지점. 반동 중 손이 분리되지 않음 |
| Muzzle / EffectOrigin | 발사구·지원 효과 시작점. 실제 스킬 원점과 매핑 |
| WeaponPivot | 조준·반동·도구 회전 |
| Attachments | 실제 사용할 장식/도구 부착점만 정의 |

메타데이터는 캔버스 크기, 원점 방향, 기준점 좌표, 몸체 bounds, 프레임 순서, 애니메이션 상태, 좌우 반전 제한을 포함한다. 원본 좌상단 좌표와 엔진의 정규화 pivot을 혼용하지 않는다.

예를 들어 시험 캔버스480×480에서 좌상단 좌표(240,384)는 좌하단 정규화 좌표로(0.5,0.2)다. **변환 예시일 뿐 실제 Unity Import 값을 적용한 결과가 아니다.** 자동 trim을 쓰면 원래 기준점과 오프셋을 반드시 보존해야 하며, 프레임마다 기준점을 새로 중심 정렬하지 않는다.

## 7. 애니메이션 요구와 실제 사건 연결

| 동작 | 반드시 읽힐 내용 | 게임플레이 경계 |
|---|---|---|
| Idle | 머리/코트의 작은 움직임, 준비 자세 | 이동·마나 회복·Ready를 새로 발생시키지 않음 |
| Walk/Move | 지면 접지, 무기 파지, 체중 이동 | 실제 이동을 시뮬레이션에서 읽음. 화면 모션이 경로를 결정하지 않음 |
| Basic Attack | 준비→실제 공격 순간→회수 | 피해/발사는 실제 공격 이벤트와1회 매핑 |
| Active | 기존 스킬의 장치/행동 특성이 보임 | 사용 자원·쿨타임·대상 조건을 애니메이션이 우회하지 않음 |
| Hit feedback | 실제 피격 이벤트의 짧은 색상 반응 | 별도 캐릭터 피격 모션·hit 오버레이를 만들지 않고 공격 모션을 유지. 실제 판정의 중단/경직은 별도 계약 |
| Down/Defeated | 전투불능이 즉시 판독됨 | Down을 영구 사망으로 바꾸지 않음 |
| Return/Recover | 기존 복귀 상태에서만 복귀 | 모션 종료를 부활 권한으로 사용하지 않음 |
| Ultimate | 실제 지정·허용된 요원 능력만 | ALWAYS·DAILY 첫 재생 시 표준 전체화면/전투0. OFF·DAILY 반복은 짧은 부분 요약 컷인 + 실제 SD 동작/FX이며 전투 계속. [18](18_BACKGROUND_CUTSCENE_STYLE.md#cinematic-scope)·[04 §14](04_COMBAT_RUN.md#skill-cinematic-policy) |

프레임 방식의 시험 출발점은 Idle4~6, Walk6~8, Attack6~10, Active8~12, Down/Return 각각4~6프레임으로 제안한다. **상태당 비교용 원화 개수이며, 스킬 지속시간·초당 프레임·피해 횟수·런타임 비용을 확정한 숫자가 아니다.** 실제 속도에 맞게 재생 타이밍을 조정하고 중요 포즈가 생략되지 않는지 검사한다. 이전 Hit2~3프레임 제안은 2026-09-11 사용자 지시의 피격 tint 전용 규칙과 충돌하여 제외한다. 당시 0.16 simulation초는 구현 기록이며 새 최종 수치 승인으로 취급하지 않는다. 근거: [기존 미술 인수 사양](51_UI_ART_DETAIL_CONTRACTS.md#source-0162a4001283270c)의 연속 공격·다운·복귀 사양.

피해 판정을 AnimationEvent에서 독립 생성하거나 프레임을 두 번 보였다는 이유로 피해를 두 번 처리하지 않는다. 연출 이벤트는 기존 attackId/actionId/상태와 연결해 표시하고, 순수 시각 잔상은 판정이 없다고 구분한다. 높은 공속에서 지나친 배속으로 포즈가 무너진다면 회수 포즈·보간·표시 빈도를 조정하되 실제 공격 횟수는 바꾸지 않는다.

전투 정지 중에는 실제 SD 개체와 게임플레이 애니메이션을 정지 정책에 맞춘다. ALWAYS 또는 DAILY 첫 재생의 표준 전체화면 및 별도 허용된 초토화 요약 전체화면은 별도 presentation clock으로 움직이는 연출용 객체이며, 실제 정지한 배우/포탑을 움직여 판정 상태를 바꾸지 않는다. UI·컷신과 전투 시간의 경계는 [04 §14](04_COMBAT_RUN.md#cinematic-clocks)를 따른다. 스킬 쿨타임·증강 선택·열차 주행 시간을 캐릭터별 Update나 독립 모션 타이머에서 다시 계산하지 않는다.

## 9. 상태·이펙트·장비 표현 경계

머리·대표 무기는 지속적으로 식별 가능해야 한다. 위험 예고와 실제 피해/보호막의 시작·유지·해제를 각각 구분한다. 높은 등급 장비의 상시 거대한 오라로 다른 요원과 적을 가리지 않는다.

실제 장비3슬롯은 인벤토리/효과 시스템이다. 모든 카테고리·성급·세트 조합별로 인물의 의상을 갈아입히는 기능은 추가하지 않는다. 단일 세트 태그 실장착 계산과 인챈트 시술값은 [13](13_EQUIPMENT_ENCHANTMENTS.md)가 소유한다. 시각 자료에 6성이면3세트 같은 잘못된 설명을 넣지 않는다.

포탑은 요원과 다른 자산이다. 별도 궁극기 모션·게이지를 만들지 않으며, HP가 남아도 소속 객실 파괴로 전투불능이면 발사 준비/정상 작동 FX를 종료한다. 이미 발사된 투사체의 후속 처리 등은 기존 전투 계약을 따른다.

색만으로 Down·선택·아군·적군을 구분하지 않고 아이콘·외곽·자세를 함께 사용한다. 화면 전체 색 보정이 꺼져도 이 상태 정보는 유지돼야 한다.

Reina와 Kyle를 첫 비교쌍으로 제안한다. 둘의 얼굴/가벼운 코트/권총과 무거운 전열이 동시에 읽히는지 확인한 뒤, Mira 또는 Vex로 긴 무기 겹침을 점검한다. 세 캐릭터의 기본 문법을 검증하기 전 10인의 전체 애니메이션을 양산하지 않는다.

## 11. 납품 계약 — 파일·메타데이터·검수 자료

필수 자료는 기준 포즈 확인본, 사용 방식의 편집 원본, 분리 파츠 또는 프레임 출력, 필요 방향표, 애니메이션 목록, 기준점/좌표계/trim 오프셋, 실제 assetId 매핑, 라이선스/출처·수정·승인 기록이다. 어떤 도구에서 생성했는지만으로 품질 승인하지 않는다.

샘플 파일 형식은 `op_<stableId>_sd_<view>_<state>_<revision>.png`다. 실제 stableId·폴더·atlas·Addressables key는 기존 자산 등록과 맞춘다. 가칭 이름 변경으로 서버 ID를 바꾸지 않는다.

투명 배경의 엣지·검은 테두리 번짐·밝은 배경의 halo·아틀라스 이웃 픽셀·텍스처 압축을 실제 출력에서 검사한다. 필터·압축·PPU는 비픽셀 목표와 실제 카메라 기준으로 결정하며 과거 pixel 전용 Point 설정을 묵시 재사용하지 않는다.

원본 레이어/프레임과 검수용 합성 시트는 구분한다. 프레임 이름·라벨이 붙은 합성 시트를 게임 스프라이트처럼 임포트하지 않는다. 실제 콘텐츠 준비·배포는 [02](02_CONTENT_UPDATE.md)·[08](08_BALANCE_RELEASE.md)를 따른다.

### 12.1 개인 바이블 교차 검토의 실제 확인

같은 각도·중립 조명에서 얼굴을 먼저, 헤어·장비를 포함한 전신을 컬러/흑백/검은 실루엣으로 비교한다. 장비·머리색을 가린 얼굴 비교는 구조 검사용이며 게임용 민머리/무장해제 자산이나 기능을 추가하는 요구가 아니다. 얼굴 비교쌍과 차이의 전문은 [17 §3.2](17_OPERATOR_COMMON_STYLE.md#face-comparison)와 개인 문서를 따른다.

긴 무기의 Mira/Vex/Rin, 허리 장비의 Eve, 머리/촉매의 Nyx, 펼침 프레임의 Iris는 몸체와 장비/FX 외곽을 별도 측정한다. 지원 요원은 양손의 위치·물리 접점·처치 방향·공간 제스처·관측 입력·보호 지지가 서로 다른지 확인한다.

군집 첫 기준은 Kyle/Reina/Eve/Sera/Mira다. 지원 표현은 Eve/Sera/Nyx/Cipher/Iris, 장비 점유는 Kyle/Rin/Mira/Vex/Iris 조합으로 추가 비교할 수 있다. 시각 시험 조합이지 추천 편성·밸런스 평가가 아니다. 빈 배경만이 아니라 실제 적·포탑·위험 예고·상태 UI를 함께 표시하며 공통10인 전체 비교도 수행한다.

## 13. 후속 결정과 출처

**후속 제작 결정:** 실제 SD 비례·주 시점, 원본/출력 캔버스와 화면 높이, 파츠/프레임/혼합 도구, 필요한 동작·방향·클립 수. 위의 수치 후보를 최초 비교에 사용하고 실제 화면 승인 뒤 고정한다.

근거는 이 채팅의 ‘원화→SD 전투 모델 변환 규칙 문서’ 요청과 [16](16_ART_STYLE_GUIDE.md), [17](17_OPERATOR_COMMON_STYLE.md)의 정체성, [04](04_COMBAT_RUN.md)의 전투/시간/포탑 상태, [13](13_EQUIPMENT_ENCHANTMENTS.md)의 장비 경계다. 파츠를 움직임·가림으로 나누는 방식과 각 시험 규격은 이번 제작 설계안으로 기록한다.

새 바이블에서 정체성·주 손·대표 무기를 변경하면 원화·SD·모션·아이콘을 함께 영향 검토한다. 새 원화가 예쁘다는 이유만으로 기존 승인 SD를 조용히 다른 디자인으로 교체하지 않는다.

## 전투 요원 일반 비율·큰 동작 정책 — 2026-10-05 사용자 승인
