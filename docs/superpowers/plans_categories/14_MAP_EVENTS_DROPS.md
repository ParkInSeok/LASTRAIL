## 1. 맵 구조 — 부모가 하위 노드를 공유

| 상위 노드 | 좌·중앙·우 하위 노드 예시 |
|---|---|
| 1 | 4,5,6 |
| 2 | 5,6,7 |
| 3 | 7,8,9 |

좌/중/우는 현재 노드에서의3선택이다. 같은 하위 노드를 여러 부모가 공유할 수 있고, 공유하지 않을 수도 있다. 노드 객체와 연결 edge를 분리하여5번 같은 노드를 부모마다 별개로 복제하지 않는다. '트리'라는 사용자 표현은 이 합류 가능 분기 구조를 뜻하며 엄격한 단일부모 트리로 제한하지 않는다.

전진 깊이만 연결하고 이전 노드 재방문을 허용하지 않는 방식은 기존 추천안이다. 시작·종료 노드의 연결 수 예외, 맵 깊이/폭 상한, 진입할 수 없는 노드 제거, 최종 목표 형태는 [00 J04](00_INDEX.md#j04)에서 확정한다. 전체 맵을 무제한3배 확장하지 않는다.

## 2. 맵과 전투·성장의 역할

증강은 전체 전투 스타일의 큰 규칙, 장비·인챈트는 개별 장착자의 성장, 기존 작전 재화는 전술 투자 자원으로 유지한다. **J04 사용자 방향:** 노드는 사건 단위이며 각 전투 노드에 몇 웨이브를 진행할지 정한다. 전투 노드가 사용하는 encounterProfile에 waveCount/종료조건을 고정한다. 구체적인 노드별 횟수는 [§9](#node-wave-proposal)의 추천안이다. 기존15웨이브 승리 검증을 맵15노드/고정15웨이브+Final 정책으로 확대하지 않는다.

상위 특성의 올인/고가치 표적은 [09](09_COMMANDER_PROGRESSION.md#capstone-rules)의 승인된 규칙을 확장한다. 올인의 추가 정예 단계는 같은 노드에 속하므로 개전·노드당1회 효과/장비 기본드랍을 재지급하지 않는다. 실제 증원·최종 목표·실패 정산 수치는 별도 확정한다.

## 3. 노드 이벤트 풀

사용자가 제시한 증강·전투·인챈트·장비·엘리트를 기본 종류로 둔다. 정비·상인·정찰, 확장형 적재물 회수·구조 작전은 추천안이다. 아래는 기존 비증강 상대 가중치와 이번에 제안하는 증강 가중치20이다. **J04 신규 추천**으로 총120이며 모든 노드의 무조건 확률%가 아니다.

| 이벤트 | 역할 | 상대 가중치 시험값 | 상태 |
|---|---|---:|---|
| 증강 | 큰 전투 규칙 선택 | 20 | J04 신규 추천. 보장 구간 없이 일반 랜덤 풀에 포함 |
| 전투 | 기본 전술 재화·장비 확보 | 40 | 기본 종류 |
| 엘리트 | 높은 위험·장비 성장 기회 | 12 | 기본 종류 |
| 장비 보급 | 특정 카테고리 확보 | 14 | 기본 종류 |
| 인챈트 | 장비 시술·승급·재조정 | 14 | 기본 종류 |
| 정비 | 요원·열차 생존 보완 | 8 | 추가 추천 |
| 상인 | 기존 작전 재화로 장비·서비스 구매 | 8 | 추가 추천 |
| 정찰 | 앞선 경로·위험 정보 확인 | 4 | 추가 추천 |

**시작 증강·경로별 횟수·정해진 지점의 증강 배치 보장은 모두 없음**이 최신 결정이다. 비증강 가중치 합계가100이라고 그 값을 최종%로 표시하지 않는다. 제안값 전체가 유효한 경우 증강은20/120의 상대 선택 비중이지만, 유효풀·맵 제약을 적용한 뒤 실제 확률을 계산해야 한다. 이번 값은 승인 전 추천으로 운영 발행하지 않는다.

적재물 회수는 추가위험을 받아 보급을 얻는 확장안, 구조작전은 별도 구출목표를 수행하는 확장안이다. 현재 필수 노드 수·가중치에 임의 추가하지 않는다.

### 3.1 사건 배치 로직 — 구현할 연결안

1. 승인된 작전 데이터 버전으로 그래프·노드 식별자를 고정한다.
2. 각 노드의 진행구간·허용유형·특성조건으로 적격 풀을 만든다.
3. 확정될 가중치·배치 제약으로 사건을 선택하고 노드 인스턴스에 저장한다.
4. 동일 합류 노드는 어떤 부모에서 와도 같은 사건을 사용한다. 재접속·경로 미리보기로 재추첨하지 않는다.
5. 도달/완료/안전 대기는 서버가 검증하며 클라이언트의 node 선언만으로 장비·증강을 발급하지 않는다.
6. 시작~종료 도달 가능성·유효 선택지·장비 공급·연속 위험·허용 사건을 검증한다. 증강 최소 횟수는 검사하지 않는다.

일반 분기에서 전투/비전투를 함께 제시, 엘리트 연속 강제 방지, 무효 대상 인챈트 대체는 기존 권장 제약이다. 이것들을 확정하지 않은 채 난수 가중치만 적용하면 노출 확률도 달라지므로 발행 전 함께 결정한다. 경로 분기선택의 시간은 [04](04_COMBAT_RUN.md), 증강 선택의 완전정지는 [05](05_AUGMENTS.md#pause)에 따른다.

## 4. 전투 완료 장비 지급 단위 — J06 채택 기준안

J06의 기존 추천대로 **전투 노드 전체 클리어마다 보상 묶음1회**를 지급하는 안을 초기 기준으로 채택한다. 적마다/웨이브마다 지급하는 것으로 확대하지 않는다. 노드가 여러 웨이브를 가져도 기본 묶음은 한 번이며 추가 보상은 승인 계획에 명시한다.

passed(통과)는 killed(처치)가 아니다. [04](04_COMBAT_RUN.md)의 구분을 유지하여 이탈/통과로 처치보상을 만들지 않는다. 작전 종료의 기본/광고 보상은 [06](06_REWARDS_ROULETTE.md)과 별도이며 런 장비를 영구 보상으로 자동 전환하지 않는다.

## 6. 드랍 성급 확률 — J06 채택 시험표

초/중/후반의 깊이 경계는 총 맵구조 결정 후 설정한다. 아래는 마지막 드랍 초안에6성 열을 명시한 것으로, 최고6성 결정이 직접6성 드랍을 승인한 것은 아니다.

| 전투·구간 | 1성 | 2성 | 3성 | 4성 | 5성 | 6성 |
|---|---:|---:|---:|---:|---:|---:|
| 일반·초반 | 90% | 10% | 0% | 0% | 0% | 0% |
| 일반·중반 | 65% | 30% | 5% | 0% | 0% | 0% |
| 일반·후반 | 40% | 45% | 15% | 0% | 0% | 0% |
| 엘리트·초반 | 20% | 70% | 10% | 0% | 0% | 0% |
| 엘리트·중반 | 10% | 60% | 30% | 0% | 0% | 0% |
| 엘리트·후반 | 0% | 50% | 45% | 5% | 0% | 0% |

**J06 채택 기준안은 직접5·6성 드랍 없이 합성/승급으로 성장**시키는 위 표다. 실제 노드량·장비 공급·무재료 승급 가치에 대한 시뮬레이션 검증은 별도다. 장비보급 노드는 같은 구간 일반표를 쓰고 카테고리/세트는 유효후보 내 균등 추첨하는 안이다. 적격성·지휘관 특성의 추가 획득량과 실제 확률 공시는 별도 계산한다.

## 7. 원자 지급·보관함·복구

후속 미승인 세부안: [13 보관함 초과·보상 보류](13_EQUIPMENT_ENCHANTMENTS.md#equipment-overflow-flow-v01). 일부 수령/새 보상 수령 포기·종결 시 처리·경합 복구를 비교하며 노드 보상 묶음1회 생성 원칙과 영구 보상 분리를 유지한다.

노드보상은 원계정·작전·노드·데이터버전·보상계획·키에 결속한다. 장비 생성과 보상소비를 한 거래로 확정하고 재조회는 고정 결과를 반환한다. 장비 상세 정의와 인챈트 시술값은 [13](13_EQUIPMENT_ENCHANTMENTS.md)를 따르고 성급 상승 미리보기를 복제/재추첨 권한으로 사용하지 않는다.

보관함 가득 참은 자동 장비삭제가 아니라 현재보상 대기→정리 후 진행이라는 추천안을 [09](09_COMMANDER_PROGRESSION.md)에서 참조한다. 점검·전투정지·장비정비의 상태가 겹쳐도 한 상태를 해제했다고 나머지를 해제하지 않는다. 점검 복구는 [12](12_SERVICE_MAINTENANCE.md#recovery), 구형작전 폐기는 [04](04_COMBAT_RUN.md#discard)를 따른다. 오래된 작전 만료는 [04 §12](04_COMBAT_RUN.md#run-expiry)의 J11 확정 정책(72시간·중단 보정·복구 후 최소24시간)을 따른다. 보상 미리보기 TTL과 같은 수명으로 취급하지 않는다.

## 8. 아직 정해야 할 것과 출처

[00 판단표](00_INDEX.md#open-decisions): J04의 맵/웨이브/보스·가중치 신규안은 승인 전이다. J06의 드랍 시험 기준과 J07의 카드(슬롯)별 무료3회·추가1회/광고·상품 경로는 승인되어 더 이상 기획 선택 대기가 아니다. 실제 세부DTO·효과 처리기·밸런스 검증은 별도 연결 작업이다. 참조된40종 증강·시너지·지원스킬·기존 노드 API는 실제 원문/소스 연결이 필요하다.

작성용 [map_drop_draft.json](map_drop_draft.json)은 본문의 시험값을 보존하며 `publishable=false`다. J04의 증강 가중치20 등 새 제안은 proposal로 저장하고 승인 전 활성화하지 않는다. 미정/미승인 값을0으로 처리해 조용히 없애거나 보장슬롯으로 되돌리지 않는다. 위키·확률 공시는 [11](11_WEBSITE_COMMUNITY.md)의 검증된 버전별 공개투영으로 생성한다.

출처는 이 세션의 사용자 맵예시·장비드랍 요구·증강보장 삭제·6성 정정 및 직전 assistant 수치 제안이다. 원본32개 파일의15wave 테스트가 이 전체 맵 기획의 구현 증거는 아니다. 게임 소스/DB/QA를 이번 문서 작업으로 변경하지 않는다.

## 9. 노드별 웨이브와 첫 맵 구성 — J04 신규 추천, 승인 전

**노드=이동 경로에서 선택한 사건, 웨이브=그 사건 안의 전투 단계**다. 플레이어가 노드마다 웨이브 수를 설정하는 기능이 아니라, 서버가 선택한 전투 프로필로 구성한다. 맵 노드/프로필·예정 웨이브 수·보스 페이즈를 작전 준비 데이터에 고정하고 복원 시 바꾸지 않는다.

### 9.1 전투 프로필

| 노드 | 기본 구성 추천 | 설명 |
|---|---|---|
| 일반 전투 | 2웨이브 | 1웨이브 기본 병력,2웨이브 조합 압박. 상위난도는 숫자 증가보다 구성·위협을 먼저 조정 |
| 엘리트 | 3웨이브 | 일반 위협→보조/복합 위협→엘리트 중심 전투 |
| 보스 | 1웨이브 안에3페이즈 | 동일 보스 인스턴스의 체력/기믹 조건으로 전환.3페이즈를3마리/3클리어로 세지 않음 |
| 튜토리얼 전투 | 명시 프로필에서1웨이브 | 처음 설명용 예외이며 일반 노드를 임의로 축약하지 않음 |
| 증강/장비/인챈트/상인/정비/정찰 | 0웨이브 | 해당 선택/처리가 완료되면 노드 종료 |
| 올인 채택 노드 | 원 프로필 뒤 정예 증원1웨이브 추가 | 기본2→3/엘리트3→4. 같은 노드, 전투당1회 효과/기본드랍 재지급 없음. 보스/최종노드는 초기 대상에서 제외하는 안 |

각 웨이브는 단순 타이머 경과가 아니라 해당 프로필의 출현 종료·필수 적/목표 해결로 완료된다. 남은 내부침입 위협을 처리하지 않은 채 외부 적만 없다는 이유로 넘기지 않는다. 통과가 허용된 적은 그 실패/통과 결과를 처리하고 처치보상을 주지 않는다.

보스의 페이즈 전환은 실제 보스 정의의 조건을 사용한다. HP를 임의로 만피 복원하거나 장비 개전효과·지휘 스킬 쿨타임을 초기화하지 않는다. 보스 HP 경계/행동은 별도 카탈로그 연결 대상이다.

### 9.2 웨이브 사이와 노드 사이

웨이브 사이는 같은 전투의 연속이므로 HP·마나·쿨타임·남은 버프·개전 인챈트·노드당1회 사용 여부를 이어간다. 조작을 끼워 넣어 무제한 대기 회복을 할 수 없도록 정상 시뮬레이션의 짧은 자동 전환으로 처리하고, 전술 구매/합성은 노드 종료의 정비 구간으로 둔다. 웨이브 종료를 자동 완전회복·부활·기본 장비드랍으로 처리하지 않는다. 요원 Down/부활의 기존 상세 원문은 회수됐다. [전투 보완 계약](34_COMBAT_POLICY_COMPANION.md)의 첫 테스트 회복 수치와 출시 기본값을 구분하며 새 복귀 시간을 여기서 만들지 않는다.

노드 최종 웨이브/목표 해결→노드 결과 검증→보상 묶음1회→장비 정리/전술 강화→다음 경로 선택으로 구성한다. 정비·증강·점검 hold는 서로 독립이므로 하나가 끝났다고 나머지 정지를 해제하지 않는다. waveIndex 변경 시 체크포인트를 남기고 복원은 원 nodeId/waveIndex/보상영수증을 사용한다.

### 9.3 첫 공개 데모 경로 시험안

시작 준비화면을 제외하고 **한 경로가 방문하는12노드(일반 진행11 + 최종 보스1)**를 추천한다. 맵 전체의 후보 노드 수가12개라는 뜻은 아니다. 초반1~4/중반5~8/후반9~11/최종12로 드랍 구간을 정의하는 시험안이다.

일반 층의 노드 폭은3~7개로 제한하고 부모가 서로 다른 하위3개를 갖도록 연결한다. 부모 간 하위노드 공유는 허용하며, 마지막 보스로 합류할 때의1연결은 명시 종료 예외다. 무제한3배 팽창과 도달 불가능한 노드를 막는다.

예시 경로: **일반5 + 엘리트2 + 비전투4 + 최종보스1 =12노드**. 일반/엘리트는16웨이브, 최종보스는1웨이브3페이즈다. 이것은 생성 결과 예시이지 모든 경로의 보장 개수 또는 고정17웨이브 규칙이 아니다. 증강0회도 가능하며 시작/최소 횟수 보장은 되살리지 않는다.

사건 가중치 제안은 §3의 일반40/엘리트12/증강20/장비14/인챈트14/정비8/상인8/정찰4다. 상대합120이며 조건부 배치 후의 최종확률을 별도로 공시한다. 지원되는 빌드/노드 길이에서 장비 공급량이 충분한지, 연속 위험/전투 편중이 심하지 않은지 생성 Seed 묶음으로 검증한다. 특정 경로의 증강 최소횟수를 강제로 맞추는 검증은 하지 않는다.

최종보스 클리어를 기본 데모 작전 완료로 보는 안이다. 기존 Final Operation/강습/초토화 관련 원문은 보존되어 있으나 신규 노드 구조의 종료 프로필과 연결이 확정된 것은 아니므로 이 뒤에 또 최종전을 자동 덧붙이지 않는다. 다른 작전 목표를 도입할 때 종료 프로필을 따로 정의한다. 이12노드/보스 모델은 새 추천이며 확정 정책으로 승격하려면 J04 승인이 필요하다.

|---|---|---|
| A 채택 | 현재 연결된 다음 목적지의 사건 종류·확인된 위험·보상 종류. 먼 노드의 사건 내용은 숨김 | 당장 선택에 필요한 근거를 주며 미래 정보 과다 노출을 줄임 |

과거 A의 먼 사건 비공개 제한은 후속 사용자 전체 공개 v02로 폐기됐다. 신규 작전은 시작부터 전체 그래프와 모든 노드의 실제 이벤트 아이콘을 공개한다. 정찰 노드는 아직 도입 추천이므로 정보 확인을 정찰 구매나 새 재화 소비의 필수 조건으로 만들지 않는다. 실제로 조회하지 못한 값을 의도적인 비공개로 위장하지 않는다.

### 읽기 실패·접근 제한

- 숨김: 공개 정책에 따라 감춘 사건 정보. ‘미공개’로 표시하며 오류 재시도 버튼을 붙이지 않는다.
- 조회 실패: ‘정보를 불러오지 못했습니다’와 재조회. 비용/진입 조건처럼 선택에 필수인 값이 누락되면 확정 차단, 장식 설명 누락만으로 차단하지 않는다. 필수 표시 계약은 소유자가 정의한다.
- 진입 불가: 원 그래프에서 연결되지 않았거나 권한/프로필이 지원하지 않는 목적지. 사유를 표시하고 임의 일반 노드로 교체하지 않는다.
- 도달 가능한 후보가 실제로1~2개인 승인된 예외는 그 수만 표시한다.3개를 맞추려고 가짜 목적지나 같은 node의 복제 카드를 만들지 않는다. 일반 구간에서 기대 후보가 누락된 경우 정상 예외로 숨기지 말고 계약 오류로 처리한다.
- 새로운 조회가 늦게 도착해도 계정/run/현재 노드가 달라졌으면 현재 화면에 반영하지 않는다. 재접속/미리보기 반복으로 사건·보상 후보를 다시 추첨하지 않는다.

### 소유권·연결·수용

Server는 원 그래프/사건 identity와 공개 가능한 정보·진입 조건·보상 조건을 제공한다. 클라이언트가 숨길 데이터도 전달받은 뒤 화면에서만 감추는 방식은 정보 공개 통제가 아니다. Unity Controller는 조회·선택·재시도를 조정하고 View는 전달된 정보/상태만 표시한다. Direction은 기존 승인 UI 자산을 활용해 카드 요약→상세 펼침을 구성하며 실제 카드 수·긴 제목·글자 크기·터치 영역을 확인한다. 새 API명/필드/버전·최종 시안은 이 기획에서 확정하지 않는다.

검수 조건: 부모가 다른 공유 노드의 같은 정보, 미공개와 읽기 실패 구분, 보상 기회와 지급 보장 구분, 미승인 J04 수치 노출0, 스토리 결말 누출0, 원 목적지 유지, 빠른 카드 전환 시 이전 응답 덮어쓰기0, 카드/확정 입력 중복0. 360/720 폭에서 긴 한국어 제목과 아이콘 없이도 선택 근거를 읽을 수 있는지 실제 화면 검수가 필요하다. 현재는 문서 검토만 수행했고 시안·코드·런타임 검증은 미실행이다. 공개 방향 결정은 해소됐다. WAIT-003에서 필수 데이터/표시 계약과 실제 연결·화면 검수를 계속 대기한다.

## 목적지 선택 화면 상세기획 v0.1 — 2026-09-22 / 상세 후보

작성 책임 Plan_6. 사용자 상세기획 진행 지시에 따른 화면·입력·오류·복구 명세다. 목적지/선로 분리와 정보 공개 A는 승인됐고, 아래 배치·버튼·세부 상태 전이 및 앞 절 확정/시간 후보는 별도 검토 대상이다. 작업 범위는14·33·WAIT-003 문서이며 Server/Unity/Direction 구현을 대신 수행하지 않는다.

### 1. 진입·화면 구성

진입 조건은 현재 노드의 결과가 확인되고 선행 필수 처리 완료 후 다음 목적지를 선택할 수 있는 상태다. 기존 보상/정비 흐름은 node-transition-flow-v01에 따르며 그 미결 규칙을 새 승인하지 않는다. 종료 노드는 선택 화면을 열지 않고 기존 작전 결과 흐름을 따른다.

| 영역 | 내용·동작 | 표시 제한 |
|---|---|---|
| 상단 | ‘다음 목적지’, 현재 위치, 원 작전 맥락 | J04 미확정 총 노드 수로 진행률을 만들지 않음 |
| 경로 지도 | 현재 노드와 실제 연결 후보, 허용된 연결·합류 표시 | 미리보기는 점선/‘미리보기’, 저장된 경로는 실선/‘확정’ 등 색 외 구분 |
| 후보 요약 | 사건 아이콘+이름, 확인된 위험, 보상 기회 | 실제 좌/중/우 순서 유지. 임의 위험순 정렬로 지도 위치를 바꾸지 않음 |
| 상세 | 선택 후보 이름, 사건 소개, 위험·목표·보상 조건 | 긴 본문 스크롤, 필수 조건은 접힌 영역에만 숨기지 않음 |
| 하단 | 현재 상태 안내, ‘목적지 확정’ 또는 상태별 복구 입력 | 선택 대상 이름을 함께 표시. 카드와 다른 후보를 확정할 수 없음 |

카드 목록과 상세의 배치는 Direction 시안에서 검증한다. 360/720 폭에서 강제3열로 글자를 줄이기보다 지도 위치 표식과 읽을 수 있는 목록을 함께 쓰는 방향을 권고한다. 정확한 크기·폰트·여백은 기존 승인 화면 기준을 사용하고 이 문서에서 새 수치를 확정하지 않는다. 프레임/아이콘/문자/선택 표시/입력 영역은 독립 제어한다.

### 2. 버튼·입력 계약 후보

- 카드/지도 후보 누름: 같은 미리보기 명령으로 연결한다. 도달 가능한 edge에 속한 node만 대상이며 저장/이동/추첨을 실행하지 않는다. 이미 선택한 카드를 다시 눌러도 확정되지 않는다.
- 다른 후보 누름: 미리보기와 상세만 교체한다. 늦게 온 이전 상세 응답으로 새 후보의 정보를 덮지 않는다.
- 목적지 확정: 현재 유효 후보와 최신 선택 가능 상태가 모두 확인됐을 때 한 번 실행한다. 확정 버튼 자체가 명시 확인이며 매번 추가 확인 팝업을 겹치지 않는 안을 권고한다.
- 뒤로/닫기: 상세가 열렸으면 상세만 접는다. 최상위에서는 화면만 닫을 수 있되 경로를 자동 선택하거나 이동 대기를 해제하지 않는다. 기존 목적지 입력으로 다시 열 수 있어야 한다. 요청 전송 후 닫기는 저장 취소가 아니다.
- 다시 불러오기: 읽기 실패 시 원 작전/노드 상태를 재조회한다. 신규 그래프·사건 생성 요청이 아니다.
- 선택 결과 확인: 응답 유실 시 원 명령 결과를 조회한다. 별도 새 확정 명령이나 ‘다른 목적지 선택’을 동시에 제공하지 않는다.

### 3. 상태 전이

아래는 설명용 상태명이며 새 wire enum을 지정하지 않는다. 화면 수명은 표시 구독을 소유하고, 요청·원 거래 복구 수명은 기존 작전 Controller/저장 소유자가 관리한다.

| 현재 상태 | 진입/입력 | 다음 상태와 처리 |
|---|---|---|
| 읽는 중 | 진입·재조회 | 성공→선택 전 또는 이미 확정됨. 실패→읽기 실패 |
| 선택 전 | 카드 입력 | 미리보기. 첫 후보 자동 선택·자동 확정 없음 |
| 미리보기 | 후보 변경/확정 | 변경은 미리보기 유지, 확정은 저장 중. 필수 정보 누락이면 확정 차단 |
| 저장 중 | 응답 수신 | 성공→확정됨, 명확한 거절→상태 재조회, 전송 후 결과 불명→결과 확인 중 |
| 결과 확인 중 | 원 결과 조회 | 확정됨→해당 경로 복원. 원 거래의 미적용이 권위 있게 확인됨→다시 선택 가능. 조회 실패→결과 확인 중 유지 |
| 읽기 실패 | 재조회 | 읽는 중. 이전 캐시는 참고 표시만 허용하고 확인 전 확정 금지 |
| 확정됨 | 화면 복원·저장 성공 | 원 선택 표시. 별도 이동 허용 조건/hold를 확인해 기존 진행 조정에 전달 |
| 더 이상 선택 불가 | 작전 종료·만료·현재 노드 변경 | 이전 입력 무효화 후 해당 원 상태 화면으로 연결. 선택 거래 취소/보상 회수 임의 실행 없음 |

단순 ‘결과 없음’ 한 번을 미적용 증거로 간주하지 않는다. 조회 일관성·진행 중/미적용 판별·동일 요청 재전송 허용은 Server 계약이 필요하다. 중복 전송이 필요해도 기존 멱등 계약 안에서 같은 논리 명령을 복구하며 새 선택으로 바꾸지 않는다. 도메인 상태가 이미 이동했으면 이전 화면 상태보다 원 상태를 우선한다.

문구 후보: ‘다음 목적지를 선택하세요’, ‘목적지를 저장하고 있습니다’, ‘선택 결과를 확인하고 있습니다’, ‘정보를 불러오지 못했습니다’, ‘이 목적지를 선택할 수 없습니다’, ‘목적지가 확정되었습니다’. 전송 후 결과 불명에 ‘저장 실패’라고 단정하지 않는다. 내부 오류 식별자는 사용자 문구 대신 진단 문맥으로 남긴다.

### 4. 필요한 데이터 의미와 결손 처리

| 데이터 의미 | 소유·검증 | 없을 때 |
|---|---|---|
| 계정/작전/현재 노드와 적용 버전 | Server 원 상태, Unity는 현재 화면 문맥 일치 확인 | 확정 차단·원 상태 조회 |
| 후보 node와 연결 edge/순서·선택 가능 여부 | 원 그래프 소유자. 공유 node를 부모별 복제하지 않음 | 임의 후보 생성 금지·오류 표시 |
| 공개 사건/위험·보상 조건 | 공개 정책 적용 후 제공 | 장식 설명 생략 가능, 필수 진입 조건 누락은 차단 |
| 미리보기 후보 | 화면/Controller 임시 상태 | 선택 전 상태, 저장된 선택과 혼동 금지 |
| 확정 선택과 원 명령 결과 | 저장/명령 소유자 | 결과 불명 상태에서 새 확정 금지 |

### 2. 진행 가능 판정

다음 목적지 선택으로 넘기는 조건은 원 사건 결과 확인, 현재 노드 필수 선택/적용 완료, 필수 보상 처리 해결, 미확인 변경 요청 없음, 진행을 막는 hold 없음, 작전 미종결, 유효한 다음 연결 존재다. 조건별 권위 상태를 기존 진행 조정 객체에서 평가하며 View가 별도 bool 조합으로 판정하지 않는다.

보상 잔여 처리의 완료 정의는13의 미결 정책에 의존한다. '일부 수령/새 보상 포기 후 모두 해결'을 후보로 쓰되 승인·계약 전에는 해당 버튼이나 보상 포기 기능을 구현 완료로 취급하지 않는다. 단순 설명 열람·장비 정비는 필수 처리로 추가하지 않는다.

여러 대기 사유가 있으면 원 명령 확인처럼 다른 행동의 안전성을 결정하는 사유를 먼저 안내하고 나머지도 함께 노출하는 안을 권고한다. 점검 중 허용되지 않는 거래를 '공간 정리' 해결책으로 실행시키지 않는다. 필요한 사유 해결 전 주요 버튼을 비활성화하고 이유를 읽을 수 있게 한다.

원 거래 결과가 불명확하면 조회 실패와 미적용을 구분한다. Server가 원 상태를 확인하기 전 UI가 대기 항목을 미수령으로 되돌리거나 이미 지급된 항목을 새 묶음에 넣지 않는다. 정확한 명령/오류/조회 일관성·경합 순서는 실제 계약 연결 대상이다.

### 4. 보관함·정비·뒤로가기

장비 정비는 기존 화면을 재사용한다. 돌아올 목적은 원 run/node/보상 묶음으로 유지하며 화면 좌표나 제목 문자열로 복귀 위치를 찾지 않는다. 복귀 시 해당 작전이 종료됐으면 옛 결과 화면으로 강제 복귀하지 않는다.

비교/재료 미리보기에서 뒤로가기는 임시 선택만 취소한다. 요청 전송 후 뒤로가기는 거래 취소가 아니며, 미확인 거래는 소유 Controller가 보존/복구한다. 화면 닫기·정비 종료는 새 보상 포기나 작전 포기가 아니다. 작전 포기는 기존 별도 확인 절차를 사용한다.

합성 후 공간이 늘었다고 가정하지 않고 원 결과와 최신 용량을 확인한다. 일부 수령/포기 및 최종 노드에서 런 장비 정리를 생략하는 안은13의 결정 대기 상태를 유지한다. 최종 작전 보상·스토리 첫 보상과 런 장비 수령을 한 상태로 묶지 않는다.

### 5. 보상·시간·복구 책임

Server는 사건 완료, 원 보상 묶음/항목/영수증, 보관 상태와 거래·종결 순서를 소유한다. Unity 진행 Controller는 보상/정비/증강 등의 소유 상태를 읽어 단계 전환을 조정하고 View 입력은 기존 명령에 바인딩한다. 개별 보상 컴포넌트가 작전 이동이나 정지 전체를 직접 해제하지 않는다.

정비/증강/점검/백그라운드 정지는 각 원 소유자가 해제한다. 다음 목적지 선택의0.01·복귀0.6초와 완전 정지를 혼동하지 않는다. 결과 대기 단계의 정확한 시간/주행 경계는 기존 실제 driver 계약과 대조해야 하며 이 문서가 임의 전체 정지 승인 근거는 아니다.

재접속 시 UI가 마지막으로 보인 단계가 아니라 권위 있는 사건/보상/작전 상태로 복원한다. 일부 수령이 승인·지원된 경우 받은 항목은 유지하고 남은 원 항목만 표시한다. 계정/작전 교체 후 이전 응답 표시, 재바인딩 중복 호출, 화면 파괴 후 표시 갱신을 막는다. 거래를 소유하지 않은 View는 요청을 취소했다는 이유로 서버 결과를 되돌리지 않는다.

## D5 사건 결과·보상·장비 정비 화면 연결 v0.2 — 2026-09-22 / 상세 검토안

Plan_6 소유. 목적은 사건마다 팝업이 연속으로 열리지 않으면서 남은 처리와 돌아갈 위치를 분명하게 만드는 것이다. **D5 화면 구성/복귀 UX는 승인 대기**이며 D2 배치·잠금, D3 선택 수령·포기, D4 시술/통과는 승인된 원본13을 따른다. 앞선 본 문서의 D3 미승인 표현은13 상단 승인 기록으로 대체한다. 정책 원본은13, 화면 연결 원본은 이 절로 구분한다.

### 1. 단일 추천 흐름

사건 결과와 보상 상태를 **한 결과 화면의 내부 상태**로 제공하고 정비는 필요할 때 기존 장비 화면으로 이동한다. 결과→보상 전용화면→수령 완료 팝업을 연속으로 만드는 대안보다 왕복과 중복 확인을 줄인다. 장비 비교/거래 결과는 장비 화면 안에서 갱신한다. 기존 화면 호스트/라우팅을 재사용하며 새 전역 모달 호스트를 추가하는 뜻이 아니다.

결과 화면 상단은 검증된 사건 결과, 본문은 확정 보상/대기 항목, 하단은 현재 할 행동이다. 보상 카드의 결과 상세는 펼침/접힘으로 보되 독립적으로 스크롤할 수 있게 한다. 장비 정비를 매 노드 필수 방문으로 만들지 않는다. 영구 보상과 작전 장비는 구분하고 확인된0보상과 조회 실패를 같은 빈 화면으로 표시하지 않는다.

### 2. 생성·출격 수락

준비에서 지원 풀/정의와 계정 적격성을 확인하고 원 계획을 만든 뒤 구조를 검증한다. 모든 시작→정상종점 경로의 방문12,일반 하위3개 고유edge·공유허용·층3~7·일반최종1연결을 확인한다. D7 첫층/4~8층 사건과 마지막 이야기/일반 최종2선택 예외는 명시 스토리 프로필에만 적용한다.

이야기 적격/지원이면 배정node 경유 완주경로와 배정node를 지나지 않는 완주경로가 모두 존재해야 한다. 증강 최소횟수를 생성기 검증조건에 추가하지 않는다. 원 node의 일반/엘리트/비전투 속성과 연속엘리트 대안 조건은 모든 관련 부모에서 검사한다. 공유node 때문에 조건이 충돌하면 검증된 다른 원 계획을 생성하되 지원불가/재시도 제한을 담당 계약으로 명시한다.

START 수락은 계정/출격 적격·지원버전·지휘실/편성/비용quote·계획 일치 검사,비용/입장 원거래와 원계획/snapshot 저장을 함께 보장한다. 클라이언트가 제출한 임의 그래프를 수락하지 않는다. 실패한 생성/검증을 일반작전으로 무통보 대체하거나 비용만 확정하지 않는다. 수락 후 정의/카탈로그 변경은 원run 계획을 변경하지 않는다.

### 5. 경합·오류·구버전 복원

- 같은revision에서 서로 다른edge 확정은 하나만 수락한다. 동일key 같은edge는 원결과,동일key 다른edge는 충돌이다. 저장성공 뒤 다른edge로 재선택하지 않는다.
- node완료 중복은 같은원보상/근거를 반환한다. 다른부모로 공유node를 보았다는 이유로 새사건·보상을 생성하지 않는다.
- 보상수령/이벤트선택 대 다음edge는 권위 hold/revision으로 검사한다. 클라가 대기목록을 숨긴 것으로 통과하지 않는다.
- FINISH 대 시술/수령은 S2 원자 순서를 따른다. 종결후늦은응답으로 전투/장비를 부활시키지 않는다.
- 계정진행이 다른run에서 먼저 상승해도 현재run의 원사건은 유지하고 최종계정 갱신은 단조/중복검사를 적용한다. 현재run에 후속사건을 자동배정하지 않는다.
- 확정후응답유실은 원key 결과 복구이며 새계획/새보상으로 다시 실행하지 않는다. 실제서버 원근거가 없는 상태를 성공영수증으로 복구하지 않는다.
- 구15wave run은 원프로필/저장버전으로 복원한다. 신규12node 모델로 강제변환/현재seed 재생성 금지. 지원불가 판정은 기존04 비호환 절차와 매핑한다.
- 저장손상/미확인/점검을 정상만료로 취급하지 않는다. 계속하기 전 읽기확인·원거래복구와 명시재개는 D1 유지.

오류 의미는 정의/프로필미지원,그래프구조불가,출격quote변경,선택revision충돌,edge부적격,미해결hold,목표근거부족,종결,계정불일치,원결과불명을 구분한다. 실제 wire code는 기존 Server 규약으로 정한다.

## 작전 시작 시 전체 경로·노드 이벤트 공개 v02 — 2026-09-22 사용자 확정

사용자 요청으로 기존 ‘다음 목적지만 사건 공개/먼 노드는 점·사건 비공개’ 정책을 폐기한다. 작전 시작에 원그래프·모든 노드의 실제 배정 이벤트를 고정하고 **플레이어가 처음부터 전체 경로와 모든 노드의 이벤트 아이콘을 보고 경로를 계획할 수 있게 한다.** 기존 destination-preview-info-v01의 A채택/원거리사건숨김 및 그 정책을 소비한 화면/문구보다 이 절이 우선한다.

### 1. 생성·공개 범위

- 최초 수락된 START에서 해당작전의 전체 node/edge·이벤트종류 배정을 원버전/seed와 결속해 고정한다. 전체 맵 표시 때 실제 원그래프를 사용하고,노드 진입 때 이벤트를 뒤늦게 추첨하거나 이미 보여준 종류를 바꾸지 않는다. 같은 합류 node는 어느부모에서도 같은 사건이며 조회/재접속으로 재추첨하지 않는다.
- 현재·다음·먼미방문·최종·다른분기의 **모든 노드**에 실제 배정 이벤트 아이콘과 범례/이름을 제공한다. 먼6개를 점으로 대체하는 방식은 신규정책에 부적합하다. 실제노드수는원그래프를따르고,12방문길이를전체그래프노드12개로오인하거나시안의9개를최대치로고정하지않는다.
