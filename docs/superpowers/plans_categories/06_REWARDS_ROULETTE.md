# LAST RAIL | 클리어 보상·광고·공용 룰렛

범위: 기본 수령, 클리어 광고 기회, 보상 계산/정산, 공용 결과 표시. 영구권 구매·사용승인은 [07](07_AD_SKIP.md), 작전 종료 요청은 [04](04_COMBAT_RUN.md)에서 관리한다.

## 1. 책임과 기본 수령

HTTP가 인증/replay 검사를, 독립 settlement가 launch entitlement 조정·balances·ledgers·최종 preview 검증을 담당한다. 기존 basic claim을 이 서비스에 연결하며 crystal/item 계약과 기존 offline reward-line 소비자를 보존한다. CombatAd 서비스는 고정 intent/policy/result, 공통 provider registry는 검증 거래 사용을 소유한다.

완료된 run의 적격 reward preview를 account/environment/run에 결속한다. 기존 승리 화면의 **기본 보상 수령은 유지**한다. 신규 광고 룰렛은 [10](10_LIVEOPS_NOTICES.md#ads)의 현재 광고 허용과 기능 준비 조건을 충족할 때만 제공하며, 첫 공개판에서는 광고를 시작하지 않는다. 기본/광고/상품 경합은 하나의 기회로 처리하고 별도 지급 서비스를 만들지 않는다. View는 서버 승인/추첨/지급 권한을 갖지 않는다. [R23](00_INDEX.md#r23) [R24](00_INDEX.md#r24) [R25](00_INDEX.md#r25) [R29](00_INDEX.md#r29)

## 3. 광고 검증과 원자 정산

create/read/spin은 인증된 기회에 한정한다. **SDK 완료만으로 spin을 승인하지 않고** 서명된 SSV를 검증한다. 등록 challenge를 서버 소유 placement로 연결하고, offline과 combat의 공급자 거래 사용 기록을 같은 registry/batch에서 확인해 중복 사용을 막는다.

정산 시 preview/account/run/status/plan/version/expiry를 같은 DB batch에서 재검사한다. 바뀐 preview는 wallet을 변경할 수 없으며 실패 시 경제 쓰기 전체를 rollback한다. 서버에 고정된 결과만 로드해 intent/preview를 원자 소비한다. 동시 spin·기본 수령·취소 경합과 재시도에도 한 번만 지급한다.

고정 결과·원영수증·과거 policy를 보존한다. 마이그레이션은 기존 verified provider를 보존/backfill하며 충돌 시 실패한다. 미검증 policy 계산 모듈만으로 지급 endpoint가 완성됐다고 보지 않는다. [R23](00_INDEX.md#r23) [R24](00_INDEX.md#r24)

## 4. Unity 흐름과 복구

CombatAdIntent는 strict server data를, CombatAdController는 비동기 흐름·원 create/spin key·계정 encrypted action journal·provider port를 관리한다. AccountScreenRuntime는 조합하고 RunVictoryView는 callback만 전달한다.

응답 유실/재실행은 원요청과 고정 결과를 복구하며 provider UI를 다시 재생하거나 새 추첨을 하지 않는다. 세션/수명 교체와 blocked journal을 처리하고 pending/claimed/expired·실제 오류·기본 수령 확인을 표시한다. provider SDK 부재는 unavailable로 드러낸다. 최종 reward lines가 권위이며 base/excluded lines는 표시용 snapshot이다. [R25](00_INDEX.md#r25)

## 5. 보급·전투 공용 팝업

SharedRoulettePopup/View는 표시와 바인딩된 입력만 공유한다. wheel·reward cards·result highlights는 독립 제어하며 기존 보급/전투 controller의 journal·provider·settlement를 옮기지 않는다.

**실제로 룰렛을 이용하는 승인 기회**의 연출 기준은 **6.5초 + 0.6초**다. 신규 광고 없는 기본 수령에는 이 회전을 강제로 적용하지 않으며 [10 §2](10_LIVEOPS_NOTICES.md#off-benefits)의 비보유자/보유자 화면 분기를 따른다. 회전 중 기본 수량, 정지 후 count, 긴 수량의 폭/overflow와 네 번째 이후 보상 접근을 검증한다. 최종 수량은 서버 결과다. 완료 화면은 확인 하나만 제공하고 완료 전 오류/재시도는 보존한다. 이미 확정된 결과를 다시 열면 전체 연출 대신 최종 상태를 즉시 보여준다. 입력 baseline은 승인 기회에 고정된 값이며 오래된 화면 preview로 대체하지 않는다.

승인 Concept05를 기준으로 독립 brass rail frame과 cyan wheel/pointer/button을 보완하며 동적 label을 유지한다. 보급 상세 확률은 서버가 고정한 정확한 정책값을 별도 detail view로 전달한다. legacy-safe optional parsing과 binding consistency를 검증하고 malformed 값을 거부하되 draw/receipt를 바꾸지 않는다. 승인 이미지를 평면 한 장으로 납품하지 않는다. ## 7. 광고 없는 첫 출시와 공개 확률 — U7

광고 ON/OFF의 현재 권한은 [10](10_LIVEOPS_NOTICES.md#ads)이 관리한다. 기존 §1의 광고 룰렛 제공은 신규 광고가 허용되고 실제 기능이 준비된 경우다. 기본 수령은 별도로 유지한다. OFF/전환 중 이미 승인된 광고·상품·고정 결과의 정산 경계는 [10 §3](10_LIVEOPS_NOTICES.md#ad-transitions)를 따른다. 광고 OFF만으로 SSV 검증을 생략하거나 상품권을 가짜 부여하지 않는다.

**J08 승인:** 최초 데모의 BASIC_ONLY는 광고 스킵 비보유자에게 적용한다. 유효 ACTIVE 구매자는 광고 OFF여도 상품 사용승인→기존 룰렛으로 혜택을 이용하고, 광고 시청이나 SSV를 가장하지 않는다. 상세 UI/권한은 [10 §2](10_LIVEOPS_NOTICES.md#off-benefits)를 따른다. 데이터·보상 결과·공용 View를 삭제하지 않으며, 실제 배수/한도 미확정 값을 임의로 채우지 않는다.

공개 확률 표는 [11](11_WEBSITE_COMMUNITY.md#odds)의 승인된 원policy 기반 snapshot을 사용한다. 광고 OFF이면 신규 광고 보상은 현재 미제공으로 구분하되, 이전 원기회의 실제 확률/원결과 조회는 유지한다. 보급과 전투 policy를 하나로 합치지 않는다.


## 8. U9 점검과 보상 복구

[12 §4](12_SERVICE_MAINTENANCE.md#recovery)를 따른다. 신규 출격/광고 차단과 기존 승인 결과 정산은 구분한다. 정산 저장소가 사용 가능하면 기존 권한·기한·단일 지급 검증을 유지하며, 사용할 수 없으면 원요청/결과를 보존하고 조회·재시도를 대기한다. 점검으로 배수 재추첨·새 지급키 생성·자동 결과 삭제를 하지 않는다.

유효 callback을 무조건 게임점검 화면 뒤로 숨기지 않는다. 즉시 처리 또는 내구성 있는 검증된 수신을 확인할 수 없으면 성공 수신 응답을 위조하지 않으며 공급자 재전달 계약을 따른다. 기존 광고/보상 기한 변경은 별도 명시 계약·감사 대상이다.


## 9. 작전 장비 드랍과의 구분

[14](14_MAP_EVENTS_DROPS.md)의 전투 노드 드랍은 작전 전용 장비 획득이다. 이 문서의 작전 종료 보상과 다른 원거래로 다루고, 장비 소유·합성은 [13](13_EQUIPMENT_ENCHANTMENTS.md)를 참조한다. 작전 종료 때 소멸하는 장비를 자동으로 영구 인벤토리에 넣거나 클리어 룰렛 배수로 늘리지 않는다. 새 드랍 수치·노드 종료 조건은 해당 문서의 시험안 상태를 유지한다.


## 10. 저장 작전 만료와 이미 확정한 보상

[04 §12](04_COMBAT_RUN.md#run-expiry)의 72시간 재개 수명·게임 중단 보정·원인별 입장 비용 반환은 2026-09-21 사용자 승인으로 확정되었다. 실제 정산·만료 처리 구현은 별도로 검증한다. 조사 체크포인트의 보관은 [15](15_LOG_RETENTION.md#retention-matrix)의 승인된 유형별 정책을 따른다. 재개 수명·조사 보관 어느 쪽도 이 문서의 보상·광고 claim 기한을 변경하지 않는다. 서버가 이미 FINISH/지급을 승인한 작전을 활성 작전 만료로 덮지 않는다. 미확정·고정 결과·원장·중복 방지 영수증을 재개 데이터와 함께 삭제하지 않으며 기존 기한·원거래로 복구한다.
