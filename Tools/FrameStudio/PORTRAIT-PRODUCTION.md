# LASTRAIL 전투 카드 초상 제작 기준

2026-11-03 · Direction · 가로 전투 HUD 하단의 요원 카드

제작자는 먼저 **어느 요원의 어떤 사용처에, 어떤 승인 원본을 쓸지** 확인한다. 이 문서는 전투 카드용이다. 로비·출발 공용 초상, 전투 자세, 궁극기 컷인은 별도 자산이다. 카드 후보를 승인해도 다른 사용처나 Unity 연결이 함께 승인되지는 않는다.

## 1. 기준과 원본

- 카드의 위치·틀·정보 배치는 [가로 D 승인 시안](../../QA/SideViewReuse-20261023/ui-layout-v01/D-controls.png)을 따른다. D안의 얼굴은 크기와 가독성 비교용이다. 요원의 머리색·복식·장비는 해당 캐릭터의 최신 승인 원화를 따른다.
- 제작 전 [공통 화풍](../../docs/superpowers/plans_categories/16_ART_STYLE_GUIDE.md), [요원 등록부](../../docs/superpowers/plans_categories/17_OPERATOR_COMMON_STYLE.md#character-registry), 해당 요원의 개별 바이블과 [제작 운영 기준](PRODUCTION.md)을 확인한다.
- 현재 최종은 [사용자가 지정한 5인 카드 이미지](../../QA/SideViewReuse-20261023/reina-battle-hud-v01/d-console/approved-five-reference.png)다. 전투 카드 5종 모두 손 없는 좌향 ¾ 구도를 사용한다. [전체 화면 정지 검수본](../../QA/SideViewReuse-20261023/reina-battle-hud-v01/d-console/combat-review.png)에서 카드 슬롯을 함께 확인할 수 있다. 이전 개별 승인/세미 명칭은 최신 표시 기준을 대체하지 않는다.

| 슬롯 | 최종 인물 원본 | 표시 기준 |
|---|---|---|
| 레이나 | [좌향 원화](../../QA/SideViewReuse-20261023/reina-battle-hud-v01/d-console/sera-composition/reina.png) | 남색 포니테일·붉은 리본, 하늘색 배경 |

## 2. 구도·표정·배경

1. **얼굴을 먼저 읽히게 한다.** UI 초상은 눈높이 카메라가 기본이다. 실제 카드에서 눈매·표정·요원별 식별점이 보이는지를 먼저 판단하고, 확대본으로 선과 접합을 확인한다. 손·무기가 얼굴을 가리면 다른 구도를 고르거나 가린 부위만 복원한다.
2. **세라 구도를 요청받으면** 손 없는 왼쪽 ¾ 측면과 눈높이를 기준으로 한다. 현재 비교 도구는 눈 위치를 크롭 너비 약 51%, 높이 약 53%에 놓고 눈–턱 간격으로 확대율을 잡는다. 이는 비교용 시작값이다. 현재 최종에서는 카일과 이브만 각각 15% 확대한다. 레이나의 종전 8% 크롭을 좌향 원화에 중복 적용하지 않는다.
3. **비율을 먼저 맞춘다.** 1004×565 검토 화면의 초상 입력 영역은 약 70×75px이고 프레임이 가장자리를 일부 가린다. 원화 비율을 유지해 크롭한 다음 축소한다. 정사각형을 직사각형으로 눌러 넣지 않는다. 정모·휘장·리본·머리 매듭이 잘리면 실제 카드 크기의 전후 비교로 선택한다.
4. **표정 수정은 작게 시작한다.** 이브처럼 미간만 문제라면 눈썹 안쪽만 편집한다. 기존 눈·코·입·턱·정모를 보존하고 수정 범위 밖 픽셀을 대조한다. 반대로 시선을 정면에서 ¾로 돌리는 일은 새 각도의 작화다. 원본을 보존하고 인상이 달라진 부분을 설명한다.
5. **얼굴 주변의 명암을 정리한다.** 윗눈꺼풀, 앞머리 아래, 턱과 옷깃 사이를 작은 크기에서도 구분되게 한다. 흰 머리와 밝은 코트는 목 아래의 어두운 면으로 분리한다. 다른 요원의 얼굴형이나 눈을 복사해 화풍을 통일하지 않는다.
6. **배경은 인물과 독립적으로 둔다.** 현재 검토 팔레트는 레이나 하늘색, 카일 모래색, 이브 청록색, 세라 청회색, 닉스 보랏빛 회색이다. 인물에는 실제 알파를 사용하고, 프레임·배경·이름·역할·HP·충전량·선택 효과는 따로 제어한다.

## 3. 제작·검수·납품 순서

1. 요원 ID, 사용처, 원본 파일·버전·승인 근거를 확인한다. 기존 원화의 크롭으로 충분한지, 국소 편집인지, 새 각도의 작화인지 정한다.
2. 한 요원 한 후보를 별도 버전으로 만든다. 원본과 세미 후보를 보존한다. 첨부본·신규 생성·좌우 반전·크롭·국소 합성 등 실제 방식과 변경 부위를 기록한다.
3. **같은 배율로** D안 해당 슬롯 → 이전 카드 → 새 후보를 비교한다. 실제 카드와 같은 얼굴 영역 확대본을 함께 제시한다. 초상 밖 UI가 바뀌지 않았는지, 알파 가장자리·마스크·배경 대비를 확인한다. 마지막으로 다섯 카드가 놓인 전장 전체에서 확인한다.
4. 사용자가 고른 이미지·크롭·배경·승인 범위를 [기존 승인 기록](PRODUCTION.md)에 남긴다. 세미 후보와 단순 비교안은 따로 보관한다. 제품 공급 시 원본·출력 경로, 해시, 크롭·배경·소비자 ID와 검수 근거를 함께 넘기고 Unity에서는 실제 연결·화면 크기·마스크를 별도로 확인한다.

현재 표시는 [단일 콘솔 빌드](../../QA/SideViewReuse-20261023/reina-battle-hud-v01/d-console/build.py)가 위 최종 원본에서 재생성한다. 제품 Unity 연결은 별도 검수 사항이다.
